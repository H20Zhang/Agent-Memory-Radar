# Demystifying Agent Skills: Why They Work—Until They Don’t

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Evaluation & Analysis](../../categories/evaluation-analysis.md)

[arXiv 2608.14036](https://arxiv.org/abs/2608.14036) · Published 2026-08-14 · Importance **4/5** · Confidence **high**  
`procedural` `text` `coding` `general-agent`

> **Research delta.** Using the **same source trajectories**, standardized Skills outperform Workflow Memory and mostly help as procedural anchors; exact retrieval labels remain a weak proxy for downstream execution utility.

## Problem

“Skill works” is too coarse a claim. Aggregate task success can conflate representation, outcome annotations, framework transfer, retrieval, invocation, and final execution. A skill can be correctly retrieved and still fail; a non-ground-truth but related skill can still help.

The paper therefore asks which stage actually produces the observed gain.

## Mechanism

The study holds prior experience fixed and varies how that experience is represented and consumed:

`same trajectories → Raw / Workflow Memory / SKILL.md → retrieval / selection / actual use → execution outcome`

It also removes explicit success/failure hints, transfers artifacts across agent frameworks, and performs contrastive trajectory analysis to classify *how* the injected experience changed behavior rather than recording only pass/fail.

## Compared with

The cleanest comparison is **Skill vs Workflow Memory constructed from exactly the same trajectories**. That isolates representation more effectively than comparing against no memory or a different experience corpus.

A second comparison separates three notions that are often collapsed: embedding retrieval, explicit agent selection, and actual execution-time skill use.

## Decisive evidence

Skills improve over Workflow Memory by **6.06 points** under matched source experience.

The trajectory taxonomy is more revealing than the headline gain:

- **65.7%** of skill cases are procedural anchoring;
- only **4.5%** are explicit knowledge injection.

As the skill pool grows from **5 → 100**, actual-use precision falls from **29.6% → 3.3%**, while downstream success remains comparatively stable. Exact labeled retrieval is therefore **neither sufficient nor necessary** for successful execution.

The qualitative coding is also unusually well checked: 8,135 trials are normalized, 238 valid labels retained, and human/LLM aggregation agreement is reported at **95.8%** with **κ = 0.952**.

## Main caveat

Most evidence comes from software-oriented terminal tasks and a small set of frameworks/models. The retrieval arms are diagnostics rather than one end-to-end learned router, and the study does not cover months-long libraries whose content and policy co-evolve.

Open questions:

- What should “ground-truth retrieval” mean when related non-labeled skills can be useful?
- Does procedural anchoring remain the dominant mechanism outside software/tool tasks?
- How should retrieval, invocation, and marginal execution effect be evaluated separately in growing skill libraries?

## Memory lifecycle

| Stage | Design under study |
|---|---|
| **Write** | Distill matched trajectories into Workflow Memory or SKILL.md; optionally remove outcome labels to isolate their effect. |
| **Organize** | Represent reusable experience either as cleaned trace-like memory or as a standardized procedural artifact. |
| **Read** | Measure embedding retrieval, explicit selection, actual access, and downstream success separately. |
| **Update / forget** | Not studied online; the paper evaluates fixed constructed skills, transfer, retrieval, and use. |

## Why it matters

This paper changes the evaluation target for procedural memory. A skill is not valuable merely because it is retrieved or because task success rises; the useful question is **what representation-induced behavior changed, and did that change causally improve execution?**

It also suggests that skill retrieval benchmarks should not optimize exact labels without checking whether those labels predict actual utility.
