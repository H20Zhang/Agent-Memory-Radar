# Demystifying Agent Skills：Representation、Retrieval 与 Utility 分开看

**中文** | [English](2608.14036.md) · [返回首页](../../README.md) · [Research Library](../../library/README.md)

[Paper](https://arxiv.org/abs/2608.14036) · **Importance: 4/5**

> **Research delta.** 这篇最有价值的设计是把 source experience 固定住，再比较 Workflow Memory 与标准化 Skills。结果说明：procedural memory 的收益不能简单归因给“检索到了正确 skill”；**representation、actual use 与 downstream utility 是不同阶段。**

## Problem

很多 skill/memory 工作同时改变：历史 trajectory 怎么压缩、怎么表示、怎么 retrieve、什么时候 invoke、actor 如何使用、最终任务是否成功。Aggregate success 很难告诉我们到底哪一层起作用。

尤其是“ground-truth skill retrieval accuracy”容易被当成代理指标，但一个被标成正确的 skill 可能没有被真正使用，反过来一个没有命中精确标签的 skill 也可能通过 procedure anchoring 帮助执行。

## Mechanism / experimental design

这篇工作不是靠新 runtime mechanism 取胜，而是做 matched representation comparison：

`same source trajectories → Workflow Memory or SKILL.md → matched execution → measure retrieval / selection / actual use / final success separately`

这让 representation effect 比常见的跨系统 leaderboard 更容易解释。

## Closest comparison

最关键的是 **same source experience** 下 Workflow Memory vs standardized Skills，而不是和完全不同训练数据/agent scaffold 的外部系统比较。

仍然存在的边界是：不同 representation 会自然影响 retrieval/invocation interface，因此它不是一个只改文本格式、其他全部不动的纯 representation test。

## Decisive evidence

论文报告：

- Skills 相比 Workflow Memory 提高 **6.06 points**；
- 成功 skill case 中，**65.7%** 被归为 procedural anchoring，knowledge injection 只有 **4.5%**；
- pool size 从 **5 → 100** 时，actual-use precision 从 **29.6% → 3.3%**，但 downstream success 相对更稳定。

这说明 exact retrieval label 很可能不是 skill utility 的充分 proxy。

## What remains unproven

软件任务里 procedure 相对容易标准化，所谓 “ground-truth skill” 也更容易定义。真正需要验证的是：large/evolving skill library、非 coding domain、多个相似/冲突 skill、长期更新之后，standardized procedural representation 是否仍然有稳定优势。

还要继续区分：retrieval miss、wrong invocation、正确 invocation 但 actor 未使用、以及 skill 本身低质量。

## Field-map consequence

Evaluation 不应只保留 `retrieval → task success` 两个端点，而要显式看到：

`representation → retrieval → selection → actual use → downstream utility`

这也意味着“skill retriever 更准”未必等于“memory system 更好”。
