# Reconstructing the Right Episode / TSIM

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#field-map) · [Representation & Organization](../../categories/representation-organization.md) · [中文](2608.25655.zh.md)

**Paper:** [arXiv:2608.25655](https://arxiv.org/abs/2608.25655) · **Published:** 2026-08-26 · **Importance:** 4/5

> **Research delta.** Flat mixed-topic conversation makes memory a **state-localization / episode-integrity** problem before it is a similarity-search problem. TSIM reconstructs coherent episodes and routes through hierarchical views before assembling evidence.

## Problem

Long threads multiplex unrelated tasks without explicit session boundaries. Turn-level RAG can retrieve semantically similar snippets while mixing evidence from different episodes; full context can also fail to identify which old episode the current request continues.

## Mechanism

TSIM segments the turn stream into coherent temporal-semantic episodes, creates deterministic episode summaries and cluster-level views, then routes a query through those views to reconstruct the relevant episode rather than treating history as one flat corpus.

## Compared with

The useful comparison is TSIM against strong RAG and long-context baselines on the **same flat interleaved thread**. Benchmark novelty (SCALE-QA) is evidence infrastructure; the Memory-Radar claim is about episode reconstruction.

## Decisive evidence

SCALE-QA contains 3,000 audited deterministic four-choice questions over 10 domains, evaluated through 128K context plus a 400-question 1M diagnostic. Across three open/proprietary backends, TSIM is best in every corresponding setting and improves accuracy by **5.6–17.6 points** over the strongest matched baseline.

## Main caveat

TSIM bundles segmentation, deterministic summaries, hierarchical multi-view indexing, and cluster routing. The result supports the package, not any one representation choice. Full construction/update/query latency, token, dollar, and energy cost is not matched across all baselines.

## Memory lifecycle

`flat turn stream → episode segmentation → summary + hierarchical views → query-time episode localization → reconstructed evidence → answer`

Forgetting, revocation, conflict repair, and governance remain largely outside the evaluated lifecycle.

## Why it matters

If one conversation is really many interleaved state machines, “retrieve the nearest turn” is the wrong abstraction. The first operation should be **which prior episode/state does this task belong to?**
