# MESA: Task-Adaptive Multi-Structure Evidence Selection for Long-Horizon Agent Memory

**arXiv:** [2608.10108](https://arxiv.org/abs/2608.10108) · **Published:** 2026-08-10 · **Category:** Retrieval & Access · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `episodic` `structured` `general-agent`

> **TL;DR.** MESA makes the strongest current case that multi-structure memory is a **selection/composition problem**, not a mandate to read every representation. It builds five fixed views, then learns an explicit query-adaptive subset policy from answer-level feedback.

## Problem

Once a memory system exposes several views, two easy policies are both flawed: **route-to-one** throws away complementary evidence, while **read everything** adds redundant/noisy context and token cost. The right set can vary by query.

## Core idea

Build five views of the same trajectory—**summary, temporal store, knowledge graph, vector database, and raw episodic trace**—using fixed builders. At query time an inspectable selector chooses a non-empty subset, invokes each view's native access operator, composes the evidence, and sends it to a frozen answer model. The selector is evolved using answer quality regularized by evidence-token cost, with prior-guided proposals and UCB scheduling.

## Memory design

| Stage | Design |
|---|---|
| Write | Construct five complementary views offline; builders are fixed during selector learning. |
| Organize | Keep global, temporal, relational, semantic, and raw step-level evidence in separate structures. |
| Read | Select a query-dependent subset, retrieve through each selected view, then compose evidence before a frozen answer model. |
| Update / forget | Stored views remain fixed in the evaluated setting; only the access policy evolves. Continuous update/forgetting is not studied. |

## Compared to what

The load-bearing comparisons are not only prior systems such as **AMA-Agent**. They are **route-to-one**, **all five structures**, zero-shot/random selection, and validation-selected coarse lookup policies. Those controls ask whether the gain is really from adaptive composition rather than simply having five memories available.

## Evidence

On AMA-Bench with Qwen3-32B, MESA reaches **65.1±0.8%** overall accuracy versus **56.6%** for AMA-Agent. More diagnostic: route-to-one scores **57.0%**; reading all five reaches **63.7%** using **18.7k** evidence tokens/query; MESA uses **2.8 structures / 11.0k tokens** on average and reaches **65.1%**—**+1.4 points with 41.2% fewer evidence tokens** than all-structure.

The skeptical correction is important: a validation-selected **domain-conditioned policy already reaches 64.4%**, so the extra gain from fine-grained learned selection over a strong coarse routing table is only 0.7 point. On LoCoMo, MESA reports **49.0 F1 vs 47.2** for EMem.

## Why it matters

This sharpens the radar's current thesis: **structure earns its complexity when the access layer can choose which structure the current decision actually needs**. The useful result is neither “graphs help” nor “multi-memory helps”; it is that the best query can need *several but not all* evidence interfaces.

## Limitations / questions

- The representation library is hand-chosen and fixed at five views.
- A strong coarse domain-conditioned selector is already close to MESA, so how much fine-grained policy learning is necessary remains open.
- Constructing all views adds offline cost even when read-time selection saves tokens.
- Continuously updated and multimodal memories are untested; builders/retrievers are not jointly optimized with selection.

**Curator take:** **4/5.** The route-to-one vs all-vs-adaptive ablation is unusually useful. The importance would rise if the same structure-selection principle survives online memory evolution and less hand-curated representation libraries.
