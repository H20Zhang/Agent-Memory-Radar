# SkillEvo: Self-Renewing Evolution Gradients from Multi-Turn Interaction Feedback

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md)

[arXiv 2608.13120](https://arxiv.org/abs/2608.13120) · Published 2026-08-13 · Importance **4/5** · Confidence **high**  
`procedural` `structured` `general-agent`

> **Research delta.** SkillEvo shows that sustained procedural-memory improvement is primarily a **feedback-surface problem**: multi-turn interaction keeps exposing useful defects after single-turn feedback saturates, while governance mainly prevents regression and bloat.

## Problem

Self-evolving skills often improve quickly and then plateau. The bottleneck may not be editing capacity: single-turn feedback stops revealing failures that emerge only after follow-up, constraint changes, or reactions to earlier answers. Repeated editing also creates a second problem—persistent procedural state can accumulate factual regression and structural bloat.

## Mechanism

SkillEvo separates the signal that drives an edit from the mechanism that keeps the edited artifact safe enough to persist:

`multi-turn interaction → failure attribution → bounded evidence-grounded edit → governance check/repair → persist checkpoint → repeat`

The feedback generator exposes new defects; the governor checks whether the resulting persistent skill has regressed or expanded unnecessarily.

## Compared with

The most useful control is a **single-turn-QA evolution condition** that keeps attribution, revision, governance, and round count aligned while changing the feedback source. The paper also compares against the original static production skill and multi-round self-reflection without the same interaction feedback.

This makes the feedback-source ablation more informative than a generic self-evolution leaderboard.

## Decisive evidence

Across 9 production Tencent Cloud Skills, task success rises from **30.0%** initially to **59.4 → 71.3 → 77.9 → 81.8%** over four evolution rounds.

The cleaner attribution result is:

- multi-turn interaction: **81.8%**;
- matched single-turn QA: **66.4%**.

Governance plays a different role. Removing it gives **78.6%**, but cumulative knowledge bloat rises from **+2.8% → +16.2%**. The simulator audit reports **98.9% intent coverage** and **95.3% human-rated fidelity** on 200 dialogues.

## Main caveat

The strongest signal comes from a simulator in one production support domain. The audit is useful, but the external-validity claim still depends on simulator coverage and fidelity.

Open questions:

- Does the multi-turn advantage survive real-user feedback outside a high-fidelity simulator?
- Which kinds of failure should be allowed to edit the persistent artifact versus only update short-lived control state?
- How should rollback/versioning work when a later edit helps one task family but damages another?

## Memory lifecycle

| Stage | Design |
|---|---|
| **Write** | Start from hand-authored production Skills and revise skill/reference files only from attributed failures. |
| **Organize** | Persistent procedural state lives in SKILL.md + reference files; each evolution round retains intent, evidence, edit, inspection, and outcome. |
| **Read** | The current persisted skill artifact guides later multi-turn support interactions. |
| **Update / forget** | Repeated evaluate→attribute→edit cycles; governance repairs/rejects degraded versions and persists inspected checkpoints. |

## Why it matters

SkillEvo separates two control surfaces that are easy to conflate. **Richer feedback drives most of the capability gain; governance protects the quality of accumulated state.** That suggests self-improving memory research should ask first whether the system observes the right failures before designing a more elaborate edit operator.
