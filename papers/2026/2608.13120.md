# SkillEvo: Self-Renewing Evolution Gradients from Multi-Turn Interaction Feedback

**arXiv:** [2608.13120](https://arxiv.org/abs/2608.13120) · **Published:** 2026-08-13 · **Category:** Memory Learning & Evolution · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `procedural` `structured` `general-agent`

> **TL;DR.** SkillEvo argues that sustained procedural-memory evolution is a **feedback-surface problem**: multi-turn interaction keeps exposing defects after obvious first-round gaps are repaired, while a separate governance layer limits regression and skill bloat.

## Problem

Self-evolving skills often improve quickly and then plateau. The bottleneck is not necessarily editing capacity: single-turn feedback can stop revealing the failures that only emerge after a user follows up, changes constraints, or reacts to an earlier answer. Repeated editing also risks accumulating factual regression and structural bloat.

## Core idea

Use realistic multi-turn user simulation as the evolution signal generator. Attribute each exposed failure to a skill defect, make bounded evidence-grounded revisions, and require an independent governor to inspect/repair degradation before a revised skill version is persisted.

## Memory design

| Stage | Design |
|---|---|
| Write | Start from hand-authored production Skills and revise skill/reference files only from attributed gaps surfaced by real tickets or faithful simulations. |
| Organize | Persistent procedural memory lives in `SKILL.md` plus reference files; each evolution round retains the intent, evidence, edit, inspection, and outcome for auditability. |
| Read | The current skill artifact is the reusable procedural memory consulted by the support agent during later multi-turn interactions. |
| Update / forget | `evaluate → attribute → edit → evaluate`, up to four rounds. Governance checks factual regression and bloat, repairs/rejects degraded versions, and persists only inspected checkpoints. |

## Compared to what

The cleanest comparison is not with unrelated memory systems. SkillEvo compares against the **original static production Skill**, multi-round **self-reflection without evaluation feedback**, and a **single-turn-QA evolution condition** that retains attribution, revision, governance, and round count while changing the feedback source.

## Evidence

Across 9 production Tencent Cloud Skills, task success rises from **30.0%** initially to **59.4 → 71.3 → 77.9 → 81.8%** over four SkillEvo rounds. The strongest causal result is the feedback-source ablation: replacing multi-turn interaction with single-turn QA while keeping the rest of the evolution stack gives **66.4%**, a **15.4-point** gap.

Governance has a different role. Removing it gives **78.6%**, only 3.2 points below full SkillEvo, but cumulative knowledge bloat rises from **+2.8% to +16.2%**. The simulator audit reports **98.9% intent coverage** and **95.3% human-rated fidelity** on 200 dialogues.

## Why it matters

For self-improving procedural memory, **diagnostic feedback may be scarcer than editable state**. SkillEvo separates two control surfaces that are easy to conflate: richer multi-turn feedback drives most of the capability gain, while governance mainly preserves the quality of the accumulated persistent state.

## Limitations / questions

- Evidence is concentrated in cloud technical-support skills from one production domain and organizational workflow.
- The decisive feedback signal comes from a simulator; external validity therefore depends on simulator coverage and fidelity despite the audit.
- The matched single-turn condition is a representative baseline rather than a reimplementation of every recent skill-evolution method.
- The memory artifact is explicit text/reference state; transfer to implicit policy updates or open-ended tool skills is not established.

**Curator take:** **4/5**. The important result is the clean separation between **feedback richness** and **governance**. The former drives most of the score gain; the latter prevents the memory from degrading as it evolves.
