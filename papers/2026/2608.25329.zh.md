# HiPS：Hierarchical Strategy Co-Evolution for Agent Memory

[论文](https://arxiv.org/abs/2608.25329) · [English](2608.25329.md) · [Memory Learning & Evolution](../../categories/zh/memory-learning-evolution.md)

## Research delta

HiPS 把 **memory-management policy 本身**当成 persistent adaptive state：一层跨用户共享规则，加一层 persona-specific delta。真正值得看的是 shared/personal boundary 的消融与跨模型迁移，不是 model-confounded 的总 leaderboard。

## Problem

静态 writer 必须对所有用户用同一套 retain/compress/discard 规则。全局策略会吞掉用户差异；完全个性化又容易把偶然例外固化成规则，且难 scale。

## Mechanism

Universal Strategy Distillation 从跨 persona outcome 中提炼共享管理规则；Persona Delta Distillation 只在 persona-specific predictive gain 足够时产生 local rule；Cross-Level Rule Flow 把反复成立的个人规则提升为 shared rule，并把被反例击穿的 global rule 下沉为 persona-local。查询时只注入预算内相关规则。

## Closest comparison

优先看 component ablation 与 **universal-only vs universal+persona-delta 的 cross-model transfer**。全文 system table 中部分 baseline 使用不同 backbone/checkpoint，不能把排名差异全部归因给 HiPS memory mechanism。

## Decisive evidence

PersonaMem 上 HiPS 为 `73.49/62.01`，MemSkill 为 `64.45/55.37`，但这不是完全 matched。更干净的 PERMA 消融：full 为 `66.95/56.56/63.83/56.30`；去掉 Cross-Level Rule Flow 降到 `45.39/40.87/43.12/36.50`；去 persona gate 为 `51.63/44.99/52.62/46.79`。学到的 universal+delta rule 还能迁移到不同 Qwen、GPT-4o-mini、Gemini 2.5 Flash、GPT-5 consumer，而不携带原 RL policy。

## Main caveat

distillation、persona gating、rule flow、selection、policy optimization 同时变化；总增益不能做单组件归因。dialogue 从 4K 扩到 128K 时 strategy evolution 时间大约从 140s 增到 1700s，完整维护/美元/能耗成本没有给全。

## Memory lifecycle

`cross-persona outcomes → universal rules + gated persona deltas → budgeted rule injection → profile write/transform → 后续证据驱动 promotion/specialization`

它演化的是**管理 memory 的 policy**，不是用户事实的完整 privacy/deletion lifecycle。

## Why it matters

下一层问题不是只有“存什么”，而是：**哪些 memory-management rule 应跨用户共享，哪些必须保持用户局部？** HiPS 给出这个边界本身可学习的 early signal。
