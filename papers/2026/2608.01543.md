# V-Mem: Modality-Routed Retrieval for Long-Term Multimodal Agentic Memory

**arXiv:** [2608.01543](https://arxiv.org/abs/2608.01543) · **Published:** 2026-08-02 · **Category:** Retrieval & Access · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `episodic` `multimodal` `timeline` `personalization` · **Code:** [Dingyi-Kang/V-Mem](https://github.com/Dingyi-Kang/V-Mem)

> **TL;DR.** V-Mem treats multimodal memory retrieval as a routing problem: search within a modality, cross modalities through shared conversational rounds, and generate a query-side anchor only when raw similarity cannot reach the target evidence.

## Problem

Multimodal histories violate the usual nearest-neighbor assumption in two ways. A **modality gap** makes text queries closer to text than to relevant images even in joint embedding spaces; a **similarity–relevance gap** means the item most similar to a multimodal query may still not be the evidence that answers it.

## Core idea

V-Mem keeps raw conversations as chronological rounds with separate text and image lanes. It infers both query modality and target-evidence modality, searches the appropriate lane, uses **shared-round identity** to cross modalities without directly comparing text and image vectors, and generates a hypothetical caption or image-enriched text anchor when the raw query is structurally mismatched to the evidence.

## Memory design

| Stage | Design |
|---|---|
| Write | Append raw rounds; build dense+BM25 text indexes and an image-embedding lane without LLM summarization or fact extraction. |
| Organize | Chronological rounds bind text and image units; modality-specific lanes remain separate rather than collapsing into one vector space. |
| Read | Route by query/target modality, retrieve within lanes, cross modalities through same-round matching, fuse ranks, optionally generate an anchor, and return neighbor rounds when appropriate. |
| Update / forget | Incremental append; no explicit consolidation, conflict repair, or forgetting mechanism. |

## Compared to what

The paper compares with **Omni-SimpleMem**, **M2A**, and **A-Mem** under matched answer backbones/encoders. The important delta is not a stronger multimodal embedding: it is preserving conversational structure and choosing **different access paths for different modality relations**.

## Evidence

On Mem-Gallery with gpt-4o-mini, V-Mem reports **0.825** LLM-judge score versus **0.561** for the strongest baseline, and **0.872** on provided-image questions where no baseline exceeds **0.472**. On LoCoMo it reports **0.690 vs 0.583**. The ablation is more informative than the headline: vanilla retrieval is **0.680**, +routing **0.689**, +shared-round matching **0.818**, and +generated anchors **0.825**. Thus the load-bearing mechanism is the structural same-round bridge, not the LLM-generated query anchor.

Construction is also unusually cheap: the memory build uses **zero LLM tokens**. The trade-off is that answer-time context can be larger than some extraction-based baselines.

## Why it matters

V-Mem supplies the first strong anchor in this radar's **Retrieval & Access** category. It suggests that when memory becomes multimodal, the decisive interface may be **routing + structural operators**, not one increasingly universal semantic top-k call.

## Limitations / questions

- Target-modality inference partly uses query-form heuristics and can fail when the information need is ambiguous.
- Generated anchors add only a small aggregate gain after shared-round matching and hurt some text-to-text cases.
- Evidence is long-term conversation QA, not a multimodal acting agent whose memory drives tools or environment actions.
- Open-domain LoCoMo questions are weaker than M2A in the reported breakdown, and smaller vision-language backbones change relative performance.

**Curator take:** **4/5**. The key result is unusually diagnostic: preserving round structure dominates the ablation. That is a real access-design point, though it is not yet proven outside conversational QA.
