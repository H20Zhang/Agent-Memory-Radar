# MAP-Graph: Provenance-Aware Shared Memory for Multi-Agent Workflows

**arXiv:** [2608.10509](https://arxiv.org/abs/2608.10509) · **Published:** 2026-08-11 · **Category:** Retrieval & Access · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `semantic` `graph` `general-agent`

> **TL;DR.** MAP-Graph turns provenance from audit metadata into **read/action control state**: permission eligibility, recursive ancestry trust, and action risk are distinct gates over a shared memory.

## Problem

The most relevant memory is not necessarily eligible for a reader or sufficient for a downstream action. Derived summaries can also hide restrictions inherited from earlier sources, so local metadata plus semantic ranking can produce behaviorally wrong access decisions.

## Core idea

Couple a task-scoped typed provenance graph with a semantic vector store. Retrieval first asks **CanRead**; only eligible candidates proceed. It then reranks them by `semantic score × recursive path trust`. After the agent proposes an action, a separate risk-sensitive gate can Allow, Block, Redact, Reverify, or AskUser. Revocation remains connected to descendants through recorded lineage.

## Memory design

| Stage | Design |
|---|---|
| Write | Append records with `derived_from` references and inherited permission scope from referenced inputs. |
| Organize | Typed provenance graph for agents/sources/memories/claims/actions + Chroma semantic candidates joined by memory ID. |
| Read | Semantic candidates → hard CanRead filter → recursive path-trust rerank → risk-sensitive action gate. |
| Update / forget | Append rather than overwrite; explicit revocation marks affected lineage and descendants discover revoked ancestry during later trust evaluation. No general supersession state machine. |

## Compared to what

The strongest control is **Flat Provenance**: it keeps rich per-record ownership, visibility, trust, revocation, and action-risk metadata but removes recursive ancestry/path-trust propagation. The paper also compares shared/isolated vector memories and adapted graph/collaborative/lineage mechanisms.

## Evidence

On the paper's single-run 2,700-task synthetic benchmark, MAP-Graph reports **94.96% task success / 72.70% exact decision accuracy**, versus **74.67%** best baseline task success and **51.07%** best baseline exact accuracy. Removing path-trust propagation drops task success to **87.37%** and changes the adverse-action rate from **1.52% to 8.56%**.

A more revealing ablation removes the permission filter: aggregate utility rises slightly, but **conditional unauthorized access becomes 100%**. That is the paper's strongest conceptual result—endpoint utility can hide a violated read boundary.

## Why it matters

The contribution is not “use a provenance graph.” It is the decomposition of memory admissibility into three different control problems: **may this agent read it, how much inherited trust should it carry, and is it sufficient for this action's risk?** That makes provenance executable state.

## Limitations / questions

- Synthetic templated tasks, simulated actions, and only one four-agent round.
- Main results are one temperature-zero run, so inference nondeterminism is not estimated.
- Several external baselines are core-mechanism adaptations rather than full reproductions.
- The action-risk group still contains 9.11% impermissible Allow decisions; trust/risk constants are hand-designed.

**Curator take:** **4/5.** Strong design decomposition and useful boundary metrics, but the importance depends on transfer to genuinely long-running, consequential multi-agent workflows.
