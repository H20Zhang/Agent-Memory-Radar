# When Not to Imitate: Boundary-Aware Skill Memory for Reliable Tool-Use LLM Agents

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#field-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md) · [中文](2608.22339.zh.md)

**Paper:** [arXiv:2608.22339](https://arxiv.org/abs/2608.22339) · **Published:** 2026-08-23 · **Importance:** 4/5 · **Confidence:** Medium

> **Research delta.** A retrieved skill needs a validity boundary, not only a procedure. Applicability, risk, avoidance, and recovery fields reduce imitation traps, but the full package is not Pareto-improving.

## Problem

Success-derived procedures can look relevant while prescribing the wrong tool in a changed state.

## Mechanism

BASM writes seven-field skills from successful, failed, and partial trajectories, validates them, retrieves under a fixed budget, and applies, suppresses, or locally repairs a skill after a boundary check.

## Compared with

Procedure Skill uses the same backbone and retrieval but stores only goal, procedure, and tools. Equal-token padding and same-prompt attention knockouts test whether boundary text—not length alone—changes the actor.

## Decisive evidence

Qwen3-8B Base/Procedure/BASM scores are **34.13/33.88/38.88** on BFCL and **29.76/33.33/36.31** on AppWorld. AgentDojo ASR falls to **5.90**, but utility **35.93** remains below Base **40.99**. Boundary knockout recovers **69.4%** of the wrong-tool gap.

## Main caveat

Representation, failed-trajectory admission, retrieval, formatting, checker, and repair change together. Prompt-BASM and Repair-only hurt AppWorld; several slices reverse. Extraction, validation, embedding, checker, repair, latency, dollars, GPU-hours, and energy are unreported.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Seven-field skills include validity and recovery state. |
| Organize | A schema/tool validator retries or discards malformed skills. |
| Read | Fixed-budget retrieval is followed by an applicability gate and optional repair. |
| Update / forget | No dynamic boundary update, forgetting, or long-horizon maintenance. |

## Why it matters

Relevance is not authorization to imitate; procedural memory needs an explicit post-retrieval validity contract.
