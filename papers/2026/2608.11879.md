# Total Recall at What Cost? Benchmarking the Serving Cost of Agentic Memory Systems

**arXiv:** [2608.11879](https://arxiv.org/abs/2608.11879) · **Published:** 2026-08-12 · **Category:** Evaluation & Analysis · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `semantic` `text` `general-agent`

> **TL;DR.** Dedicated memory is not automatically cheaper than resending history. The break-even point is an end-to-end property of the memory pipeline, backbone, message size, and conversation length—not a consequence of smaller retrieved context alone.

## Problem

Memory systems are often sold on a simple cost story: replace an ever-growing transcript with a small retrieved payload. That ignores the system's own ingest, extraction, reflection, consolidation, retrieval, and answer calls. Until these are measured together, “memory saves serving cost” is an assumption.

## Core idea

Replay identical conversations through **Mem0, Hindsight, Mastra Observational Memory**, a ten-turn rolling window, and full-history prompting. Meter billed model input across ingest/retrieval/answer, model cost as separate functions of message size and conversation depth, compute sustained break-even against full history from measured per-turn cost, and pair each configuration with LoCoMo answer accuracy.

## Memory design

| Stage | What the benchmark measures |
|---|---|
| Write | Native ingest cost: extraction / reflection / consolidation when each system triggers it. |
| Organize | Systems keep their native representations; the benchmark does not force a common storage model. |
| Read | Native retrieval plus answer-generation cost under common backbone/reasoning configurations where controlled. |
| Update / forget | Native lifecycle behavior is measured rather than replaced by a new policy. |

## Compared to what

The two critical references are a **ten-turn rolling window** as a cheap non-persistent floor and **full-history resubmission** as the cost ceiling. The paper then compares three materially different memory pipelines under the same workload grid.

## Evidence

A depth×message-size regression predicts the two reference strategies with only **2.9–6.5% held-out error**, but misses the memory systems by **18–69%**—evidence that internal memory state/pipeline events dominate their cost surface.

Across measured 400-turn workloads, sustained break-even against full history spans **Mastra OM: 0–86 turns; Mem0: 0–342; Hindsight: 60–never**. At 400 turns full history can be **12.7×** more expensive than a memory system that has crossed break-even, while Hindsight can still be **3.3×** more expensive than full history in small-message cases. Accuracy spans roughly **21–54%**, with no configuration dominating both cost and accuracy.

## Why it matters

The systems lesson is stronger than another cost table: **memory economics depends on maintenance behavior**. A system that retrieves few tokens can still lose if its ingest/reflection pipeline is expensive or irregular. Memory benchmarks therefore need cost surfaces and break-even regions, not isolated token-savings claims.

## Limitations / questions

- Cost dialogues are synthetic; real content can change extraction/consolidation frequency.
- Accuracy is one stratified LoCoMo subset, not tool-using/task-oriented agents.
- The fitted model is descriptive and extrapolates poorly for memory systems.
- Hindsight's ingest backbone was not controlled across cells, so its cross-backbone comparisons are invalid.
- Provider routing/caching and serving-stack token-count behavior add deployment-specific variance.

**Curator take:** **4/5.** This adds a missing evaluation axis and, importantly, produces a negative result: a dedicated memory system may not pay for itself in the workload you actually run.
