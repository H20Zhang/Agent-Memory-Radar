# MemGuard：让 Verifier 信号贯穿 Agent Memory 生命周期

[English](2608.21867.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#field-map) · [写入、更新与整合](../../categories/zh/write-update-consolidation.md)

**Paper:** [arXiv:2608.21867](https://arxiv.org/abs/2608.21867) · **Published:** 2026-08-22 · **Importance:** 4/5 · **Confidence:** Medium · **Artifact:** [代码](https://github.com/whyyyyy123/MemGuard)

> **Research delta.** Verifier signal 只有在 admission 之后仍持续控制 retrieval、冲突处理、summarization 与 archival，才真正成为 memory state。最接近的 verifier-only 对照在所有均值上落后，但论文没有报告这一对照的显著性检验。

## Problem

One-shot filter 无法治理已经误接收且继续活跃的记录，也无法随 bank 增长处理重复、过时和冲突状态。

## Mechanism

MemGuard 给每个候选附加 reward、confidence、label 与 uncertainty，并在 activation、retrieval、conflict resolution、merge、summary、archive 及 actor guard context 中复用。

## Compared with

生命周期最匹配的对照是相同任务顺序、step、retrieval 与 context budget 下的 Verifier-only Filter。No-memory、四个 memory system 以及简化/随机 descriptor 用于约束 package claim。

## Decisive evidence

在 16 个 backbone-benchmark cell、五个 seed 上，MemGuard 的 success 与 steps 均值最好。Qwen Plus 上 full/verifier-only 为 **67.4/63.7**、**83.6/79.8**、**58.4/52.0**、**51.8/46.8**。BH/Holm 检验针对 ReasoningBank，并非这一最接近对照。

## Main caveat

Full 与 verifier-only 仍同时改变多个生命周期算子。只用 `{label, confidence}` 距 full 仅 **0.7–1.5 points**，random/uniform weight 也很接近。Verifier/governance 增加 **4.0–5.8k tokens**；calibration drift、美元、能耗、隐私与删除成本未报告。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | Activation 前附加 verifier descriptor。 |
| Organize | Descriptor 控制冲突、合并、摘要和归档。 |
| Read | Retrieval 与 actor guard context 读取持久 verifier state。 |
| Update / forget | Maintenance 复用 descriptor；未审计删除和 calibration drift。 |

## Why it matters

如果可靠性证据在后续使用与维护前消失，安全 admission 本身不够。
