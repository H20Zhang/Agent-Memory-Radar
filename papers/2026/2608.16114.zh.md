# HyperSkill：Hypergraph-Structured Skill Memory

**中文** | [English](2608.16114.md) · [返回首页](../../README.md) · [Research Library](../../library/README.md)

[Paper](https://arxiv.org/abs/2608.16114) · **Importance: 4/5**

> **Research delta.** HyperSkill 的研究点不是“把 vector store 换成 hypergraph”，而是让 trajectory 中的高阶关系真正进入 **retrieval、skill ranking 与 maintenance**。Structure 是否有价值，要看这些关系有没有改变 read/update operator。

## Problem

Flat trajectory / skill store 可以保存过去经验，却容易丢掉“哪些 subtask 一起出现、哪些 skill 在哪些 trajectory 中共同成功、哪些 skill 已经冗余或低效”这类 higher-order relation。

但仅仅存 graph/hypergraph 并不自动构成贡献；真正的问题是：**关系结构是否在执行时提供了 flat store 难以便宜恢复的操作。**

## Mechanism

核心 read/update path 可以压成：

`task → subtask retrieval + trajectory retrieval → fuse retrieved hyperedges → co-occurrence-based skill ranking → execute → extract/update skills → utility/structure-aware prune/merge`

Hypergraph 因而不是 passive metadata，而是影响 candidate construction、skill ranking 与长期维护。

## Closest comparison

论文比较 No Memory、若干 experiential-memory baseline，并提供 w/o hypergraph、w/o subtask retrieval、w/o trajectory retrieval 等消融。

最值得质疑的是 `w/o hypergraph`：它不仅换掉 representation，也改变了 dual-path structural access pipeline。因此这不是一个纯 representation-matched control。

当前实验更强地支持：**“hypergraph + dual-path retrieval + structural ranking/maintenance”这套 package 有用**，而不是单独证明 hypergraph 比 flat/binary graph 表示不可替代。

## Decisive evidence

Qwen3 的 task success（xBench / GAIA / WebWalkerQA）：

- full: **52.00 / 36.97 / 50.59**
- w/o hypergraph: **41.00 / 35.76 / 44.71**
- w/o subtask retrieval: **43.00 / 32.73 / 47.06**
- w/o trajectory retrieval: **48.00 / 35.76 / 43.53**

这说明 structural pipeline 不是装饰；尤其不同 retrieval path 在不同 benchmark 上承担的作用并不相同。

## What remains unproven

最有判别力的下一步是固定 decomposition、retrieval budget、dual-path controller、ranking 与 maintenance，只替换：flat store / binary graph / hypergraph representation。

还要计入 graph construction、update、pruning 和 retrieval latency；否则“更强 relation”可能只是把额外工作移到 memory lifecycle 的其他阶段。

## Field-map consequence

HyperSkill 强化的是：

`organization structure → access operator → maintenance policy`

这三个阶段应联合分析，但不能在 attribution 上混成一个“structured memory”标签。
