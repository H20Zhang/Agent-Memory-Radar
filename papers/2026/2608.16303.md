# FTA-Mem: Fact-Time-Affect Anchored Memory for Low-Density Long-Term Dialogue

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Write, Update & Consolidation](../../categories/write-update-consolidation.md)

[arXiv 2608.16303](https://arxiv.org/abs/2608.16303) · Published 2026-08-17 · Importance **3/5** · Confidence **high**  
`episodic` `structured` `timeline` `personalization`

> **Research delta.** FTA-Mem turns memory-unit granularity into an explicit **quality × construction-cost** parameter: situation-level units beat coarse sessions on sparse dialogue while costing less than turn-pair memory, but they are not universally more accurate on denser data.

## Problem

Long-term support dialogue is low-density: useful evidence can be distributed, implicit, and only meaningful when facts, time, and affect are interpreted together. A writer therefore faces a granularity trade-off:

- session-level memory is cheap but can mix several situations and erase detail;
- turn/turn-pair memory preserves detail but fragments coherent events and increases construction cost.

The question is where to draw the **persistent event boundary**.

## Mechanism

FTA-Mem builds situation-level **Fact-Time-Affect** units with boundary preservation:

`dialogue → coherent window → partial FTA units → carry unresolved boundary evidence → fuse adjacent fragments → temporal links → retrieve → structured context`

A unit keeps factual evidence with temporal grounding and affect/intention/relation cues. Incomplete evidence near a segment boundary remains open long enough to absorb the adjacent fragment before persistence.

## Compared with

The broader baselines include long-term dialogue-memory systems such as MemoryBank, MemGPT, MemoryOS, A-Mem, and CompassMem. The more useful comparison directly varies write granularity:

- session-level;
- turn-pair;
- situation-level FTA-Mem.

That exposes the actual operating-point trade-off rather than hiding it inside an architecture leaderboard.

## Decisive evidence

On ES-MemEval:

| Granularity | F1 | Construction tokens |
|---|---:|---:|
| Session | 31.76 | **1.58M** |
| Turn-pair | 37.06 | 6.40M |
| FTA-Mem | **38.71** | 4.99M |

On LoCoMo the ordering changes: turn-pair reaches **38.28 F1** versus FTA-Mem **37.35**, but costs **7.04M** versus **3.39M** construction tokens.

This reversal is the result to remember: FTA-Mem is a **density-dependent operating point**, not a universally dominant memory representation.

## Main caveat

The density/implicitness story is strongest on ES-MemEval and does not reproduce consistently on LoCoMo. The method is also motivated by affect-rich support dialogue, so transfer to tool, code, or embodied agents remains uncertain.

Open questions:

- Can granularity be adapted online as evidence density changes rather than fixed globally?
- Does the cost-quality trade-off survive acting-agent workloads where bad segmentation causes downstream action errors?
- Which fields must be protected when situation units are later compressed or consolidated?

## Memory lifecycle

| Stage | Design |
|---|---|
| **Write** | Segment into situations, carry unresolved boundary evidence forward, and fuse adjacent fragments before finalizing a persistent unit. |
| **Organize** | Store Fact + Time + Affect together, with temporal links and source provenance. |
| **Read** | Retrieve, deduplicate, and synthesize selected units into a structured context packet. |
| **Update / forget** | Adjacent evidence can be fused before finalization and longitudinal links can be added; deletion/conflict repair/learned forgetting are not central. |

## Why it matters

FTA-Mem gives a useful negative rule for agent-memory research: **there may be no globally optimal memory-unit size**. Write granularity should be evaluated against evidence density, downstream quality, and construction cost rather than justified only by semantic intuitiveness.
