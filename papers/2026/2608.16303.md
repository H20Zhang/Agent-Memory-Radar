# FTA-Mem: Fact-Time-Affect Anchored Memory for Low-Density Long-Term Dialogue

**arXiv:** [2608.16303](https://arxiv.org/abs/2608.16303) · **Published:** 2026-08-17 · **Category:** Write, Update & Consolidation · **Importance:** 3/5 · **AI confidence:** High

**Tags:** `episodic` `structured` `timeline` `personalization`

> **TL;DR.** FTA-Mem treats memory-unit granularity as a cost-quality control for sparse, implicit dialogue. Situation-level Fact-Time-Affect units preserve more QA-relevant evidence than session summaries while avoiding some of the construction cost of turn-pair memory. The important caveat is that finer turn-pair memory still slightly wins on denser LoCoMo, so this is a density-dependent trade-off rather than a universally better representation.

## Problem

Long-term emotional-support dialogue is unusually **low-density**: useful evidence may be spread across many turns, stated indirectly, or depend on how facts, time, and affect interact. A memory writer therefore faces a bad granularity trade-off:

- **session-level** units are cheap but can erase details and mix several situations;
- **turn/turn-pair** units preserve local evidence but are expensive and can fragment one coherent event into redundant pieces.

The question is not simply what fields to store, but **where the persistent memory boundary should be drawn**.

## Core idea

FTA-Mem builds **situation-level Fact-Time-Affect (FTA) units** using a boundary-preserving pipeline.

`dialogue → coherent window → partial FTA units → carry unresolved units across boundary → fuse adjacent evidence → finalize ID + temporal links → retrieve → structured context packet`

Each persistent unit keeps factual evidence together with temporal grounding and affect/intention/relation cues. If evidence near a segment boundary is incomplete, the unit can remain open and absorb the adjacent fragment before persistence.

## Memory design

| Stage | Design |
|---|---|
| Write | Boundary-preserving window segmentation; construct situation-level units and carry/fuse unresolved evidence across adjacent fragments before assigning persistent IDs. |
| Organize | Fact + Time + Affect in one unit, with temporal links to related historical units and provenance to source dialogue. |
| Read | Retrieve, deduplicate, and synthesize selected units into a structured context packet rather than a flat passage list. |
| Update / forget | Adjacent evidence can be fused before finalization and links added longitudinally; explicit conflict resolution, deletion, or learned forgetting are not central. |

## Compared to what

The paper compares with **MemoryBank, MemGPT, MemoryOS, A-Mem, CompassMem**, and other long-term dialogue-memory methods. More importantly, it directly varies the **construction granularity**:

- session-level;
- turn-pair;
- situation-level FTA-Mem.

That comparison is more useful than another architecture leaderboard because it exposes the actual resource trade-off.

## Evidence

On **ES-MemEval**, FTA-Mem reaches **38.71 F1 / 66.68 BERTScore**. The key systems comparison is:

- session-level: **31.76 F1**, **1.58M** construction tokens;
- turn-pair: **37.06 F1**, **6.40M** tokens;
- FTA-Mem: **38.71 F1**, **4.99M** tokens.

This is a real middle operating point: more evidence preservation than coarse session memory with lower write cost than very fine memory.

But the conclusion changes on **LoCoMo**. Turn-pair reaches **38.28 average F1** versus FTA-Mem **37.35**, while requiring **7.04M** construction tokens versus **3.39M**. So FTA-Mem is not universally more accurate; it offers a different quality/cost point.

The component ablation also supports the representation: removing **temporal information** causes the largest degradation, with affect and links contributing smaller gains. On ES-MemEval, FTA-Mem's gain over CompassMem increases when factual density is lower (**r = -0.39**) and implicitness higher (**r = 0.41**), but that pattern does not reproduce consistently on LoCoMo.

## Why it matters

FTA-Mem gives the radar a useful negative rule: **there may be no globally optimal memory-unit granularity**. The right write unit depends on evidence density, implicitness, and the price of construction.

That matters beyond emotional support. Any persistent agent stream with sparse but jointly meaningful events—tool failures, human feedback, project state—should be evaluated against coarse and fine controls rather than assuming one semantic segmentation policy is optimal.

## Limitations / questions

- The density correlation is benchmark-specific; it is clear on ES-MemEval and inconsistent on LoCoMo.
- Turn-pair memory slightly wins LoCoMo quality, so the method's advantage is partly efficiency, not pure accuracy.
- Affect is especially motivated by support dialogue; transfer to code/tool/embodied agents is uncertain.
- Evaluation remains long-term dialogue QA, not consequential longitudinal action.

**Curator take:** **3/5**. A useful systems result because it quantifies granularity rather than hand-waving about “semantic memory units.” The contribution is narrower and domain-specific, and the denser-benchmark result correctly prevents a stronger universal claim.
