# Causal Episodic Memory for Feedback-Driven Agent Repair

**arXiv:** [2608.05906](https://arxiv.org/abs/2608.05906) · **Published:** 2026-08-06 · **Category:** Write, Update & Consolidation · **Importance:** 3/5 · **AI confidence:** High

**Tags:** `episodic` `structured`

> **TL;DR.** MERIT is more valuable as a controlled negative result than as a new memory architecture: cross-query repair experience helps over stateless repair, but its typed dual-polarity structure is **not reliably better than a simpler untyped dynamic-retrieval memory**.

## Problem

Execution-guided repair agents usually discard a correction once the current task ends. A later task with a similar failure must then rediscover the same repair, even though the earlier finalized episode contained useful evidence.

## Core idea

After each finalized Text-to-SQL episode, MERIT stores **positive memory** (oracle-verified successful correction transitions) and **negative memory** (finalized unsuccessful directions). For a later repair, a deterministic classifier predicts a coarse failure type, then a hybrid dense + BM25 retriever searches only **earlier finalized episodes** of the relevant type before the frozen model proposes a revision.

The paper calls this “causal” because retrieved memory is temporally prior to the current query. It is **not causal attribution of memory contribution**.

## Memory design

| Stage | Design |
|---|---|
| Write | Persist oracle-confirmed successful repair transitions and final unsuccessful directions after an episode finishes. |
| Organize | Separate by polarity and coarse failure type while retaining schema/task context. |
| Read | Type-conditioned hybrid lexical+dense retrieval over causally prior finalized episodes. |
| Update / forget | Append new finalized evidence online; no learned forgetting or semantic consolidation beyond fixed eligibility/retrieval rules. |

## Compared to what

Three comparisons matter: **stateless iterative repair** with identical initial SQL/budget, **untyped dynamic retrieval** from earlier finalized episodes, and **Reflexion-style memory** with substantially higher inference cost.

The second is the skeptical baseline: it tests whether MERIT's extra typing/polarity machinery is actually load-bearing.

## Evidence

With Qwen2.5-7B-Instruct and matched initial predictions/budgets, MERIT improves execution accuracy from **66.34% → 69.79% on Spider** and **47.35% → 48.44% on BIRD** over stateless iterative repair.

But the interpretation should stop there: paired evidence is clear on Spider and weaker on BIRD, and **MERIT is not reliably separated from untyped dynamic retrieval on either benchmark**. Reflexion reaches **51.24% on BIRD** at substantially higher inference cost.

## Why it matters

This is a useful correction to a common memory instinct: **more structure is not automatically better memory**. Cross-query experience is valuable here; the specific failure typing, polarity, and hybrid ranking do not establish a robust extra gain over a simpler dynamic memory.

## Limitations / questions

- “Causal” means temporal eligibility, not estimation of marginal causal memory utility.
- Oracle-assisted benchmark feedback is needed to label successful corrections.
- The structured design is not reliably better than untyped dynamic retrieval.
- Evidence is concentrated on Text-to-SQL repair with one frozen 7B model.

**Curator take:** **3/5**. Useful and unusually honest evidence, but the main structured-memory mechanism does not clear a strong enough incremental baseline for a 4/5 rating.
