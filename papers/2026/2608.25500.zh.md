# CaSKG：面向可扩展 Agent Skill Retrieval 的反事实关系校准

[English](2608.25500.md) · [← 最新论文](../../README.md#latest) · [Retrieval & Access](../../categories/zh/retrieval-access.md)

**Paper:** [arXiv:2608.25500](https://arxiv.org/abs/2608.25500) · **Importance:** 4/5 · **Confidence:** Medium · **Tags:** `procedural` `graph` `structured` `general-agent` · **Code:** [ZhiyuanLi218/Caskg](https://github.com/ZhiyuanLi218/Caskg)

> **Research delta.** 这篇真正值得带走的不是“causal graph 能解决 skill retrieval”，而是：**graph 本身就是一个有风险的 access policy**。在 skill library 和 downstream agent loop 都冻结时，只改变哪些 edge 可以传播 relevance，就能稳定改变后续任务行为；未经校准的 graph retrieval 甚至会比 full-library exposure 更差。

## 研究问题

Procedural memory 变大后，访问端有三种典型选择：把整个 skill library 塞给模型、按 embedding 独立检索、或沿关系图扩展相关 skill。第三种能找回 prerequisite、verification、repair 等文本不近但流程相关的 procedure，却引入新的失败模式：一条“看起来相关、实际上不可执行”的边一旦参与 propagation，就会把错误 procedure 一起放大进上下文。

## Mechanism

CaSKG 把“找到可能的关系”和“允许关系参与 retrieval”拆开：

`冻结 skill library → 多信号候选有向图 → 有预算的文本反事实 probe → Bayesian edge support/state → 发布加权图 → query seed → graph diffusion → compact skill bundle → 不变的 actor`

候选边来自 lexical、semantic、input/output 和 structural evidence。系统只对预算内的候选做方向化 textual counterfactual：移除 source skill、换成不相似 skill、反转顺序，用来估计 necessity、specificity 和 order dependence。随后做 Bayesian smoothing，把 edge 分成 confirmed、uncertain、rejected 或低权 scaffold；运行时再用 lexical/semantic seed 启动 personalized-PageRank-style expansion。

## 最近的公平比较

最关键的对照不是 Vector Skills，而是 **Graph-of-Skills (GoS)**：两者都使用同一冻结的 Skill1000，都离线建图再做 query-conditioned graph propagation，而且 downstream prompt、evaluator、episode limit 和 environment loop 保持不变。这能直接检验“更可靠的 graph relation 是否真的改变 later behavior”。Full-library Vanilla Skills 和 Vector Skills 分别提供 coverage 与 non-relational 对照；另外还有 semantic-only、去掉 LLM judge、以及 publish-all-candidate 的 construction ablation。

## 决定性证据

六个 backbone 的 macro average 上，相比 GoS，ALFWorld success 从 **80.01%→86.79%**，ScienceWorld official score 从 **72.62→80.50**；12 个 model×benchmark cell 中，CaSKG 的 mean environment steps 都少于 GoS。最有信息量的是 GPT-5.6-Luna 的 ALFWorld：**72.86% full library / 55.00% Vector / 60.71% GoS / 75.71% CaSKG**。也就是说，graph retrieval 本身并不是优势；错误结构会主动伤害 access。

MiniMax-M2.7 的 ALFWorld construction ablation 更能定位阶段：完整 CaSKG 为 **73.57%**；把 **9,937** 条 candidate edge 全部发布只有 **71.43%**；去掉 optional LLM judge 也是 **71.43%**；只用 semantic candidate 则是 **67.14%**。这支持“candidate breadth + selective edge calibration”这套 integrated stage，但还不能把收益唯一归因给某一个 counterfactual probe 或 Bayesian rule。

## 仍未证明什么

论文报告的 Steps 只是 environment interaction count，不包含 retrieval latency、graph-construction inference、token、美元或能耗，因此 lifecycle break-even 仍未知。Counterfactual probe 是 LLM 对文本 procedure 的模拟判断，不是环境中的真实 intervention，所以证据更直接支持 **edge-confidence calibration**，而不是强意义上的 causal graph。主结果也没有 repeated seed、confidence interval 或 significance test。最后，官方 GitHub 仓库已经存在，但核验时仍没有实际实现代码，因此 reproducibility 目前有限。

## 生命周期边界

`frozen procedural artifacts → offline relation induction/calibration → published skill graph → query-conditioned access → future execution`

- **Write：** 评测中不写新 skill；离线阶段只在已有 Skill1000 上生成 relation evidence。
- **Organize：** skill 成为有向图节点，候选 edge 经过 multi-signal 与 counterfactual evidence 形成 publication state。
- **Read：** query seed 沿发布后的 graph 扩散，只暴露 compact relational bundle 给 actor。
- **Update / Forget：** 离线 construction 可以确认、降权或拒绝 edge；没有评测 online skill edit、delete、drift 或长期 graph maintenance。

## 对领域地图的影响

这是 **skill-edge-confidence-calibration 的 `early_signal`**，不足以改 durable Field Map。更重要的研究门槛是：以后 graph/procedural-memory work 应该与强 graph baseline 做 matched control，并把 graph construction + maintenance cost 一起算进去。只有这样才能回答“structure 到底提供了不可替代的操作”，而不是“结构更复杂所以分数更高”。
