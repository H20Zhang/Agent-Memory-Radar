# Harness Continual Learning: Continual Adaptation Beyond Model Parameters

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md) · [中文](2608.19013.zh.md)

**Paper:** [arXiv:2608.19013](https://arxiv.org/abs/2608.19013) · **Published:** 2026-08-19 · **Importance:** 4/5 · **Confidence:** High
**Tags:** `episodic` `procedural` `structured` `general-agent`

> **Research delta.** Frozen model weights do not mean frozen behavior. Harness Continual Learning versions prompts, experience memory, capability maps, and routing together, then makes state commitment conditional on current improvement, historical retention, and validity.

## Problem

Modern agents adapt through execution-facing state outside the model. Updating a prompt, memory, skill map, or router can erase earlier behavior even if the foundation model never changes. Conventional parameter-centric forgetting metrics miss that failure.

## Mechanism

A Continual Optimizer proposes a candidate harness from post-execution feedback. The candidate jointly contains a Task Interface, Experience Memory, Capability Map, and Adaptive Router. A Continual Evaluator checks current utility, historical anchors, and validity before atomic commit under a configurable retention bound.

## Compared with

Static Harness, RAG, MemP, and MemRL run through a unified executor. The memory-stage witness is Full HCL versus no Experience Memory update. A retention-bound sweep isolates the governance trade-off, while headline gains remain package-level.

## Decisive evidence

On ALFWorld, RAG reaches **55.56** final average, Stability-HCL **61.74**, and Plasticity-HCL **62.98**; the plastic variant also incurs **10.94** forgetting. Unrestricted commitment (`b=∞`) ends at **60.13**, below **63.46** at `b=1`.

Removing memory update yields **62.28 / 0.83 forgetting** versus **63.41 / 0.45** for Full HCL. This is a narrow memory-stage signal inside four co-adapting components—not proof that memory explains the total system gain.

## Main caveat

The package jointly changes four states, and their interactions matter. Historical anchors can only guard measured regressions, and the paper reports no complete construction/evaluation/storage/serving cost or public implementation.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Post-execution feedback proposes raw/abstract experiences and other harness changes. |
| Organize | Jointly version Task Interface, Experience Memory, Capability Map, and Router. |
| Read | The four components condition frozen-model execution together. |
| Update / forget | Evaluate current gain, historical retention, and validity before commit; measure harness-level forgetting. |

## Why it matters

The commit boundary, not the model boundary, defines continual agent state. Guarded evolution is therefore a governance result for the whole harness; memory-component claims must stay tied to the narrower ablation.
