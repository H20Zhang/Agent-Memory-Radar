# Harness Continual Learning：模型权重不变，Agent 仍然会遗忘

[English](2608.19013.md) · [← 最新论文](../../README.md#latest) · [记忆学习与演化](../../categories/zh/memory-learning-evolution.md)

**Paper:** [arXiv:2608.19013](https://arxiv.org/abs/2608.19013) · **Importance:** 4/5

> **Research delta.** Agent 的 prompt、experience memory、capability map 与 router 都是会改变后续行为的持久状态。HCL 把候选更新的生成与 commit 分开，用当前收益、历史保留和 validity 共同决定是否接受。

## 研究问题

即使 foundation model 冻结，更新 harness 中的 prompt、memory、skill mapping 或 routing rule 仍可能破坏过去可靠的行为。只看 parameter forgetting 会漏掉这种 harness-level forgetting。

## Mechanism

Continual Optimizer 根据执行反馈提出 candidate harness；其中四个 execution-facing components 联合 version：Task Interface、Experience Memory、Capability Map、Adaptive Router。Continual Evaluator 在 commit 前检查 current utility、historical anchors 与 validity，并施加 retention bound。

## 最近的公平比较

Static Harness、RAG、MemP、MemRL 使用统一执行栈。Memory component 的最近 witness 是 Full HCL 对 w/o Memory update；retention sweep 用来审计 governance trade-off。Headline 仍只能归因给整套 evolving harness。

## 决定性证据

ALFWorld 上，RAG final average 为 **55.56**，Stability-HCL **61.74**，Plasticity-HCL **62.98**；但后者 forgetting 达 **10.94**。无限制 commit（`b=∞`）最终 **60.13**，低于 `b=1` 的 **63.46**。

w/o Memory update 为 **62.28 / 0.83 forgetting**，Full HCL 为 **63.41 / 0.45**。这是 co-adaptive package 内较窄的 memory-stage evidence，不代表 memory 主导总增益。

## 仍未证明什么

四个状态共同变化，存在 interaction effect；historical anchors 只能保护被测行为。论文也未提供完整 construction、evaluation、storage 与 serving lifecycle cost，且没有公开代码。

## 生命周期边界

`feedback → candidate harness → current/historical/validity evaluation → atomic commit → future execution`

## 对领域地图的影响

这是一条 **guarded evolution early signal**：continual agent 的治理边界应放在 harness commit，而不只看模型参数；单个 memory component 仍必须由独立消融承担归因。
