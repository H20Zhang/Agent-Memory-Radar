# Skill2Query：用 Skill Structure 生成可执行的 Pseudo-Queries

**中文** | [English](2608.16071.md) · [返回首页](../../README.md) · [Research Library](../../library/README.md)

[Paper](https://arxiv.org/abs/2608.16071) · [Code](https://github.com/MatZaharia/Skill2Query) · **Importance: 3/5**

> **Research delta.** Skill retrieval 的 query/document mismatch 不只是 wording 问题：用户描述 goal，而 skill 文档描述 capability、parameter 与调用约束。Skill2Query 用 skill structure 约束 pseudo-query generation，让 synthetic query 更接近“可调用这个 skill 的真实请求”。

## Problem

普通 document-level pseudo-query generation 可以生成主题相关的问题，却可能忽略函数 parameter、capability boundary 或调用条件。对 procedural memory 来说，“文本像不像”不等于“这个 skill 能不能完成任务”。

## Mechanism

`skill document → capability / parameter / example graph → capability template → parameter filling + validation → pseudo-query augmentation / retriever training / optional online expansion`

核心变化是先把 skill 拆成可执行语义结构，再生成 pseudo-query，而不是直接让 LLM 围绕整份文档自由改写。

## Closest comparison

论文比较 zero-shot / few-shot / SkillFlow-style pseudo-query generation，并在 BM25、dense retriever、SkillRouter 等设置下评估。

更有信息量的是去掉 skill graph 的生成质量消融，因为它直接测试结构是否约束了 functional validity。

## Decisive evidence

ToolQA 上 offline augmentation 后，SkillRouter R@1 从 **35.80% → 47.34%**。

去掉 skill graph 后：

- pseudo-query Exec-Pass: **42.85% → 22.63%**
- functional coverage: **11.32% → 2.41%**

这说明结构对于生成“功能上成立”的训练 query 有明显作用。但 online query expansion 并非稳定增益，在部分 setting 会变差。

## What remains unproven

当前证据主要证明 retrieval-side alignment；它还不能说明 end-to-end agent execution 一定改善。下一步需要把 `retrieval hit → skill invocation → parameter grounding → task success` 拆开，并在大规模、持续演化 skill library 上测试。

## Field-map consequence

它把 procedural-memory access 的一个重要轴显式化：

`surface semantic similarity ↔ capability/parameter-grounded relevance`

这更像 retrieval representation / training-data design point，而不是完整 memory architecture。
