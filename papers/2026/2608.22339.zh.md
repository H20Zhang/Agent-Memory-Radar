# When Not to Imitate：Boundary-Aware Skill Memory

[English](2608.22339.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#field-map) · [记忆学习与演化](../../categories/zh/memory-learning-evolution.md)

**Paper:** [arXiv:2608.22339](https://arxiv.org/abs/2608.22339) · **Published:** 2026-08-23 · **Importance:** 4/5 · **Confidence:** Medium

> **Research delta.** Retrieved skill 不能只有 procedure，还需要 validity boundary。Applicability、risk、avoidance 与 recovery 字段能减少 imitation trap，但完整 package 并非 Pareto-improving。

## Problem

由成功轨迹抽取的 procedure 可能语义相关，却在状态变化后指定错误工具。

## Mechanism

BASM 从成功、失败和部分轨迹写出七字段 skill，完成 schema/tool 验证后在固定预算内检索，再通过 boundary check 决定 apply、suppress 或 local repair。

## Compared with

Procedure Skill 使用相同 backbone 与 retrieval，只保存 goal/procedure/tools。Equal-token padding 与同 prompt attention knockout 用来区分 boundary text 和长度效应。

## Decisive evidence

Qwen3-8B 的 Base/Procedure/BASM 在 BFCL 为 **34.13/33.88/38.88**，AppWorld 为 **29.76/33.33/36.31**。AgentDojo ASR 降至 **5.90**，但 utility **35.93** 仍低于 Base **40.99**；移除 boundary attention 可恢复 **69.4%** 的 wrong-tool gap。

## Main caveat

Representation、失败轨迹准入、retrieval、format、checker 与 repair 同时改变。Prompt-BASM 和 Repair-only 在 AppWorld 退化，多处 slice 反转。Extraction、validation、embedding、checker、repair、latency、美元、GPU-hours 与 energy 均未报告。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 七字段 skill 保存 validity 与 recovery state。 |
| Organize | Validator 重试或丢弃不合格 skill。 |
| Read | 固定预算检索后执行 applicability gate 与可选 repair。 |
| Update / forget | 未测动态 boundary 更新、遗忘与长期维护。 |

## Why it matters

相关不等于可以模仿；procedural memory 需要 post-retrieval validity contract。
