# Can Agent Memory Systems Track Evolving State?

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#research-map) · [Write, Update & Consolidation](../../categories/write-update-consolidation.md) · [中文](2608.19652.zh.md)

**Paper:** [arXiv:2608.19652](https://arxiv.org/abs/2608.19652) · **Published:** 2026-08-20 · **Importance:** 4/5 · **Confidence:** Medium
**Tags:** `semantic` `structured` `timeline` `general-agent`

> **Research delta.** StateMemBench scores current versus superseded answers instead of treating both as retrieval success. StateMem makes supersession and recomputation explicit, but dependency propagation is unstable and its strongest matched result comes from a separate answer-time full-transcript wrapper—not from persistent storage.

## Problem

A memory system may retrieve every relevant fact and still act on a stale budget, retired constraint, or derived value whose inputs changed. Existing recall-shaped benchmarks rarely isolate this state drift.

## Mechanism

StateMemBench contains 234 synthetic multi-session scenarios and 322 probes. A deterministic event program computes the operative state and several executable lazy-reader policies compute plausible stale answers. Closed-pool grading separates `gold`, `drift`, `other`, and `off-pool` outcomes.

Persistent StateMem writes sourced units with priority and typed dependencies. Superseded units remain for audit but are inactive. A deterministic rechecker marks dependent units `needs_recheck`; one answer call receives active state and recomputation guidance.

StateMemWrapper is a separate experiment. It has no store and no per-turn processing: at answer time it reads the full numbered transcript plus unchanged retrieved chunks, writes a query-conditioned value chain, then resolves precedence and recomputes the current state.

## Compared with

The closest persistent controls are staged ablations: extraction-only, extraction plus supersession, full without dependency propagation, and full without recomputation guidance. Cross-system comparisons include same-backbone long context, retrieval, graph-RAG, and four memory systems.

For the wrapper claim, the strongest control fixes the backend, retrieved chunks, full transcript, one answer call, 250-word intermediate budget, commit-before-answer format, and judge. It replaces explicit state tracing with a generic question-conditioned summary.

## Decisive evidence

On DeepSeek-V4-Flash, persistent StateMem reaches **0.363**, versus **0.205** for Dense and **0.199** for A-Mem. Extraction-only is **0.174**; adding supersession reaches **0.298**; removing recompute guidance falls to **0.301**. Dependency propagation does not pay globally: removing it improves **0.363→0.373** and avoids a **12.5-point** Set-B anti-trap penalty.

On Qwen, StateMem is **0.233** versus Mem0 **0.149**, but statistically level with GraphRAG **0.224** (paired McNemar **p=0.82**). External results are narrower: on DeepSeek, StateMem is **0.656 vs 0.666** long context on LongMemEval and **0.592 vs 0.587** on LoCoMo; gains concentrate in drift-shaped question types.

Across six backends, StateMemWrapper contributes **+15.0 to +31.7 points** beyond its matched generic-summary control on StateMemBench. This is strong evidence for query-conditioned state resolution, but the wrapper reads the full transcript and is not persistent memory.

## Main caveat

The synthetic benchmark is generated and filtered around the same supersession/recomputation policy family StateMem implements, so its own-benchmark margins are an in-distribution upper bound. Every configuration is a single run under one fixed DeepSeek-family judge, and some released baselines produce many non-answers.

Cost changes the interpretation. Persistent StateMem performs roughly **165–600 ingestion LLM calls per scenario**; tokens, latency, dollars, store growth, maintenance, and amortization are not reported. The wrapper avoids ingestion but reads median **8.6k / 87k input-token transcripts** and adds about **350 tokens** beyond its control per question. No tool execution or multi-step action outcome is evaluated.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | One TurnEncoder LLM call per conversational turn writes sourced state units. |
| Organize | Track active, superseded, and needs-recheck units with priority, dates, and dependencies. |
| Read | Render active state for a final answer call; the separate wrapper instead scans the full transcript. |
| Update / forget | Retire superseded units without deleting audit history; flag dependent values for recomputation. |

## Why it matters

Current-state resolution is a lifecycle boundary distinct from recall. A benchmark should penalize answers that retrieve the right history but consume the wrong operative state. The paper provides notable early evidence for supersession and query-conditioned resolution, not a general proof that structured persistent memory dominates simpler systems.
