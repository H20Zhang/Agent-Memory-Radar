# Weighted Memory Tree：长任务中哪些状态应继续保持活跃

[English](2608.20631.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [检索与访问](../../categories/zh/retrieval-access.md)

**Paper:** [arXiv:2608.20631](https://arxiv.org/abs/2608.20631) · **Published:** 2026-08-21 · **Importance:** 3/5 · **Confidence:** Low
**Tags:** `episodic` `hierarchical` `structured` `general-agent`

> **Research delta.** WMT 把 selection-driven active retention 放到 retrieval 之前：task tree 通过 score、decay、fold 与 suppression 决定哪些 execution branch 进入后续 prompt。现有证据支持的是一套耦合的 within-task working-memory package，而不是 cross-session memory，也不是某条 scoring rule。

## Problem

线性 execution history 会随长任务持续增长，并把过期或失败 branch 一并暴露给 actor；系统缺少“哪些状态仍应活跃”的显式策略。

## Mechanism

每道 GAIA 题都会新建 task/subtask/action tree。Event 使用固定 outcome score，未被选择的记录会 decay，branch priority 逐层聚合，完成轨迹被折叠成 summary，低优先级内容可 suppression 或 reopen。LLM 选择出的 tree view 会进入后续 prompt。

## Compared with

Linear History 是最接近的 end-to-end control：model、task、tool、instruction 与 limit 都相同。`Tree + Selection + Summary` 是最接近的 mechanism control，但 Full WMT 仍同时加入 score、decay、priority 与 suppression 等多个规则。

## Decisive evidence

在 127 题 GAIA-Text subset 上，linear→WMT accuracy 分别为 Qwen **20.47→33.86**、Gemma **24.41→33.07**、Llama **9.45→17.32**；prompt token 分别从 **43.67→32.48M**、**65.27→37.85M**、**73.96→51.17M**。165 题 GAIA 包含该 subset，不能算独立 replication。

Full 在报告的 GAIA cell 上都胜过最接近的 partial package，但组件效果并不单调：GAIA-Text 的 Llama 上，`Tree+Summary` 为 **19.69**，高于 Full 的 **17.32**。被保留的状态确实改变 episode 内的后续动作和最终答案。

## Main caveat

每道题都从空树开始，论文设想的 global promotion 没有评估。研究没有 seeds、paired test、confidence interval、逐题 trace 或公开 artifact。Poison 实验使用作者构造场景，并给已标为 failure 的记录低分，因此不能证明 robust truth detection。

Prompt-token accounting 包括 selector 与 summary；全研究报告 **6,132 次执行 / 2.391B prompt tokens**，硬件为 8 张 RTX 6000。Output tokens、wall time、GPU-hours、美元、持久 storage 与 energy 仍缺失。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | Action、observation、event、task 与 subtask 进入每题新建的 tree。 |
| Organize | Hierarchy、outcome score、decay、branch priority、fold 与 suppression 调节 active state。 |
| Read | Selected/folded state 进入后续 prompt，改变 within-task behavior。 |
| Update / forget | 可见性与权重变化，但未测试 durable deletion 或 cross-session forgetting。 |

## Why it matters

Active working memory 可能需要在 retrieval 之前做 retention decision；但 package win 不能被提升成 long-term memory 或 dynamic scoring 的单独收益。
