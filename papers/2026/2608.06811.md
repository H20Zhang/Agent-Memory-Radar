# Coupling Planning with Episodic Memory in LLM Agents for Software Issue Resolution

**arXiv:** [2608.06811](https://arxiv.org/abs/2608.06811) · **Published:** 2026-08-07 · **Category:** Retrieval & Access · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `episodic` `structured` `coding`

> **TL;DR.** PMCoder makes planning and memory a bidirectional control loop: the current repair phase changes what episodic evidence is retrieved, while memory-derived trajectory statistics decide when the planner is stuck and should backtrack or replan.

## Problem

Long software-repair trajectories span exploration, hypothesis formation, implementation, and verification. Repository agents often strengthen **planning** or **memory** separately, which creates a mismatch: evidence useful during exploration is not necessarily useful during verification, repeated failed edits can remain invisible to the planner, and the agent can mistake its own completion claim for execution evidence.

## Core idea

PMCoder couples a deterministic hierarchical phase planner to episodic memory in both directions:

`plan phase → retrieval policy → retrieved evidence → actions/observations → memory statistics → stuck detection / replanning`

The planner phase and active subtask condition retrieval anchors, scoring, and token budgets. In the reverse direction, edit counts, repeated actions, read saturation, and other trajectory signals can trigger backtracking or replanning. When an issue-reproduction script is available, its verdict grounds verification in execution rather than self-report.

## Memory design

| Stage | Design |
|---|---|
| Write | Mirror observations/actions into episodic nodes with role, recency, compact content, file/edit metadata, and trajectory statistics; injected context is not recursively re-ingested. |
| Organize | Chronological episodic nodes plus an incremental file/code-structure graph from imports, co-occurrence, and trajectory adjacency. |
| Read | Phase-conditioned anchors and budgets drive MMR retrieval over episodic evidence plus code-structure signals. |
| Update / forget | Append observations continuously; memory statistics can change planner state. Selection/truncation is query-time; no semantic consolidation or cross-issue forgetting policy is central. |

## Compared to what

The main baseline is a **harness-matched repository agent** without the coupled substrate. More importantly, the paper includes a **2×2 planner × memory component study**, which is the right comparison for the claim that coupling matters.

Portability is also probed with an OpenHands port and other model backbones.

## Evidence

On SWE-bench Verified with Qwen3-Coder-30B, PMCoder resolves **167.33/500 vs 142.33/500** cases on average for the matched baseline: **+25 cases, +5.0pp**.

The sharper result is the factorial ablation: plan only **+1.3pp**, memory only **+1.7pp**, full plan + memory **+5.0pp**, reported interaction **+2.1pp**, `F(1,8)=10.92, p=.011`.

An OpenHands port reports **+4.6pp**. Additional model and TerminalWorld probes point in the same direction, but several are single-run because of cost.

## Why it matters

The important result is not “memory helps coding.” It is that **memory access can be a function of explicit controller state, and memory can in turn modify that controller state**. That is a stronger architectural claim than adding a vector store beside a planner.

## Limitations / questions

- The strongest repeated evidence is concentrated on SWE-bench Verified and one primary local model.
- Several portability probes are single-run, so transfer evidence is directional rather than definitive.
- The 2×2 ablation supports planner-memory interaction but does not independently isolate every auxiliary mechanism, especially execution grounding and edit recovery.
- The memory is primarily within-issue episodic state; transfer across independent software issues is not the demonstrated contribution.

**Curator take:** **4/5**. The systems idea is broadly reusable and the interaction ablation is unusually useful. The paper would become more important if the same bidirectional coupling survived non-coding agents where controller phases are less hand-designed.
