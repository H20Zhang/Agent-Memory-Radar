# Hindsight Memory-PRM: Supervising Memory Management with Auditable Hindsight Credit

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#field-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md) · [中文](2608.29605.zh.md)

**Paper:** [arXiv:2608.29605](https://arxiv.org/abs/2608.29605) · **Published:** 2026-08-30 · **Importance:** 5/5

> **Research delta.** Hindsight Memory-PRM makes memory-policy credit auditable: it separates episode reward, observational use, and controlled entry deletion under one shared memory scaffold and fixed reader. The useful claim is about supervision placement, not a new storage architecture.

## Problem

A long-horizon manager makes roughly dozens of Write/Merge/Noop decisions before an episode score arrives. Outcome-only RL therefore cannot tell whether a specific persistent entry later mattered or merely co-occurred with a successful trajectory.

## Mechanism

The system logs every managed read path and answer citation. Entries never touched by any read path are certified inert under the stated retrieval invariant; source-anchored probes then run one controlled deletion-and-reanswer for cited entries. These observations train an operation-conditioned memory-utility critic and provide online ordinal entry-presence credit, which is propagated along non-destructive version chains as an action-level proxy.

## Compared with

The decisive controls are inside the same scaffold: untrained/SFT, outcome-only GRPO, observational attribution, and the full intervention-calibrated method. Matched-scale and shuffled-flip controls test whether the final gain is just denser or larger reward. External memory systems remain system-level references because their interfaces differ.

## Decisive evidence

LoCoMo moves **58.6 untrained → 62.5 SFT → 63.4 outcome-only → 70.2 observational → 77.5 full** under the same retriever, reader, and judge. The final **+7.3 points** changes only the flip-promotion/toxicity branches; matched-scale and shuffled-flip controls stay at **70.6/70.5**. Deleting the **74.6%** of entries outside every logged read path changes accuracy by only **−0.1 points**, while deleting cited entries costs **12.4 points**. LongMemEval repeats the reward ladder at **66.0 → 72.5 → 79.0**.

## Main caveat

Deletion identifies whether the final **entry is necessary for a fixed reader/probe**, not the ideal counterfactual value of the original Write or Merge action. Chain propagation remains a proxy (sampled replay Spearman **0.72**). Schema transfer is also incomplete: direct LoCoMo→LongMemEval falls to **58.4**, while schema adaptation without policy retraining reaches **71.2** versus **79.0** native. The audit is expensive: about **1.6M API calls / $1.1k** for three LoCoMo seeds and **9.8M / $6.5k** for LongMemEval.

## Memory lifecycle

`conversation → Write/Merge/Noop → event/profile/verbatim layers + version chains → deterministic retrieval → citation/deletion audit → critic + intervention-calibrated policy learning`

The evaluated lifecycle is deliberately lossless; destructive forgetting, privacy deletion, retention budgets, and revocation are not established.

## Why it matters

This raises the evidence standard for learned memory managers. A credible claim should distinguish **entry-presence utility**, **action-level credit**, and **total supervision cost** instead of assigning a packaged trajectory gain to the memory writer.
