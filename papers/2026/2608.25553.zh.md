# When Stale Constraints Go Unchecked

[论文](https://arxiv.org/abs/2608.25553) · [English](2608.25553.md) · [Evaluation & Analysis](../../categories/zh/evaluation-analysis.md)

## Research delta

这篇把 stale-memory failure 变成一个很干净的 **fixed-budget verification-allocation** 实验：provenance 仍然正确，唯一关键变量是 consumer 会不会把两个 verification slot 里的一个花在能发现 supersession 的路径上。

## Problem

一个约束写入时可以完全正确，但后来被新的 authoritative record 撤销。只“保留 provenance”并不等于会使用 provenance；budget-limited agent 如果行动前不检查这条路径，仍会按 stale belief 做决策。

## Mechanism

Memory 历史上指向 `S0`；superseded world 中 `S1` 后来撤销该 constraint，但继承的 one-line memory 不重新 consolidation。固定 `k=2` verification credits，对比 native record choice 与同预算下强制把一个 slot 指向 critical provenance path。

## Closest comparison

最有判别力的是 **native vs forced-critical，且 verification budget 完全相同**；再用 source 仍与 memory 一致的 valid world 作为 control。它比两个不同 memory architecture 的总分对比干净得多。

## Decisive evidence

constraint 明示时，native agent 只在 20.1% / 23.1% 的 primary / fresh-wording episode 检查目标 provenance。constraint 已 supersede 时，native 决策仍与 stale memory 一致的比例为 77.3%、74.7%、74.7%。强制检查 critical path 后，current-record-consistent decision 从 `34/150→145/150`（+74.0pp）、`38/150→147/150`（+72.7pp）、`38/150→130/150`（+61.3pp）；修正 held-out robustness run 为 +73.3pp。memory 仍有效时，同样 intervention 只改变 0–2pp。

## Main caveat

forced-critical 用的是**实验者已知的 critical path**。它能识别 allocation 导致多少错误，不是可部署 scheduler，也没有证明 production 中 stale stated constraint 的基率。

## Memory lifecycle

`write/consolidate S0 → preserve provenance → S1 supersedes S0 → inherited stale belief → 选择 2 条 verification path → 根据已检查证据行动`

真正缺的是 freshness / supersession-aware verification allocation。index 维护、reconsolidation、美元/能耗与隐私成本没有完整测量。

## Why it matters

**Relevance 和 freshness 是两种控制问题。** 最影响当前决策的 memory，反而可能因为“看起来已经给出限制”而最少被核验。后续系统应该在同预算下比较 relevance-only access 与可部署的 freshness / cost-of-being-wrong verification policy。
