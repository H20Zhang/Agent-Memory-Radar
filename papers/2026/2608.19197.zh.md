# SPADE：用跨 Episode 环境记忆引导训练课程

[English](2608.19197.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [记忆学习与演化](../../categories/zh/memory-learning-evolution.md)

**Paper:** [arXiv:2608.19197](https://arxiv.org/abs/2608.19197) · **Published:** 2026-08-19 · **Importance:** 3/5 · **Confidence:** Medium
**Tags:** `procedural` `structured` `general-agent` · **Code:** [spade-rl/spade](https://github.com/spade-rl/spade) · **Project:** [SPADE](https://spade-rl.github.io/)

> **Research delta.** 一个有界的跨 episode memory，把过去生成的可执行环境提供给后续 Environment Designer。移除这条 memory path 会降低一次 30B training package 的 selected benchmark average，但现有证据不能把差异归因给 regret retrieval 或 FIFO retention。

## Problem

开放式自我改进需要持续生成位于 learner 当前能力边界附近的训练环境。无状态的 designer 容易重复已有任务，或生成过易、过难甚至无效的环境。

## Mechanism

SPADE 让同一个 LLM 承担两个角色：Environment Designer 编写带 `reset()/step()` 的可执行环境，Reasoning Agent 在这些环境中学习。系统用有提示与无提示的 reward gap 估计 regret，并把环境代码、skill、win rate、regret 与 rollout identity 写入持久 buffer。

下一次生成前，designer 会读取最多两个同 skill 的 high-regret 代码片段，以及一个过易或过难的 negative description。Buffer 最多保留 200 条，按 oldest-first 淘汰。

## Compared with

最接近的 control 是官方 `NO_ENV_MEMORY=1` launcher：30B base model、corpus grounding、trainable designer、400-rollout GRPO recipe、24 个环境、hint 机制和 regeneration cadence 都保持不变。但移除 memory 也会同时移除约 4,000 字符的 demonstration 与一个 negative descriptor；论文没有 token-matched static、random、score-shuffled 或其他 retention-policy control。

## Decisive evidence

八个 game benchmark 上，full run 的 selected checkpoint 平均 **58.3**，w/o memory 为 **53.2**。差异主要来自 Reasoning-Gym Math（**63.3 vs 49.1**）、Algorithmic（**32.1 vs 22.9**）和 Cognition（**37.7 vs 30.7**）；AIME 2026 反而是 full 较低（**74.4 vs 75.0**）。

8 月 24 日的 v2 revision 新增 30B actor 的 full-package tool-use 结果：BFCL-v4 MT **+5.7 points**，ACEBench-Agent **+13.9**。这扩展了 package 的 external validity，但没有隔离 environment memory。

Memory 也没有提升论文报告的 diversity：Vendi/n 为 **0.68 full vs 0.69 w/o memory**；真正让该指标降至 **0.04** 的是移除 corpus grounding。因此，现有证据只支持 memory prompt path 对整个训练 package 有贡献。

## Main caveat

每个配置只有一次 training run，而且每个 variant 都在最终报告的同一套八个 benchmark 上选择最佳 checkpoint；full 与 w/o memory 的峰值 step 也不同。Memory ablation 同时改变 prompt 长度与内容，released construction 没有给 memory sampler 显式 seed，公开 artifact 也不能对应到表格里的 exact no-memory run。因此 **5.1 分差异不能单独归因给 regret ranking、200 条容量或 FIFO forgetting**。

完整 pipeline 还包含 400 个 rollout、24 个环境、反复的 hinted/unhinted plays、generation retry、validation 与单个八 GPU 节点，但没有报告 GPU-hours、token、wall time、美元或能耗。

V2 tool-use 比较的是 full package 与外部系统，不是同一 tool-use training pipeline 上关闭 environment memory，因此不能提高 memory component 的因果归因。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 写入通过验证的环境代码、skill、win rate、regret 与 rollout metadata。 |
| Organize | Flat、skill-tagged buffer，上限 200 条。 |
| Read | 向后续 designer prompt 注入两个 high-regret 同 skill 示例和一个极端 negative。 |
| Update / forget | 根据新 outcome 追加，按 oldest-first 淘汰；最终 Reasoning Agent 在 inference 时不读取该 memory。 |

## Why it matters

Agent memory 不只服务部署期 actor，也可以决定**接下来生成什么经验用于学习**。这类 training-side state 需要独立的 control 与成本核算。SPADE 是这个边界的一条 early signal，不证明 environment memory 造成了整套 self-play 增益。
