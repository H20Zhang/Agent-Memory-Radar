# SkillGate: Training In-Policy Skill Selection in Long-Horizon Agents

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Retrieval & Access](../../categories/retrieval-access.md) · [中文](2608.18852.zh.md)

**Paper:** [arXiv:2608.18852](https://arxiv.org/abs/2608.18852) · **Published:** 2026-08-19 · **Importance:** 4/5 · **Confidence:** High
**Tags:** `procedural` `text` `general-agent` · **Code:** [DeepExperience/SkillGate](https://github.com/DeepExperience/SkillGate) · **Model:** [SkillGate-9B](https://huggingface.co/simonlqy/SkillGate-9B)

> **Research delta.** A skill library and the policy that accesses it are different memory components. In one 9B run, SkillGate's oracle-supervised local selector channel changes exposure and trial success, but three coupled loss changes prevent attribution to credit location alone.

## Problem

Long-horizon agents choose a skill file early and execute for thousands of tokens afterward. Broadcast trajectory reward gives the few selector tokens almost none of the loss mass and punishes a correct read whenever later execution fails.

## Mechanism

SkillGate partitions one GRPO update into disjoint supports. Outcome advantage trains execution tokens; a group-centered, oracle-supervised advantage trains the skill-name tokens and is positive only for a clean single-oracle read. The read call is masked from task loss, and selector loss mass is normalized independently of its small token count.

## Compared with

SkillRL (outcome only) shares the Qwen3.5-9B initialization, SFT checkpoint, data, 100 steps, and hyperparameters. Relative to it, SkillGate jointly adds privileged oracle utility, removes the read-call span from task loss, and renormalizes selector loss mass. Credit ablations narrow pieces of this package, while external routers test whether better top-1 selection alone transfers to agent success.

## Decisive evidence

Across 385 trials on five benchmarks, SkillGate reaches **53.2%** success versus **47.0%** for outcome-only SkillRL and **40.8%** for SFT. Oracle exposure moves **54.3%→83.9%**; misleading exposure falls **69.6%→21.8%**.

The pooled repeated-task difference is **+7.9pp**, with a task-clustered 95% interval of **+2.1 to +14.3**. The pass@4 interval and every individual-benchmark interval cross zero. The audit of 12,800 outcome-only trajectories finds identity tokens at a median **0.14%** of loss weight and frequent wrong-signed credit; this supports the failure hypothesis but is not a randomized mechanism test.

## Main caveat

Each configuration has one 16-H800 training run; task bootstrap is not seed replication. Training assumes verified oracle identity and synthesized hard negatives, and the positive selector signal is built around one clean read. The method changes three loss-design choices together. Open libraries with no oracle, changing skills, or compositional multi-skill use remain untested.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Fixed external skill files; no artifact learning. |
| Organize | A candidate slate with names/descriptions, including oracle and misleading skills. |
| Read | In-policy read/skip/identity choice receives the oracle-supervised local selector objective. |
| Update / forget | Model weights learn the access policy; the skill library itself is not updated or retired. |

## Why it matters

Procedural-memory evaluations should report selection supervision, actual exposure, downstream execution, and serving cost separately. Current evidence supports the local oracle-supervision package as an early signal, not credit placement as an isolated cause.
