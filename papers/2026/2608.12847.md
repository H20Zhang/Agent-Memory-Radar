# Beyond Retrieval: Query-Conditioned Reuse of Long-Horizon Agent Trajectories

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Representation & Organization](../../categories/representation-organization.md)

[arXiv 2608.12847](https://arxiv.org/abs/2608.12847) · Published 2026-08-13 · Importance **4/5** · Confidence **high**  
`procedural` `text` `web-agent`

> **Research delta.** QCR isolates a distinct **post-retrieval reuse** bottleneck: with the same selected trajectory, a target-bound support object outperforms direct trace injection by forcing stale source bindings to be reacquired from current state.

## Problem

Retrieval answers **which past trajectory may help**. It does not answer **how the current agent should use it** when users, files, object IDs, dates, constraints, or environment state have changed. Full-trace injection can copy stale bindings; a source-only summary can be shorter but still does not specify what must be rebound or when reuse should be declined.

## Mechanism

After one historical trajectory is already selected, QCR writes a compact support object with four fields:

1. **workflow invariant** — reusable action/decision structure;
2. **bindings to re-obtain** — source-specific values that must be reacquired from current evidence;
3. **applicability conditions** — when the old procedure should not be reused;
4. **verification guardrail** — what must be checked before completion.

`fixed retrieval/selection → QCR support object → reacquire current bindings → execute → verify`

The persistent trajectory bank remains unchanged; the intervention changes only the actor-facing representation of the same selected memory.

## Compared with

This is the paper's strongest experimental property. Candidate retrieval, target state, actor model, decoding, and tool budget are held fixed while only the delivery representation changes.

The key baselines are **Full Trajectory** and a length-matched **Generic Summary**. That makes the result much cleaner than comparing two end-to-end memory pipelines whose retrieval quality also differs.

## Decisive evidence

Across **2,391** WebArena, WorkArena, and AppWorld targets, QCR reaches **62.3%** average success, **+10.7pp** over Full Trajectory, while using **9.4k** online tokens versus **18.4k** for direct trace injection (**−48.9%**).

Under large binding shift, the mechanism becomes especially visible:

- stale-binding errors: **46.9% → 10.9%**;
- correct rebinding: **31.7% → 77.8%**;
- utility under large shift: **+20.1pp** for QCR versus **+2.2pp** for Full Trajectory.

Selection is already strong, which pushes the remaining bottleneck downstream of retrieval rather than back into the retriever.

## Main caveat

The source memories are successful trajectories and only one selected memory is injected. The evidence therefore supports target-conditioned reuse more strongly than it supports this exact four-field schema or multi-memory composition.

Open questions:

- Can the support writer remain faithful when several memories conflict?
- Which fields are truly necessary, and which are artifacts of this task family?
- How should reuse reason about irreversible side effects or policy constraints beyond verified task completion?

## Memory lifecycle

| Stage | Design |
|---|---|
| **Write** | Cache successful source trajectories plus compact descriptors; generic source summaries are constructed offline. |
| **Organize** | Keep the persistent bank unchanged; QCR constructs a target-bound support object after selection. |
| **Read** | Fixed retrieval/reranking selects one trajectory; the actor receives Full Trajectory, Generic Summary, QCR, or No Memory under matched target conditions. |
| **Update / forget** | Not studied; the experiment isolates reuse of verified historical trajectories rather than lifecycle editing. |

## Why it matters

QCR makes a clean systems distinction: **good archival evidence can still be the wrong actor-facing state**. Long-horizon procedural memory should therefore be evaluated as `retrieve → select → adapt for current state`, not as retrieval alone.
