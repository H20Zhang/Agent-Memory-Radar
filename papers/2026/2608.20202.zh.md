# MemTrapBench：评估记忆使用中的认知陷阱

[English](2608.20202.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [评估与分析](../../categories/zh/evaluation-analysis.md)

**Paper:** [arXiv:2608.20202](https://arxiv.org/abs/2608.20202) · **Published:** 2026-08-20 · **Importance:** 3/5 · **Confidence:** Medium
**Tags:** `episodic` `semantic` `text` `general-agent` · **Code:** [zjunlp/MemTrapBench](https://github.com/zjunlp/MemTrapBench)（核验时仍为空占位仓库）

> **Research delta.** MemTrapBench 把 retrieval 后的 applicability 变成可测 failure boundary：语义相关的历史也可能让当前答案变差。No-memory 优势只对这套 adversarial stress-test distribution 成立；AdaptiveMem 是匹配 benchmark taxonomy 的 prompt，不是经过验证的通用 admission policy。

## Problem

Memory evaluation 通常只问系统是否提取、检索了正确信息。即使历史有效且相关，actor 仍可能被旧策略、特殊个案或被污染的信念锚定。

## Mechanism

Benchmark 含 1,050 条 synthetic history：350 条 Task Boundary、350 条 Cognitive Bias、200 条 Safety、150 条 Trauma。GPT-5.4 将人工 seed 扩成 18–40 turn 对话。每个 final query 都被设计为无需历史即可独立解答，而 prior dialogue 会植入 reasoning-fixation 或 belief-distortion trap。

论文在 Gemini-3-Flash-Preview 与 Qwen3-30B-A3B-Instruct-2507 上比较 no memory、full history 与四种 memory framework。AdaptiveMem 是 answer-time system prompt：它列出四种 trap，要求模型识别当前任务、拒绝不适用历史，并优先服从 current query。

## Compared with

No-memory 能直接检验加入历史是否改变答案，但 benchmark 有意让 standalone-solvable current query 占优势。最接近 lifecycle-matched 的证据是 limited trap-free control：任务与 relevant history 保持不变，只删除设计的 trap；该对照仅覆盖 Task Boundary 与 Trauma。

AdaptiveMem 固定 memory framework，但没有 length-matched neutral warning prompt、unseen trap category，也没有用 mixed workload 测量错误拒绝 useful memory 的代价。

## Decisive evidence

Gemini 上 no-memory 平均 **85.16**，最强 memory arm EverMemOS 为 **71.17**。Qwen 上 no-memory **81.83**，FullText **70.99**、LightMem **70.13**。这些是四个 judge dimension 的平均，不是单纯 accuracy；而且并非所有 subgroup 都受害，例如 Qwen FullText 在 Trauma 上反而 **87.17→90.27**。

有限的 matched control 更有解释力。Task Boundary 在 no-memory、trap-free history、trap-inducing history 下分别为 **92.29 / 94.39 / 31.05**；Trauma 为 **86.73 / 84.33 / 69.43**。这支持 trap semantics 在这些 synthetic subset 中因果改变后续回答。

AdaptiveMem 在三个 Gemini memory arm 上分别增加 **11.8 / 14.9 / 11.3 分**，Qwen 上为 **4.2 / 2.5 / 2.6**；随机 200-item sample 没有 uncertainty estimate。

## Main caveat

MemTrapBench 是 adversarial diagnostic：每个当前问题都被构造成不需要历史，而 prior dialogue 专门生成 trap。因此大的 no-memory 优势测量的是 conditional susceptibility，不是现实 trap prevalence，也不是 memory 的净效用。QC 没有报告 annotator 数量、一致性、reject rate 或 released audit；framework version、retrieval budget 与配置同样缺失。

Headline score 平均 LLM-judged correctness、format、relevance 与 efficiency。Table 1 没有 confidence interval 或 paired test，不同 judge 的绝对分也有明显差异。AdaptiveMem 直接描述 benchmark taxonomy，因此只支持 benchmark-aligned prompt mitigation。论文没有报告 ingestion、access、latency、token、storage、美元、maintenance 或 forgetting cost。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | Generated history 由 full context 或四个未配平的 memory package 接收。 |
| Organize | 各 framework 的 compression 与 hierarchy 没有被单独控制。 |
| Read | Retrieved/full history 改变 final answer；AdaptiveMem 在使用前加入 applicability check。 |
| Update / forget | 未测试 evolving stream、expiry、conflict repair 或 maintenance policy。 |

## Why it matters

Retrieval correctness 并不足够。Actor 还需要 admission decision，在保留有用证据的同时拒绝会误导当前任务的历史。MemTrapBench 是这条 consumer-side boundary 的 early signal，不证明 memory 普遍有害，也不证明一个 prompt 已解决 admission。
