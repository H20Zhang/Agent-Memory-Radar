# Explicit State Elicitation Is Not Enough: A Controlled Audit of Memory-Policy Classification

[Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Evaluation & Analysis](../../categories/evaluation-analysis.md)

**Paper:** [arXiv:2608.17247](https://arxiv.org/abs/2608.17247) · **Published:** 2026-08-18 · **Importance:** 3/5 · **Confidence:** High  
**Tags:** `semantic` `structured` `personalization`

> **Research delta.** An explicit intermediate memory-state label is **not automatically a useful state variable**. On a matched counterfactual set, taxonomy instructions help, but requiring a state output does not significantly improve Use/Ignore/Update/Ask decisions.

## Problem

Personalized agents often convert retrieved memories into an intermediate label—use, ignore, update, ask, conflict type, validity state—and then treat that label as evidence that the decision process became more structured or faithful.

That inference is weak when datasets contain lexical shortcuts or when the label deterministically maps to the final policy. A model can become sensitive to the label without the label improving reasoning.

## Mechanism

The paper first audits a 480-example development set and finds lexical separability plus no positive standalone Ignore cases. It then freezes a controlled **160-example set: 40 matched four-way counterfactual families** with byte-identical task text inside each family and rule-derived policies.

It compares clean classification, taxonomy-only instructions, explicit state-output prompting, forced correct/wrong labels, and a decomposed semantic-evidence variant.

## Compared with

The cleanest comparison is **taxonomy-only vs explicit state-output prompting**. Both expose the meaning of the policy/state categories; only the latter forces the model to emit a structured intermediate label before the final decision.

Forced-label interventions are treated as sensitivity diagnostics, not proof of mechanism, because those labels map deterministically to policy classes.

## Decisive evidence

On Llama, clean accuracy is **44.0**, taxonomy-only **53.1**, and explicit state-output **44.6**: the isolated state field is only **+0.6 (p=.808)**. GPT-OSS goes **54.8 → 59.8** with taxonomy and **58.1** with explicit state, a marginal **+3.3 (p=.071; Holm .142)** relative to clean.

A Llama semantic-evidence follow-up scores **55.8 vs 63.3** for policy-only prompting (**−7.5; Holm .0146**). Making the intermediate representation richer does not rescue the causal claim.

## Main caveat

The audit stops at **policy classification**. It does not execute downstream responses, tool actions, or actual memory-store mutation, so a structured intermediate state could still help later behavior even if the classification metric does not improve.

The controlled set is deliberately small/synthetic, and one GPT-OSS semantic-evidence condition was unavailable because of provider-side request validation.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | No persistent-memory writer; constructs controlled counterfactual examples. |
| Organize | Four matched memory-policy families with rule-derived Use / Ignore / Update / Ask labels. |
| Read | Varies taxonomy exposure, state-output elicitation, forced labels, and semantic evidence before policy classification. |
| Update / forget | Store mutation is not executed; this is an audit of the decision interface. |

## Why it matters

The negative result is methodological: **interpretability is not causality**. A readable intermediate field should earn its place by changing downstream behavior under matched conditions, not because it looks like explicit state.
