# TRUSS：把生成的 Skill 当成需要认证后才能持久化的可执行 Artifact

[English](2608.17588.md) · [← 最新论文](../../README.md#latest) · [Research Library](../../library/README.md)

**Paper:** [arXiv:2608.17588](https://arxiv.org/abs/2608.17588) · **Importance:** 4/5

> **Research delta.** TRUSS 给 procedural memory 增加了一个 promotion gate：生成的 skill 先经过 static function/safety obligations，再进入 controlled shadow execution；只有运行证据也通过，artifact 才值得成为可复用 persistent capability。

## 还没被解决的问题

Skill 文本看起来正确，并不意味着它执行后安全。静态检查观察不到 hidden side effects、危险 tool calls 或与自然语言声明不一致的 runtime behavior；只看最终 task success 也会漏掉 unsafe intermediate action。

## Mechanism

`generate → static obligations → shadow execution → provenance trace → function/safety record → refine → re-check → promote`

候选 skill 在 brokered tools 与 breaker 保护下执行，runtime trace 被保留并回连到具体 skill content；修复后必须重跑完整检查。

## 最近的公平比较

检测侧最干净的是同一批 SkillInject artifacts 上的 **LLM checker → static checker → full TRUSS**。生成侧 no-skill / intermediate LLM / full TRUSS 则更像 package-level comparison，不能把最终增益干净归给单一 stage。

## 决定性证据

84 对 clean/injected SkillInject（168 artifacts）上：LLM checker **44.64% precision / 19.05% recall**，static checker **81.55 / 94.05**，full TRUSS **100 / 100**。SkillGenBench 上 effectiveness **17.11→29.95→52.94%**，security **50.80→75.40→100%**。

## 仍未证明什么

Strongest generation delta 属于整个 certification/refinement stack。Safety property set 是预定义的，不能覆盖所有 open-world side effects；executor dependence 也很大，因此“被认证的 skill”并不自动跨 agent 稳定。

## 对领域地图的影响

Persistent skill 的问题不应只问“有没有帮助”，还要问：**这个 reusable artifact 实际诱导了什么行为，以及什么证据足以让未来 agent 继续使用它。** 这把 governance 从外围要求变成 procedural-memory lifecycle 的一等 stage。
