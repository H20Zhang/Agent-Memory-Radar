# RoMeRL: Balancing Feedback Coverage and the Memory-Reward Trap in Self-Evolving Agent Memory via Reduced-Order Utility States

**arXiv:** [2608.02508](https://arxiv.org/abs/2608.02508) · **Published:** 2026-08-03 · **Category:** Memory Learning & Evolution · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `episodic` `procedural` `structured` `general-agent` · **Code:** [YOUNG-fnxm/RoMeRL](https://github.com/YOUNG-fnxm/RoMeRL)

> **TL;DR.** RoMeRL replaces a growing utility variable per trajectory with a fixed four-coordinate memory state, concentrating sparse feedback and reducing the surface on which co-retrieved irrelevant memories can be incorrectly reinforced.

## Problem

Runtime memory RL has two coupled failures. First, every stored trajectory creates another utility to learn, so finite feedback becomes thinner as history grows. Second, task-level rewards supervise the **retrieved bundle**, not each memory's marginal contribution. A useless memory can therefore inherit positive reward from useful neighbors—the paper's **Memory-Reward Trap (MRT)**.

## Core idea

Represent each task with a fixed **2×2 state**: success/failure × consolidated/adaptive. The four coordinates retain the most efficient successful trajectory, the first recovery success after failure, a failed trajectory with useful downstream evidence, and the most recent failure. The semantic identity of a coordinate persists while its trajectory content is replaced; its learned utility is warm-started across replacements.

## Memory design

| Stage | Design |
|---|---|
| Write | Map each new trajectory into one of four semantic roles instead of adding another persistent utility variable. |
| Organize | At most four active representatives per task: positive-consolidated, positive-adaptive, negative-consolidated, negative-adaptive. |
| Read | Rank active representatives by embedding similarity + learned Q-value and retrieve top-k. |
| Update / forget | Replace coordinate contents by efficiency/transition/utility rules; inherited coordinate utility adapts through later outcome rewards, while superseded trajectories leave the active state. |

## Compared to what

The closest comparison is **MemRL**, which learns trajectory-indexed memory utility from runtime feedback. RoMeRL changes the **parameterization of what utility is attached to**. It also compares against MemP, RAG, Mem0, no-memory, and test-time-scaling baselines under frozen backbones and matched interaction budgets.

## Evidence

Across ALFWorld and LifelongAgentBench OS/DB, RoMeRL reports a **0.862** macro-average success rate versus **0.830** for MemRL. On OS, Cold-Q falls to **9.0%** while MemRL rises to **44.9%**; feedback density rises from **4.96 to 29.93 (~6×)**. Average memory size drops **45K → 7K (-84.4%)**, and LLM calls **570K → 450K (-21.1%)**. In a controlled noisy-memory stress test, RoMeRL reaches **82.0%** success with **0.15%** final noise versus MemRL's **79.2% / 1.02%**.

Ablations support the semantic factorization: removing consolidated negative evidence reduces both current and cumulative success, while removing the sparse positive-adaptive coordinate mainly hurts current success.

## Why it matters

The deeper point is that a learned memory policy has a **state-dimension problem**. More stored experiences do not imply that every experience deserves its own learned control variable. Bounded semantic state can improve feedback efficiency and reduce reward contamination.

## Limitations / questions

- RoMeRL still receives bundle-level outcome reward and does **not** solve causal credit assignment; it reduces exposure to attribution error.
- Four coordinates encode strong assumptions about binary outcomes and reusable task structure; open-ended strategies may require richer state.
- Several theoretical results use stationarity or stylized transition assumptions that are stronger than real lifelong-agent settings.
- Current experiments cover ALFWorld and two LifelongAgentBench families rather than open-ended long-horizon deployment.

**Curator take:** **4/5**. The reduced-order view is a meaningful correction to trajectory-indexed memory RL, and the efficiency evidence is strong. The unresolved question is whether the four-coordinate semantics generalize rather than merely regularize these benchmarks.
