# LeanMem: Simple and Efficient Long-Term Memory for LLM Agents

**arXiv:** [2608.03463](https://arxiv.org/abs/2608.03463) · **Published:** 2026-08-04 · **Category:** Representation & Organization · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `episodic` `semantic` `structured` `timeline` `personalization`

> **TL;DR.** LeanMem stores different kinds of dialogue evidence differently—stable profile facts, evolving events, and source-grounded records—and plans retrieval over those stores instead of forcing all history into one memory representation.

## Problem

Long-term histories mix information with very different temporal dynamics and fidelity requirements. One universal summary or vector store either wastes context or destroys details that later queries need.

## Core idea

Filter low-value dialogue, route retained information into **profile / event / record** memory according to its semantics, evolve only the temporal event store, and compose evidence using query-specific memory-type and token budgets.

## Memory design

| Stage | Design |
|---|---|
| Write | Filter low-information content, segment by topic, and route evidence to representation-specific memory types. |
| Organize | Stable profile memory, temporally evolving event memory, and source-grounded record memory. |
| Read | Adaptive Evidence Composition decides which stores to consult and how much evidence to retrieve. |
| Update / forget | Event memory is selectively evolved; profile and source-grounded records follow different lifecycle semantics. |

## Compared to what

Against systems such as **SimpleMem, LightMem, MemoryOS, and A-MEM**, the key delta is not a more complex universal memory: it is **heterogeneous lifecycle semantics** for heterogeneous evidence.

## Evidence

The paper evaluates **LoCoMo** and **LongMemEval-S** with GPT-4.1-mini and Qwen3-8B. It reports gains over the strongest memory baseline of up to **5.54 points on LoCoMo** and **15.07 points on LongMemEval-S**, depending on the backbone. The ablation indicates that removing heterogeneous storage causes the largest drop; memory evolution and retrieval planning also contribute.

## Why it matters

This is a strong systems abstraction: evidence types that behave differently over time should not share the same write/update/read contract. If it generalizes, that principle matters more than the exact three-store implementation.

## Limitations / questions

- Evaluation remains dialogue-memory QA rather than agents taking consequential actions.
- Routing correctness depends on inferring the information type and temporal dynamics of each observation.
- Behavior under months/years of conflicting, drifting memory has not been established.

**Curator take:** **4/5**. Simple enough to be reusable, and the ablation suggests the heterogeneity—not incidental prompting—is doing real work.
