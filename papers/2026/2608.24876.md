# Recursive Experiential-Working Memory Evolution for Long-Horizon Agent Harnesses

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#field-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md) · [中文](2608.24876.zh.md)

**Paper:** [arXiv:2608.24876](https://arxiv.org/abs/2608.24876) · **Published:** 2026-08-25 · **Importance:** 4/5 · **Confidence:** High · **Artifact:** [Code](https://github.com/Gen-Verse/Recuris)

> **Research delta.** Recuris separates a persistent skill library from the control state that decides when those skills are useful. On tau2-Retail, verified working state explains most of the gain; cross-task localized memory patches transfer, while retry-matched Terminal-Bench adaptation is statistically null.

## Problem

Long-horizon histories bury current task state, persistent skills can be invoked at the wrong moment, and an outcome-only self-improvement loop cannot tell whether the failure came from the skill artifact, state tracking, invocation, or verification.

## Mechanism

Recuris factors Skill Memory as `M=(E,W,rho,C)`: experiential skills, a working-state schema, an invocation policy, and checkers. Within a task, verified working state tracks progress and unresolved goals, then grounds which skills enter context. Across tasks, structured `(working state, exposed skills, action, observation)` traces localize a failure to one component; a fixed Meta-Agent proposes a scoped patch and a held-out gate decides whether it is promoted.

## Compared with

The cleanest tau2-Retail controls are Base, experiential-memory-only, working-memory-only, and model-controlled invocation. The last model-controlled arm uses the same ten-skill library as Recuris but leaves invocation to the model, separating skill availability from state-grounded control. Cross-task evolution is compared with the same frozen initial memory on a held-out split. Terminal-Bench additionally matches the four-attempt retry budget to separate adaptation from extra attempts.

## Decisive evidence

On tau2-Retail, task success is **58.1% Base / 60.1% EM-only / 82.0% WM-only / 65.6% model-controlled / 83.6% Recuris**. The same-library model-controlled arm needs about **147k tokens per success** versus **101k** for Recuris. This makes working-state and invocation control the load-bearing causal result, not simply the existence of a skill bank.

A memory package evolved from 16 failures raises success on a frozen 86-task split by **9–17pp** when the resulting repairs are actually invoked. The same package transfers on tau2-Retail from **58.33→76.10** for GPT-5.6 Sol and **72.37→87.94** for Claude Opus 5. The important negative result is Terminal-Bench 2.1: seed memory + four retries reaches **58.6%**, while test-time adaptation reaches **60.9% (p=.774)**. Most of that headline improvement is retry budget, not isolated memory learning.

## Main caveat

The recursive-evolution evidence is strongest on one tau2-Retail lineage. SkillFlow has no held-out task split, the small development gate can reject candidates that later help the larger test split, and full evolution cost is incomplete. Terminal-Bench should be read as a direction for adaptation, not evidence of an adaptation effect after retry matching.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Localized failures become candidate edits to skills, state logic, invocation, or checkers; a held-out gate controls promotion. |
| Organize | Persistent memory is factored into `E`, `W`, `rho`, and `C` so failures and patches have an explicit target. |
| Read | Verified working state selects which experiential skills are exposed to the frozen actor. |
| Update / forget | Cross-task patches can add, revise, or remove memory-control artifacts; long-term deletion, privacy, and lifecycle governance are not separately evaluated. |

## Why it matters

The paper narrows “self-improving memory” into four separable questions: what current state is represented, how persistent experience is invoked, how failure is attributed, and which patch survives promotion. For systems work, the strongest lesson is that the state/control layer can dominate the stored artifact, and that compute-equivalent retry controls are mandatory before crediting online adaptation.
