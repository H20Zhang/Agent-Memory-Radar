# MemFuse：多源记忆的关键不只在融合，还在把分散证据找全

[English](2608.18704.md) · [← 最新论文](../../README.md#latest) · [检索与访问](../../categories/zh/retrieval-access.md)

**Paper:** [arXiv:2608.18704](https://arxiv.org/abs/2608.18704) · **Importance:** 4/5

> **Research delta.** 多源记忆同时需要两种能力：组织时保留 provenance，读取时补全散落证据。MemFuse 两者都有，但消融显示，整体提升主要来自 iterative constrained retrieval，而不是 graph representation 本身。

## 研究问题

同一问题所需信息可能散落在不同设备、应用、用户与时间点。直接拼接会丢失关系，过度融合又可能抹掉原始来源。

## Mechanism

系统先把每条 source-tagged observation 保存成不可变 atomic event，再建立 fused cluster 与 typed causal link。回答时执行：

`seed retrieval → constraint extraction → graph expansion → rerank → 固定 top-20 atomic evidence`

最终上下文仍回到原始事件，因此 fusion claim 可以追溯到 source evidence。

## 最近的公平比较

Naive RAG、Mem0、A-MEM、EverMemOS 使用相同 event stream、reader setting 与最终 top-20 evidence budget；long context 作为 raw-history competence reference。结构归因必须看 w/o Graph / Fusion，访问归因则看 w/o agentic retrieval / constraints。

## 决定性证据

三种模型设置的 Overall 为 **0.4659 / 0.4574 / 0.4698**，但 GPT-4.1-mini 对最强 memory baseline 只多 **0.0024**，Gemini long context 仍以 **0.5201** 胜出。

去掉 agentic retrieval 总体下降 **0.1036**，去掉 retrieval constraints 下降 **0.0513**；graph/fusion 的总体消融更小，只在部分问题类型上更明显。

## 仍未证明什么

MemFuseBench 是合成基准：357 个问题、7,823 个事件，约 20% 经人工检查/修正。Qwen 设置写入达到 **93.27M tokens**、回答阶段 **10.31M**；论文也没有与成熟 stateful raw search 做完整 lifecycle-cost matching。

## 生命周期边界

| 阶段 | 设计 |
|---|---|
| Write | 原始 source event 不可变保存，并生成、验证 fusion。 |
| Organize | atomic evidence + fused clusters + typed causal graph。 |
| Read | 迭代约束检索与扩展，最后回投固定数量的 atomic evidence。 |
| Update / forget | cluster 可随新证据扩展；删除、老化和冲突退役不是主要贡献。 |

## 对领域地图的影响

这是一条 **access/interface early signal**：多源组织只有在读取策略能补全证据时才产生端到端价值。现有证据不能把系统总增益归因给 graph memory。
