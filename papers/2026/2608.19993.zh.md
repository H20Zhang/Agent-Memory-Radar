# Optimal Skill Selection：具有 Bicriteria Guarantee 的 Skill Set 选择

[English](2608.19993.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [检索与访问](../../categories/zh/retrieval-access.md)

**Paper:** [arXiv:2608.19993](https://arxiv.org/abs/2608.19993) · **Published:** 2026-08-20 · **Importance:** 4/5 · **Confidence:** Medium
**Tags:** `procedural` `text` `structured` `general-agent`

> **Research delta.** BPS 把 skill access 视为有 budget 的 set problem：互补、冗余与 context penalty 属于整个 selected slate，而不是彼此独立的 relevance score。实际优势依赖大量 outcome supervision 与经过 capability gate 的固定 benchmark。

## Problem

Top-k retrieval 独立给每个 skill 打分，但两个文档可能只有一起出现才有用，也可能彼此重复，或在计入 context cost 后变得有害。

## Mechanism

历史执行结果拟合非负的 query-demand 与 skill-supply vector。系统用 monotone submodular benefit 减 token penalty 给整个 skill set 评分，再由 Best Prefix Selection 在 hard budget 下选择 slate；bicriteria guarantee 只针对 surrogate objective。固定 skill document 随后进入 frozen executor prompt。

## Compared with

直接 set intervention 比较 no skill、single skill、complementary pair、redundant skill 与 irrelevant procedure。Value-model control 使用相同的 63,596 条 execution record；search control 使用同一 fitted objective。Released router 虽共享 executor 与 library，却没有配平 BPS 的 supervision 与 optimization budget。

## Decisive evidence

在受控 capability case 中，任一单独 skill 都是 **0%**，complementary pair 为 **93%**；加入 225-token redundant skill 后为 **94%**，再加入 385-token irrelevant skill 则降到 **56%**。因此 selected document set 会因果改变后续 execution。

End-to-end lookup BPS 达到 **.73** task success，released router、retriever 与 self-selection 为 **.20–.52**；它比最强 released router 少用 **28% tokens**。Same-record 与 same-objective ablation 对组件的归因比 headline baseline comparison 更干净。

## Main caveat

Private BigCodeBench variant 只接收 standard solution 与所有 one-capability hybrid 都失败的任务，因此 no-skill success 被构造成 0，并偏向 complementarity。BPS 从 **63,596 次 Qwen3-32B execution** 学习，baseline router 没有获得同等数据；定理保证的是 fitted surrogate，不是真实 task success。

Neural deployment 版本仍需要 annotated warm-up 与 online outcome。Selection latency、training tokens、GPU-hours、美元、storage、cold-start、library maintenance 与 energy 均未报告；节省的 prompt token 未必能覆盖 ingestion cost。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 固定 skill library 与历史 outcome 由实验提供；skill authoring 不在范围内。 |
| Organize | Outcome record 估计 task demand 与 skill supply。 |
| Read | BPS 在 token budget 内联合选择互补 skill set。 |
| Update / forget | Library 不增长、不遗忘；只有 neural selector 可从后续 pass/fail 继续学习。 |

## Why it matters

Procedural-memory access 应按有成本的 set selection 来评估，同时把学习 set value 所需的监督成本计入。
