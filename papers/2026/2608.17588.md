# TRUSS: Towards Task-Reliable and User-Safe Automated Agent Skill Generation

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md)

**Paper:** [arXiv:2608.17588](https://arxiv.org/abs/2608.17588) · **Published:** 2026-08-18 · **Importance:** 4/5 · **Confidence:** High  
**Tags:** `procedural` `structured` `general-agent`

> **Research delta.** TRUSS treats a generated skill as an **executable artifact that must be certified before promotion**: static function/safety obligations are followed by shadow execution, provenance-preserving traces, and evidence-guided refinement.

## Problem

A skill can look correct while causing unsafe tool calls, hidden side effects, or behavior that contradicts its natural-language claims. Artifact inspection cannot observe those consequences; final task success can also hide unsafe intermediate actions.

The missing boundary is therefore not only skill generation, but **promotion from candidate procedure to reusable persistent capability**.

## Mechanism

TRUSS first inspects functional claims against source/domain evidence and checks the whole artifact against nine predefined safety properties. Candidates that pass enter a Controllable Execution Environment where a shadow agent uses brokered tools and an intermediate breaker; requested actions and outcomes become provenance-preserving traces.

Failures are converted into Function/Safety Records and linked back to the responsible skill content. The refiner edits evidence-bearing content, versions the candidate, and reruns the complete check while preserving obligations that already passed:

`generate → static obligations → shadow execution → trace → function/safety record → refine → re-check → promote`

## Compared with

The cleanest detection comparison is **LLM checker → static checker → full TRUSS** on the same matched SkillInject artifacts. For generation, no-skill and intermediate-LLM conditions expose how much the full inspection/execution/refinement package changes effectiveness and security.

The package comparison is informative but does not isolate static checking, shadow execution, and refinement as independent causes of the final task gain.

## Decisive evidence

On **84 matched clean/injected SkillInject pairs (168 artifacts)**, the LLM checker reaches **44.64% precision / 19.05% recall**, static checking **81.55 / 94.05**, and full TRUSS **100 / 100**.

On SkillSafetyBench, repair reduces attack success **38.71% → 19.35%** with GPT-5.5 and **46.45% → 29.68%** with GPT-5.4, with zero reported attack regression. On SkillGenBench, task effectiveness rises **17.11% no skill → 29.95% intermediate LLM → 52.94% TRUSS**, while security rises **50.80% → 75.40% → 100%**.

## Main caveat

The strongest generation delta belongs to the **whole certification/refinement stack**, not one mechanism. The safety property set is controlled and may miss open-world side effects or organization-specific policies.

Executor dependence is also large: reported safe-task completion is **52.90% for GPT-5.5 vs 23.87% for GPT-5.4**. A certified skill is therefore not automatically executor-invariant.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Generate and iteratively refine versioned skill packages containing procedure plus executable resources. |
| Organize | Explicit function/safety obligations, provenance-preserving runtime traces, and per-version Function/Safety Records. |
| Read | Shadow executor loads the candidate skill through brokered tools; static + runtime evidence gates promotion. |
| Update / forget | Refiner repairs failed obligations and reruns the full check; long-term library aging/deprecation is outside scope. |

## Why it matters

TRUSS makes persistent procedural memory answer a stronger question than “did the generated skill help?”: **what behavior did this reusable artifact actually induce, and what evidence justifies letting future agents use it?**
