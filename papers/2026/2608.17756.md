# D²ACCI: A Dual-Loop Diagnostic Protocol for Evidence-Preserving Agent Memory

[Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Evaluation & Analysis](../../categories/evaluation-analysis.md)

**Paper:** [arXiv:2608.17756](https://arxiv.org/abs/2608.17756) · **Published:** 2026-08-18 · **Importance:** 4/5 · **Confidence:** High  
**Tags:** `structured` `general-agent`

> **Research delta.** D²ACCI treats memory changes as **promotion decisions** rather than benchmark wins: paired baseline/candidate evidence, protected slices, trace localizability, and deterministic gates decide whether an intervention is accepted, monitored, feature-flagged, or rejected.

## Problem

A multi-stage memory pipeline can fail at ingestion, retrieval, filtering, context construction, generation, or state update. Aggregate end-to-end scores reveal that something changed but often cannot identify **which stage caused the gain or regression**.

This creates a deployment problem: changes get promoted from average improvements even when protected slices regress, evidence is statistically inconclusive, or logs cannot support root-cause analysis.

## Mechanism

D²ACCI wraps an instrumented inner memory runtime with an outer diagnostic loop. Each candidate change starts from an explicit hypothesis and protected slices, produces paired baseline/candidate artifacts, and is evaluated with paired statistical tests plus Diagnostic Coverage Rate (DCR).

`instrumented memory run → typed stage traces → paired baseline/candidate outcomes → significance + protected slices + DCR → accept | monitor | feature-flag | reject`

Null and rejected interventions are retained as artifacts rather than disappearing from the engineering record.

## Compared with

The strongest comparison is **result-only evaluation**. D²ACCI asks whether the same memory intervention remains localizable and promotable when the evaluator must preserve stage traces, paired statistics, and non-regression constraints.

The paper also reports five feature interventions, making it possible to see the protocol keep some apparently plausible changes out of the default path.

## Decisive evidence

Three interventions show statistically significant paired gains: supplement extraction **+2.71pp (p=.0009)**, session-memory retrieval **+3.67pp (p=.0026)**, and Forget Guard **+1.92pp (p=.0030)**.

By contrast, BM25/RRF is null on LoCoMo (**−0.41, p=.4426**) and LongMemEval (**+1.00, p=.4583**) and is retained only as a monitored feature flag. In a 60-case audit, enriched traces improve inter-rater root-cause agreement to **κ=.571 fine / .619 coarse**, versus **.258 / .272** for result-only artifacts. PersonaMem diagnosis further attributes **87%** of observed failures to post-retrieval stages.

## Main caveat

DCR is defined around actionable trace coverage, so its advantage over result-only logs is partly structural: an uninstrumented system cannot score well on a metric whose purpose is to reward instrumentation. The more important claim is therefore about **decision discipline**, not that DCR itself predicts user value.

The protocol is demonstrated on one instrumented stack; portability across frameworks and online deployment remains unproven.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Record typed stage traces and paired baseline/candidate artifacts around memory interventions. |
| Organize | Group evidence by stage, protected slice, paired outcome, trace coverage, and promotion decision. |
| Read | Diagnostic loop consumes traces/statistics to accept, monitor, feature-flag, or reject a memory change. |
| Update / forget | Governs system changes and retains null/rejected priors; it is not an end-user memory-deletion mechanism. |

## Why it matters

D²ACCI turns a methodological principle into an executable contract: **memory features should earn promotion with paired, localized evidence—not an architecture-level score**. The fact that a plausible BM25/RRF change stays feature-flagged is more informative than another leaderboard improvement.
