# SkillEvo：Feedback Surface 决定 Procedural Memory 如何继续进化

**中文** | [English](2608.13120.md) · [返回首页](../../README.md) · [Research Library](../../library/README.md)

[Paper](https://arxiv.org/abs/2608.13120) · **Importance: 4/5**

> **Research delta.** SkillEvo 把主要变量放在 feedback source：当 single-turn QA 已经暴露不出新的缺陷时，multi-turn interaction 仍能持续提供可归因的 failure signal。Governance 则主要限制 repeated editing 带来的 regression 与 bloat。

## Problem

Self-evolving skill/memory 很容易在前几轮修掉明显问题后进入 plateau。原因不一定是 update algorithm 不够强，而可能是**反馈表面太贫乏**：single-turn 成功/失败只暴露局部 defect，长时程 interaction 才会显现 cross-turn dependency、错误状态累积、procedure mismatch 等问题。

同时，反复修改 skill 会引入另一个 failure mode：越改越长、旧能力 regression、冲突 rule 堆积。

## Mechanism

`multi-turn task → execution feedback → failure attribution → evidence-bounded skill edit → governance → persist checkpoint → next interaction`

SkillEvo 把 interaction trajectory 当成 evolution signal，而不是只从单轮 QA 或 self-reflection 生成修改。

## Closest comparison

最有判别力的是 matched single-turn-QA-driven evolution：update machinery 尽量对齐，只换 feedback source。另一个关键消融是去掉 governance，看它对 success 与 bloat 分别有什么作用。

## Decisive evidence

论文报告四轮 evolution 后：

- multi-turn interaction: **81.8%** task success
- matched single-turn QA: **66.4%**
- w/o governance: **78.6%**

同时 skill bloat 从有 governance 的 **+2.8%** 上升到无 governance 的 **+16.2%**。

这组结果支持两个相对分离的判断：**丰富 feedback 提高可修复 defect 的发现率；governance 更多负责控制长期副作用。**

## What remains unproven

当前 feedback 仍来自较高保真 simulator。真实用户反馈更稀疏、更噪声、更不一致，而且用户目标本身会变化。下一步需要检验：真实 interaction 下 multi-turn signal 是否仍可稳定归因，以及 rollout/edit/governance 的总成本是否值得。

还需要问：skill evolution 是否能 transfer 到新的 consumer model、toolset 与 domain，还是只在原环境里过拟合 trajectory failure。

## Field-map consequence

Memory evolution 不应只问“怎么 update”，还要拆成：

`what state evolves × what feedback is observable × update rule × governance × transfer`

SkillEvo 主要推进的是第二项。
