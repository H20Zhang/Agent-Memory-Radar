# Remember, Verify, or Ask?：跨模型家族评估记忆承诺

[English](2608.19564.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [评估与分析](../../categories/zh/evaluation-analysis.md)

**Paper:** [arXiv:2608.19564](https://arxiv.org/abs/2608.19564) · **Published:** 2026-08-20 · **Importance:** 3/5 · **Confidence:** Medium
**Tags:** `semantic` `text` `personalization` `general-agent`

> **Research delta.** MCB 把 memory admission 拆成四种有 authority 含义的动作：持久写入、仅当前使用、向外部世界核验、向用户澄清。实验还显示，模型口头选择的 label 不能可靠预测 structured tool selection；但这些动作并未执行，也没有测后续记忆行为。

## Problem

一次交互里获得的信息不应自动成为持久 Agent state。临时格式要求、会变化的服务状态和指代不清的修改请求，在 scope 与 authority 上需要不同处理。

## Mechanism

每个 MCB 样本都给出 acquisition context、candidate update 与 later reuse context，模型在 `persist`、`ephemeral`、`verify`、`clarify` 中选择。Held-out set 有 70 项，另有 70 项 contrast extension。两名非作者独立复核测试与 contrast label，总体一致率 **97.1%**、**κ=0.962**；第三名盲审者处理了四项主要分歧。

Label mode 比较 bare prompt、五条显式 commitment rule 与四个 demonstration。MCB-Act 不给 label vocabulary，而要求模型选择 `memory_write`、`use_now`、`check_source` 或 `ask_user` 之一。

## Compared with

最接近的 prompt control 固定模型与 held-out item，只改变 commitment instruction 或 demonstration。Always-Persist 是有用的 lifecycle negative reference，但不是一个真正运行的 no-memory system。MCB 直接提供 candidate，不比较 store、retrieval 或 forgetting policy。

## Decisive evidence

在 Qwen3.5-9B 上，few-shot 将准确率从 **0.557→0.771**（Holm-adjusted exact McNemar **p=0.002**），但 clarification recall 仍只有 **0.333**。Policy prompt 把 erroneous persistence 从 **0.243→0.100**（**p=0.038**），总准确率增益却不显著；不确定性主要被转移到 world verification，而不是 ask user。

口头决定也不能可靠迁移到操作接口。两种 Claude 的 label–tool agreement 都是 **0.571**，Qwen 只有 **0.229**。Qwen 在 structured-call mode 从 **0.557→0.343**（**p=0.047**），主要因为过度选择 `use_now`，导致 verification recall 大幅下降。

## Main caveat

Held-out test 只有 70 个 synthetic item，其中 clarify 12 个、每个 category 10 个。使用隐藏 category 的 majority oracle 已达 **0.800**；显式 policy 重述了 labeling rule，contrast template 也与规则高度对齐。三个 checkpoint 的 intervention effect 并不一致。

更严格的边界是：MCB-Act **只选择、并不执行** write、source check 或 question；没有 state 被后续读取，也没有 downstream utility。Label–tool 对比还同时改变 interface 与 output budget。论文没有报告 aggregate token、latency、compute、美元、energy 或 maintenance cost；所称 reproducibility artifact 也没有 primary-source locator。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 在持久写入、临时使用、向世界核验和向用户澄清之间选择；不执行动作。 |
| Organize | 四个动作编码 authority 与 scope，而不是 topic。 |
| Read | Candidate 与 later reuse context 直接给出，没有 retrieval system。 |
| Update / forget | 未评估；benchmark 在 commit 和后续 reuse 之前停止。 |

## Why it matters

Memory governance 从写入之前就开始了：Agent 需要识别谁能解决当前不确定性，以及信息是否被授权影响未来行为。MCB 让这条边界可以被测量，但现阶段只是 early benchmark signal，不是 persistent-memory policy 已改善的证据。
