# Agent Skills Can Be Harmful: An Empirical Study of Skill-Induced Failures in LLM Agents

**arXiv:** [2608.11888](https://arxiv.org/abs/2608.11888) · **Published:** 2026-08-12 · **Category:** Evaluation & Analysis · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `procedural` `text` `general-agent`

> **TL;DR.** A retrieved skill can be topically relevant yet reduce task quality or efficiency. The paper's key contribution is a matched-execution methodology for measuring the marginal behavioral and cost effect of reusable procedural guidance.

## Problem

A worse skill-guided run does not by itself isolate the skill from base-model, task, verifier, environment, or run effects. Passing runs can also become materially more expensive when skill instructions change the execution trajectory.

## Core idea

Hold task, verifier, agent framework, model, repository/container state, and input data fixed. Change only the skill setup: compare a target skill-guided execution with no skill or a semantically matched alternative skill that performs better or more cheaply, then inspect trajectory differences and classify the observed mechanism. SkillTriage automates part of this differential attribution.

## Memory design

| Stage | Role in the study |
|---|---|
| Write | Existing reusable `SKILL.md` packages are the procedural-memory artifacts; the study does not learn new ones. |
| Organize | Skills package procedures, examples, constraints, tool guidance, and optional references. |
| Read | Selected skill text enters the agent context and can alter planning, tool use, implementation, validation, and stopping. |
| Update / forget | Not implemented; the analysis motivates compatibility checks, lazy loading, and budget-aware selection/revision. |

## Compared to what

The closest comparison is the **same task under a different procedural-memory condition**, not another memory architecture. This extends SkillsBench / SWE-Skills-Bench from aggregate utility toward mechanism-level differential analysis.

## Evidence

After filtering and manual review, the study reports **307 confirmed cases**: **125 functional** and **182 high-confidence efficiency** regressions. Task-Implementation Fault accounts for **86/125 (68.8%)** functional cases, whereas simple applicability mismatch is only **2/125**. Excessive Procedure accounts for **114/182 (62.6%)** efficiency cases, including **67 excessive-verification** and **30 heavy implementation-pipeline** cases; context bloat accounts for 46/182.

SkillTriage matches the manual exact label in **111/125** functional and **132/182** efficiency cases, leaving meaningful ambiguity at category boundaries.

## Why it matters

For procedural memory, **relevance is not utility**. A skill can match the topic yet impose the wrong implementation detail or too much verification/execution work, so admission and routing should consider marginal outcome and cost relative to a matched alternative.

## Limitations / questions

- Root-cause labels still rely on human judgment and neighboring categories can be ambiguous.
- Evaluation uses SkillsBench and SWE-Skills-Bench with one OpenCode / Claude Opus 4.6 setup.
- Matched reference runs support attribution but do not establish a unique explanation for every trajectory difference.
- No online skill revision, suppression, versioning, or forgetting policy is evaluated.

**Curator take:** **4/5.** The durable lesson is the differential-testing principle: evaluate reusable procedural memory against a matched alternative, including the extra trajectory work it induces.
