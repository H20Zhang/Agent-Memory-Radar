# The Compaction Cliff：长时 Agent Memory 的压缩断崖

[English](2608.22752.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#field-map) · [写入、更新与整合](../../categories/zh/write-update-consolidation.md)

**Paper:** [arXiv:2608.22752](https://arxiv.org/abs/2608.22752) · **Published:** 2026-08-24 · **Importance:** 4/5 · **Confidence:** Medium · **Artifact:** [代码与语料](https://github.com/searchsim-org/cikm26-knowledge-triage)

> **Research delta.** Compaction 需要显式的 typed preservation contract：安全约束不能像 episodic log 一样自由改写。但最接近的 source-fidelity 对照在 50% 压缩时几乎打平，而且没有进入行为实验。

## Problem

统一 summarization 把安全规则、偏好、事实与日志放进同一失真预算，而这些信息对改写和丢失的容忍度并不相同。

## Mechanism

Knowledge Triage 先给 item 分类，再分别调用 TypeCompact、TypeDecompose 或 TypeRetrieve。约束可以保持原文、复制到适用分区，或在相关性证据之前固定保留。

## Compared with

最接近的算子对照是作者复现的 MaRS-FL，它同样面向 source fidelity。Type-blind compactor 是更宽的参考；行为实验只比较 Sonnet、hierarchical 与 full context，没有纳入 MaRS-FL。

## Decisive evidence

在 20 个配置上连续进行五轮 50% 压缩，Sonnet 的 constraint recall 从 **.53 降到 .10**，TypeCompact 约为 **.96**。在 50/25/10% 比例下，TypeCompact 为 **1.00/.95/.80**，MaRS-FL 为 **.99/.75/.43**。Retail pass 为 **37.7%**，高于 full **28.6%** 与 hierarchical **29.2%**，但保留 token 没有配平。

## Main caveat

50% 时，最强对照只落后 .01。五分类器 κ=.45，其调用、错误与成本没有计入 deterministic operator 的零 token 成本；TypeRetrieve 还假设 query topic/scope 标签正确。Retail 为 **1,136 vs 669 tokens**，最坏 decomposition overhead **+219%**，完整美元、能耗、审计与维护成本均缺失。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 上游分类器赋予 preservation type。 |
| Organize | Typed compaction/decomposition 保留或复制约束。 |
| Read | In-scope constraint 先于 relevance evidence。 |
| Update / forget | 测了重复压缩；未测修复、删除与在线审计。 |

## Why it matters

压缩应同时报告 obligation retention 与配平预算下的后续行为，而不是只报告 context 变短。
