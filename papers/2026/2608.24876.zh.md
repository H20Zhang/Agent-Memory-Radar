# Recuris：长 Horizon Agent 的经验-工作记忆递归演化

[English](2608.24876.md) · [← 最新论文](../../README.md#latest) · [记忆学习与演化](../../categories/zh/memory-learning-evolution.md)

**Paper:** [arXiv:2608.24876](https://arxiv.org/abs/2608.24876) · **Importance:** 4/5 · **Confidence:** High · **Code:** [Gen-Verse/Recuris](https://github.com/Gen-Verse/Recuris)

> **Research delta.** 这篇最重要的不是“又一个 self-improving memory”。最干净的对照显示：**verified working state + state-grounded invocation 比持久 skill library 本身更关键**；跨任务局部 patch 能迁移，但 Terminal-Bench 在配平 retry budget 后并没有显著 adaptation gain。

## 研究问题

长轨迹会把当前状态淹没在历史里；skill 即使被持久保存，也可能在错误状态被调用。更麻烦的是，只看最终 reward 的 self-improvement loop 无法判断错误来自 skill、working state、invocation policy 还是 checker。

## Mechanism

Recuris 把 Skill Memory 拆成 `M=(E,W,rho,C)`：经验 skill、working-state schema、invocation policy 和 checker。任务内，working memory 维护经过验证的当前进度与未解决目标，再据此选择要暴露的 skill；任务间，结构化 trace 把失败定位到具体 component，固定 Meta-Agent 只 patch 该处，再由 held-out dev gate 决定是否 commit。

## 最近的公平比较

tau2-Retail 的关键对照是 Base、EM-only、WM-only、model-controlled invocation 和完整 Recuris。后两者使用**完全相同的 10 个 skill**，因此能把“有 skill”与“基于当前状态正确调用 skill”分开。跨任务演化则从同一个冻结初始 memory 出发；Terminal-Bench 另外加入相同四次尝试预算的 retry control。

## 决定性证据

Retail task success 为 **58.1% Base / 60.1% EM-only / 82.0% WM-only / 65.6% model-controlled / 83.6% Recuris**。同一 skill library 下，model-controlled 每成功约 **147k tokens**，Recuris 约 **101k**。所以 load-bearing mechanism 首先是 state/control，而不是 skill bank 的容量。

用 16 个 failure 演化出的 package，在冻结的 86-task held-out split 上，当 patch 真正被调用时可带来 **9–17pp** 提升；同一 package 在 Retail 上把 GPT-5.6 Sol **58.33→76.10**、Claude Opus 5 **72.37→87.94**。但 Terminal-Bench 的 matched control 是关键反证：seed memory + retries 已到 **58.6%**，test-time adaptation 只有 **60.9%，p=.774**，大部分 headline gain 来自更多尝试。

## 仍未证明什么

最强 recursive-evolution 证据集中在一条 tau2-Retail 演化链；SkillFlow 没有 held-out task split。Retail 的小 dev gate 统计功效有限，曾拒绝后来在 86-task test 上更好的 candidate。论文也没有完整报告每轮注入 memory token、美元/能耗和完整 evolution cost，因此 lifecycle break-even 还未知。

## 生命周期边界

`execution → verified working state → state-grounded skill invocation → structured failure trace → component-local patch → held-out gate → persistent Skill Memory → future execution`

## 对领域地图的影响

这是 **state-grounded memory evolution 的 early signal**，不是 durable trend。它把“self-improving memory”进一步拆成 current-state control、persistent experience access、failure attribution 和 patch promotion 四个可独立验证的阶段；下一步最需要的是把 evolution compute、retry budget 与长期维护成本完全配平。
