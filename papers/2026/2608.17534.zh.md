# ArborMem：先定位历史状态，再检索补充证据

[English](2608.17534.md) · [← 最新论文](../../README.md#latest) · [Research Library](../../library/README.md)

**Paper:** [arXiv:2608.17534](https://arxiv.org/abs/2608.17534) · **Importance:** 4/5

> **Research delta.** ArborMem 把 memory read path 拆成 `state localization → state restoration → supplemental retrieval`：先判断当前 turn 接续历史中的哪个 interaction state，再恢复那条 branch，最后才找额外证据。

## 还没被解决的问题

长期交互里多个 project/person/plan 会交错。Similarity retrieval 可以找到“主题相关”的历史，却不一定找到**当前真正恢复的是哪条 trajectory**。因此 relevance 本身缺一个条件：relevant to which state?

## Mechanism

Conversation 被表示成 interaction-state forest。显式 continuation cue 可以走 fast path；否则系统用 topic keys、path/node summaries、entities 等信号 rerank candidate states。

`new turn → localize parent state → restore root-to-parent trajectory → retrieve supplemental facts → answer → commit new state`

## 最近的公平比较

最干净的内部 control 是在固定 LongMemEval subset 上移除 **state localization**，而保留其余 memory stack；atomic-fact retrieval 另做 ablation，因此可以部分区分 branch navigation 与一般 evidence extraction。

## 决定性证据

论文报告相对最强 baseline：LongMemEval **+9**、LoCoMo **+10.31**、BEAM100K **+3.36**、BranchMemEval **+5**。在固定 50-question LongMemEval subset 上，30B 模型去掉 state localization 从 **82→70**，但 4B 只从 **48→46**；该作用明显依赖模型能力。

## 仍未证明什么

Full system 同时改变 forest structure、summaries、atomic facts、structured records 和 prompt。证据更干净地支持“state localization 是独立 boundary”，并不能证明 forest 是唯一正确表示。Single-parent assumption 对 multi-intent turn 也偏强。

## 对领域地图的影响

Memory retrieval 需要再拆一层：**先确定当前处于历史的哪个 state，再谈哪些 evidence relevant。** 对反复暂停/恢复的长期 project agent，这可能比单纯改善 top-k 更关键。
