# MemFuse: Multi-Source Memory Fusion from Fragmented Observations

**Tags:** `episodic` `graph` `structured` `general-agent` · **Code:** [Darwin-Agent/Mi-Memory/MemFuse](https://github.com/Darwin-Agent/Mi-Memory/tree/master/MemFuse)

> **Research delta.** Multi-source memory needs both provenance-preserving organization and evidence-completing access. MemFuse supplies both, but its own ablations show that iterative constrained retrieval—not the graph alone—drives most of the overall gain.

## Problem

Evidence for one later question can be scattered across applications, devices, users, and time. Flattening those fragments loses relations; fusing them too aggressively can erase which source actually supports the answer.

## Mechanism

MemFuse keeps immutable source-tagged atomic events beneath cluster-level fused memories and typed causal links. A query triggers iterative seed retrieval, constraint extraction, graph expansion, reranking, and a fixed top-20 context made from the original atomic evidence.

`source events → atomic store → fused clusters / causal graph → constrained iterative retrieval → atomic evidence context`

## Compared with

The useful system-level controls share the event stream, reader setting, BGE-M3 retrieval substrate, and final top-20 evidence budget: Naive RAG, Mem0, A-MEM, and EverMemOS. Long context is a raw-history competence reference. Component attribution comes from removing graph, fusion, agentic retrieval, or retrieval constraints separately.

## Decisive evidence

Overall scores are **0.4659 / 0.4574 / 0.4698** across the Qwen, GPT-4.1-mini, and Gemini settings. The margin over the strongest memory baseline ranges from **0.0024 to 0.1461**; Gemini long context still wins at **0.5201**.

The attribution result is sharper than the headline: removing agentic retrieval costs **0.1036**, and removing retrieval constraints costs **0.0513**. Graph/fusion removals are smaller overall, though they matter more for User Query and Perspective categories.

## Main caveat

MemFuseBench is synthetic: 357 questions over 7,823 generated events, with about 20% manually inspected/corrected. Cost is also substantial—Qwen ingestion reaches **93.27M tokens** and inference **10.31M**, versus under 1.3M inference tokens for several simpler stores. There is no fully matched stateful raw-search control.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | Preserve every source-tagged observation as an immutable atomic event; propose and validate fusions. |
| Organize | Atomic evidence beneath fused clusters and typed causal relations. |
| Read | Iterative constrained retrieval and expansion, ending in a fixed top-20 atomic context. |
| Update / forget | Fused state can evolve while sources remain preserved; aging, deletion, and contradiction retirement are not central. |

## Why it matters

The paper supports an access/interface claim: a provenance-aware package can assemble dispersed evidence better than several bounded memory baselines. It does **not** show that causal graphs explain the package gain.
