# Activity Frames: Deterministic Screen-Activity Compilation for Agent Memory and Replay

**arXiv:** [2608.05784](https://arxiv.org/abs/2608.05784) · **Published:** 2026-08-06 · **Category:** Representation & Organization · **Importance:** 3/5 · **AI confidence:** High

**Tags:** `episodic` `structured` `timeline` `personalization`

> **TL;DR.** A deterministic compiler turns passive desktop activity into compact, auditable episodic memory frames, avoiding an LLM in the memory-construction path.

## Problem

Personal agents need persistent memory of what a user actually did on a computer. Raw screen/activity logs are too verbose, while LLM summaries can be lossy, expensive, and difficult to audit.

## Core idea

Compile low-level screen activity into typed **Activity Frames** keyed by application/site, time, input volume, and evidence pointers. Measured observations are kept separate from optional inferred semantics.

## Memory design

| Stage | Design |
|---|---|
| Write | Deterministically segment passive screen events into bounded frames and retain evidence pointers. |
| Organize | Chronological typed frames with explicit coverage/gaps and a measured-vs-inferred tier boundary. |
| Read | Give downstream agents compact frames and replay/pattern tools instead of raw rows or free-form summaries. |
| Update / forget | Recompile deterministically as source events change; no semantic forgetting policy is introduced. |

## Compared to what

The most useful comparison is against **raw activity rows** and **LLM-generated activity summaries**, rather than against another vector retriever. The delta is moving memory construction out of an LLM and into an auditable compiler.

## Evidence

Across eight evaluated days, the paper reports **98.4% QA accuracy** with its strongest Claude settings, versus **82.1–91.1%** for raw rows and **66.1–80.4%** for LLM summaries. The compiler is reported at **68 ms**, and the compiled representation is substantially smaller than raw activity.

## Why it matters

Some high-volume agent memory should probably be **compiled before it is retrieved**. This is a useful counterpoint to the dominant assumption that memory construction itself should be model-driven.

## Limitations / questions

- Single-user, single-machine study with one capture engine.
- Screen presence is an imperfect proxy for attention; user intent remains largely latent.
- Generalization to multi-device, multi-user, months-long personal agents is unknown.

**Curator take:** very relevant, but only **3/5 importance** today because the evidence is narrow. The architectural idea is stronger than the current evaluation.
