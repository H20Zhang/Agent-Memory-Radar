# Utility Under Attack：Agent Memory 污染与内容筛查、来源排序的边界

[English](2608.21230.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [评估与分析](../../categories/zh/evaluation-analysis.md)

**Paper:** [arXiv:2608.21230](https://arxiv.org/abs/2608.21230) · **Published:** 2026-08-21 · **Importance:** 4/5 · **Confidence:** Medium
**Tags:** `semantic` `structured` `general-agent` · **Artifact:** [论文锁定的 Aegis Memory commit](https://github.com/quantifylabs/aegis-memory/tree/6d2863083361f7a5c8e12b4512346c94cb453c2c)

> **Research delta.** Provenance 不是可以免费叠加的 trust bonus。在同一套 memory stack 中，加法式来源权重要么不足以压过语义更强的 poison，要么会把合法的 untrusted evidence 一并排除。论文提出 bounded occupancy，但没有实现或验证。

## Problem

错误陈述一旦进入持久记忆，就可能在未来 session 被再次取出。Content screening 无法只靠文本判断真假；source prior 又可能以牺牲 useful-evidence recall 为代价换取攻击抵抗。

## Mechanism

Aegis 在写入时依次检查结构、敏感信息、prompt injection pattern 与可选 LLM classifier，并保存 channel provenance。读取时先做 semantic over-fetch，再把 similarity、trust prior、effectiveness、decay 与 provenance 相加排序，最后把 top-15 memory 交给 reader。

论文固定 corpus、retriever、candidate set、reader 与 judge，只改变 provenance weight。随后用两个构造语料分别测有利端点——untrusted item 全是 distractor——以及最坏端点——真正 answer-bearing evidence 也来自 untrusted channel。

## Compared with

最接近 lifecycle-matched 的对照，是同一 poisoned corpus 上关闭 provenance weighting。Mixed-corpus 实验在相反的 source/truth 相关性下隔离同一个排序开关。缺少的关键对照，是在相同 evidence budget 下实现 bounded source occupancy。

## Decisive evidence

在 120 个被攻击的 LongMemEval_S 问题上，clean accuracy 为 **.850**，poison/no-defense 为 **.300**，shipped weighting 为 **.317**，stronger weighting 为 **.475**。Shipped weight 与无防御无显著差异（**p=.80**），仍让 poison 在 **87%** 的问题上排第一；**360** 条普通措辞的 false write 全部通过筛查。

更关键的是无 poison 的 utility failure：当正确证据来自 untrusted channel，stronger weighting 让 evidence recall 从 **99.17% 降到 0%**，answer accuracy 从 **.8583 降到 .0417**。因此持久写入与 access toggle 在该系统内确实因果改变后续答案。

## Main caveat

攻击生成器看到每道题及其正确答案，并为每题写入三条复用查询措辞的错误对话。这是 targeted poisoning，不是现实中随机污染率的估计。研究只覆盖一个 embedder、retriever、reader、产品和两个权重，并假设 provenance label 正确；两个语料给出边界端点，却没有定位真实部署的 operating point。

Bounded occupancy 仍只是提案。四个 mixed arm 的 API 成本合计 **$11.2202**，本地 screening latency 也有报告；但总 ingestion、reader/judge call、storage/index、reranking、repair、人工标注与 energy 仍不完整。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 四阶段筛查接收全部 360 条 targeted false assertion，并保存 channel provenance。 |
| Organize | Trust 表示来源，不表示已验证事实。 |
| Read | Additive provenance weight 在后续答案之前重排 semantic candidate。 |
| Update / forget | 未测试 repair、delete、relabel 或实际的 bounded-occupancy policy。 |

## Why it matters

Memory governance 必须同时测 harmful exposure 与 useful evidence retention。一个看似安全的 source prior，也可能悄然变成 denial of service。
