# KOPE: Experience-Driven Kernel Optimization with Experience Graph Memory

[Paper](https://arxiv.org/abs/2608.25570) · [中文](2608.25570.zh.md) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md)

## Research delta

KOPE makes execution feedback persistent as a **decision→outcome experience graph** and shows that it can alter later tool decisions while reducing context use. It is stronger evidence than a generic “experience helps” claim because both active context and graph memory have same-workflow ablations.

## Problem

Kernel agents repeatedly compile, test, profile, and revise, but normally discard hardware-specific failures and wins after each run. Keeping all trajectories is also untenable because accumulated history competes with the current task for context.

## Mechanism

Every attempt becomes a narrative Journal plus structured Case containing code change, correctness/performance outcome, confidence, and predecessor id. Cases form a decision-lineage graph. Before each iteration, Active Context Management builds a bounded prompt from required hot state plus graph-ranked warm experience and cold knowledge.

## Closest comparison

Two controls matter: **active vs passive context construction** on the complete 53-operator suite, and the **same GLM-5.2 workflow with vs without Experience Graph Memory**.

## Decisive evidence

Active context raises pass rate `636/1060→897/1060` (60.0%→84.6%) while aggregate optimization tokens fall `15.9B→1.113B` (−93.0%); score rises 636.00→2004.49. Enabling Experience Graph Memory raises full-suite pass rate 55.2%→84.6%; on 412 paired positive timing cases the graph-enabled condition has a **1.43×** geometric-mean speedup ratio.

## Main caveat

The active-context ablation jointly changes retrieval ranking, compression, and injection. Graph edges are execution lineage and the downstream-outcome score is a ranking heuristic, **not a causal effect** of an earlier decision. Full storage/index/graph maintenance cost is missing.

## Memory lifecycle

`compile/test/profile attempt → Journal + structured Case → decision-outcome graph → relevance/outcome ranking → bounded warm injection → next optimization decision/task`

The model remains fixed; persistent external state evolves. Long-horizon consolidation, deletion, privacy, and governance are not evaluated.

## Why it matters

The useful memory object here is not a summary of old text but **measured execution evidence connected to the decision that produced it**. This is a strong template for tool-using agents where later behavior should depend on verifier outcomes, not semantic similarity alone.
