# Write, Execute, Refine：从执行反馈中学习 Skill Writer

[English](2608.17587.md) · [← 最新论文](../../README.md#latest) · [Research Library](../../library/README.md)

**Paper:** [arXiv:2608.17587](https://arxiv.org/abs/2608.17587) · **Importance:** 4/5

> **Research delta.** WER 训练的不是 skill follower，而是 **skill writer policy**：candidate skill 交给 frozen agent 真正执行，programmatic verifier 给结果，success/failure trajectories 变成下一轮 refinement state。

## 还没被解决的问题

Agent-authored skill 有时甚至比 no-skill 更差。问题不一定在“不会照 skill 做”，而在**skill writer 不会从真实执行后果里学会下一次怎么写得更好**。纯 self-reflection 只是在文本上改 artifact，credit signal 太弱。

## Mechanism

`candidate skill → frozen executions → verifier scores → group-relative RL → mixed success/failure records → next refinement state`

Skill Optimizer 与 frozen executor 分开，后续 phase 只保留同一 skill/task 同时出现成功与失败的 cases，作为更有信息量的诊断状态。

## 最近的公平比较

最重要的 control 是 **同一个 Qwen3-4B optimizer backbone + 同一个 refinement workflow，只去掉 optimizer training**。因此可以把一部分增益归因到“学会写 skill”而不是“多跑了一轮 refinement”。

## 决定性证据

BFCL v4 上 untrained 4B optimizer **67.28**，WER-trained 4B **76.63（+9.35）**；tau2 为 **40.43→50.72（+10.29）**。再多一轮 refinement 反而从 **76.63→75.33**，说明“继续自我修改”不是单调收益。

## 仍未证明什么

训练依赖大量 rollout、stateful tool environment 和 programmatic verifier。没有可靠 execution feedback 的 domain 不能直接继承这个优势。最终 artifact pipeline 还使用更强模型做 domain-skill merging，因此 whole-system gain 也不完全属于 4B optimizer。

## 对领域地图的影响

Procedural-memory evolution 可以从“编辑一个 skill artifact”升级成**学习从 execution evidence 到下一版 skill 的 state-transition policy**。这把 feedback surface 和 writer policy 明确变成两个可独立比较的变量。
