# MemGuard: Persisting Verifier Signals for LLM-Agent Memory Governance

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#field-map) · [Write, Update & Consolidation](../../categories/write-update-consolidation.md) · [中文](2608.21867.zh.md)

**Paper:** [arXiv:2608.21867](https://arxiv.org/abs/2608.21867) · **Published:** 2026-08-22 · **Importance:** 4/5 · **Confidence:** Medium · **Artifact:** [Code](https://github.com/whyyyyy123/MemGuard)

> **Research delta.** A verifier signal becomes memory state when it persists beyond admission and governs retrieval, conflict handling, summarization, and archival. The closest verifier-only contrast favors MemGuard in every mean, but has no reported significance test.

## Problem

A one-shot filter cannot govern false accepts that remain active or repair duplicate, stale, and conflicting records as a bank grows.

## Mechanism

MemGuard attaches reward, confidence, label, and uncertainty to each candidate. These descriptors affect activation, retrieval, conflict resolution, merging, summarization, archival, and the guard context supplied to the actor.

## Compared with

The lifecycle-matched control is Verifier-only Filter under the same task order, step, retrieval, and context budgets. No-memory, four memory systems, and simplified/random descriptor variants bound the package.

## Decisive evidence

Across 16 backbone-benchmark cells and five seeds, MemGuard has the best mean success and steps. For Qwen Plus, full versus verifier-only is **67.4/63.7**, **83.6/79.8**, **58.4/52.0**, and **51.8/46.8**. The reported BH/Holm tests establish superiority over ReasoningBank, not the verifier-only control.

## Main caveat

Full versus verifier-only still changes several lifecycle operators together. A `{label, confidence}` descriptor is within **0.7–1.5 points**, and random/uniform weights are close. Verifier/governance work adds **4.0–5.8k tokens**; calibration drift, dollars, energy, privacy, and deletion cost are missing.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | A verifier descriptor is attached before activation. |
| Organize | The descriptor governs conflicts, merges, summaries, and archive state. |
| Read | Retrieval and actor guard context consume persistent verifier state. |
| Update / forget | Maintenance reuses descriptors; deletion and calibration drift are not audited. |

## Why it matters

Safe admission is not enough if the same reliability evidence disappears before later use and maintenance.
