# CaSKG: Counterfactual-Causal Skill Graphs for Scalable Agent Skill Retrieval

[← Latest Papers](../../README.en.md#latest-papers) · [Research Map](../../README.en.md#field-map) · [Retrieval & Access](../../categories/retrieval-access.md) · [中文](2608.25500.zh.md)

**Paper:** [arXiv:2608.25500](https://arxiv.org/abs/2608.25500) · **Published:** 2026-08-26 · **Importance:** 4/5 · **Confidence:** Medium · **Tags:** `procedural` `graph` `structured` `general-agent` · **Artifact:** [Code repository](https://github.com/ZhiyuanLi218/Caskg)

> **Research delta.** CaSKG is useful less as a claim that “causal graphs solve skill retrieval” than as evidence that **graph structure is itself a risky access policy**: with the skill library and downstream agent loop frozen, calibrating which edges may propagate relevance consistently changes later task behavior, while uncalibrated graph retrieval can underperform full-library exposure.

## Problem

A growing procedural-memory library forces a choice between expensive full-catalog exposure, compact but independent vector retrieval, and relational retrieval that can recover workflow context. The last option introduces its own failure mode: once relevance propagates over a graph, a plausible but operationally wrong edge can pull unrelated, unordered, or substitutable procedures into the actor context.

## Mechanism

CaSKG separates broad relation discovery from relation publication:

`frozen skill library → multi-signal candidate directed graph → budgeted textual counterfactual probes → Bayesian edge support/state → published weighted graph → query seeds → graph diffusion → compact skill bundle → unchanged actor`

Candidate edges use lexical, semantic, input/output, and structural signals. A bounded subset is assessed with direction-conditioned textual counterfactuals that remove the source skill, substitute a dissimilar source, or reverse the proposed order. The resulting necessity, specificity, and order-dependence evidence is smoothed into edge confidence; confirmed edges retain full weight, uncertain edges are downweighted, rejected edges are removed, and a bounded low-weight scaffold preserves coverage. At runtime, lexical/semantic seeds initialize personalized-PageRank-style expansion over this frozen graph.

## Compared with

The closest lifecycle-matched control is **Graph-of-Skills (GoS)**: it also starts from the same frozen Skill1000 library and performs offline graph construction followed by query-conditioned graph propagation, while leaving the downstream prompt, evaluator, episode limits, and environment loop unchanged. Full-library Vanilla Skills and independent Vector Skills provide useful coverage and non-relational controls. Construction ablations compare semantic-only candidate induction, removal of the optional LLM judge, and publishing every candidate edge.

## Decisive evidence

Across six backbones, the macro average moves from **80.01%→86.79%** ALFWorld success and **72.62→80.50** ScienceWorld official score relative to GoS. CaSKG also uses fewer mean environment steps than GoS in all twelve model-by-benchmark cells. The most informative reversal is GPT-5.6-Luna on ALFWorld: **72.86% full library / 55.00% Vector / 60.71% GoS / 75.71% CaSKG**. Graph retrieval is therefore not automatically helpful; the edge set can actively damage access.

The MiniMax-M2.7 ALFWorld construction ablation sharpens that point: full CaSKG reaches **73.57%**, versus **71.43%** when all **9,937** candidate edges are published, **71.43%** without the optional LLM judge, and **67.14%** with semantic-only candidates. This supports the integrated edge-calibration stage, but not a clean causal attribution to any single probe or scoring rule.

## Main caveat

The paper's “Steps” metric counts environment interactions, not retrieval or construction cost. Token usage, wall-clock latency, graph-construction inference, dollars, and energy are missing, so the lifecycle break-even against GoS or full-library access is unknown. The counterfactuals are LLM-simulated textual judgments, not interventions in the task environment; “edge-confidence calibration” is therefore better supported than a strong causal-graph interpretation. Main tables also report no repeated seeds, uncertainty intervals, or significance tests. Finally, the official code repository exists but contained no released implementation at verification time.

## Memory lifecycle

| Stage | Design |
|---|---|
| Write | No new skill is written during evaluation; offline construction derives relation evidence over a frozen Skill1000 library. |
| Organize | Procedural artifacts become nodes in a directed weighted graph whose candidate edges and publication states encode relation evidence. |
| Read | Query matches seed graph diffusion, which returns a compact relational skill bundle to an otherwise unchanged actor. |
| Update / forget | Offline edge states confirm, downweight, reject, or retain scaffold links; online skill revision, deletion, drift, and graph maintenance are not evaluated. |

## Why it matters

For agent memory, the main lesson is **compared to what**: a structured-memory method should beat a strong structured access control, not only vector retrieval. CaSKG shows that the graph itself is an amplifier. What matters is whether its relations improve executable access enough to justify construction and maintenance cost. That turns edge quality from a representation detail into a first-class retrieval-policy variable.
