# Break It Down, Pass It On：跨任务 Skill Transfer 的写入粒度

[English](2608.20274.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#research-map) · [记忆学习与演化](../../categories/zh/memory-learning-evolution.md)

**Tags:** `procedural` `text` `structured` `general-agent` · **Code:** [论文所列仓库](https://github.com/Zesearch/skill-transfer-llm-agents)（核验时没有 code/data）

> **Research delta.** 写入单元会改变 transfer：whole-task text/code skill 让平均成功率下降，而 subtask skill 带来小幅平均增益。这个结果高度依赖 model、domain 与 consumer，不是普遍的 subtask 优势。

## Problem

从完整 trajectory 归纳的 skill 可能把偶然细节或过宽流程带到后续任务。更细粒度可能提高复用，却也会增加 write 与 retrieval 次数。

## Mechanism

每完成一个 task 或 subtask，系统调用一次 LLM，将轨迹写成 persistent text workflow 或 Python function。后续不同任务按 description embedding 检索阈值以上的 top-5 skill。Text skill 可以 merge；code skill 可以 overwrite/deduplicate、载入 namespace，并在 dependency 失败时级联 prune。

## Compared with

Task-level text/code memory 与相同 task actor 的 no-memory 版本比较；subtask memory 也有自己的 matched no-memory actor。更强的两模型检查冻结 subtask agent 生成的 library，再交给 task actor，减少 consumer confound。Text 与 code 的差异不只来自表示，因为 code 还有 executable loading 与不同 maintenance rule。

## Decisive evidence

在 11 个模型、809 个任务上，Task no-memory/Text/Code 为 **22.1 / 20.9 / 18.0%**；Subtask no-memory/Text/Code 为 **24.8 / 26.7 / 25.3%**。早期 skill 会在后续任务被读取，并由官方 environment evaluator 检查 final state，因此 persistent memory 直接改变行为。

Frozen-library replay 报告 task actor 使用 subtask skill 后，两模型平均提升 **9.9pp**。但 task-bootstrap interval 重叠，不少 model/domain cell 反转；论文提出的 utility score 在控制 difficulty 后相关性也很弱。

## Main caveat

Task 与 subtask agent 的 planner、summarizer、query frequency、write count 以及生成 library 的 source trajectory 都不同。Task order 未说明，也没有重复 stochastic seed 或 primary paired test。论文所列 artifact 在核验时没有实现与数据。

Latency 与 MEM1 dependency curve 覆盖执行成本，但 induction、embedding、library growth、context injection、dependency loading、merge/prune、tokens、美元、storage 与 energy 没有完整统计。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 每个已完成 task 或 subtask trajectory 生成一个 skill。 |
| Organize | Description embedding、merge/overwrite、deduplication 与 dependency pruning 维护 library。 |
| Read | Top-5 text 或 executable code skill 进入后续 actor。 |
| Update / forget | 各条件的 library 随轨迹演化；broken code 与 dependency 可被 prune。 |

## Why it matters

Procedural memory 应把 granularity 当成因果政策，并在相同 consumer 上测试。更复杂、更可执行的 skill 也可能不如 no memory。
