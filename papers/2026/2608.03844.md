# MAFIA: Memory Attacks via Fully Indirect Access for LLM Agents

**arXiv:** [2608.03844](https://arxiv.org/abs/2608.03844) · **Published:** 2026-08-04 · **Category:** Evaluation & Analysis · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `semantic` `text` `general-agent`

> **TL;DR.** A query-only attacker can poison retrieval-based agent memory through ordinary interactions, causing malicious state to persist and influence later benign-looking queries without direct memory-store access.

## Problem

Persistent memory turns malicious input into persistent state. A payload can be written today, retrieved later under a different query, and influence an agent after the original suspicious interaction has disappeared from context.

## Core idea

Use black-box probes to infer where a malicious memory should land in retrieval space, then wrap the payload in factual-looking **cloaks** that evade write-time auditing while maximizing later retrieval and behavioral influence.

## Memory design

| Stage | What the attack exploits |
|---|---|
| Write | Poisoned memories are induced through normal agent interaction, not direct store access. |
| Organize | Existing RAG/similarity-based stores are the attack target; MAFIA proposes no new representation. |
| Read | Placement is optimized so malicious entries rank highly for target future queries. |
| Update / forget | Persistence is exploited; a general revocation or forgetting mechanism is not studied. |

## Compared to what

The relevant baseline is not ordinary prompt injection. MAFIA extends **query-only memory attacks** such as MINJA and tests whether write-time auditing or post-retrieval consistency checking actually prevents persistent poisoning.

## Evidence

Across the reported tasks and datasets, MAFIA reaches attack-success rates up to **90.7%**. In the highlighted setting, the strongest tested write-time audit detects at most **7.4%** of the crafted attacks.

## Why it matters

Agent memory creates a **state-integrity boundary**. Protecting only the current prompt is insufficient: provenance, authority, write policy, and retrieval-time trust become part of the memory-system design.

## Limitations / questions

- Evaluation focuses on RAG-style similarity/demonstration memories, not graph, hierarchical, or strongly typed stores.
- Defenses are limited mainly to auditing and consistency checks, not capability/provenance/information-flow controls.
- Attack transfer across substantially different retrievers and lifecycle policies remains open.

**Curator take:** **4/5**. Security is not peripheral to memory: persistent state makes failure qualitatively different from one-turn prompt injection.
