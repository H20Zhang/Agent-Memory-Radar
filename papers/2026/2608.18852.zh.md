# SkillGate：带 Oracle 监督的局部选择通道改变技能暴露

[English](2608.18852.md) · [← 最新论文](../../README.md#latest) · [检索与访问](../../categories/zh/retrieval-access.md)

**Paper:** [arXiv:2608.18852](https://arxiv.org/abs/2608.18852) · **Importance:** 4/5

> **Research delta.** Skill library 与访问它的 policy 是两个不同组件。单次 9B training run 显示，带 Oracle 监督的局部选择通道会改变 exposure 与 trial success；但三项 loss design 同时变化，不能只归因给 credit placement。

## 研究问题

长轨迹里，skill name 只占很少 token；之后执行失败时，broadcast trajectory reward 仍会惩罚此前正确的 read。技能存在，不代表 policy 学会了何时读、读哪一个。

## Mechanism

一次 GRPO update 被分成两个互不重叠的 token support：

- outcome advantage 只训练 execution tokens；
- group-centered、Oracle-supervised advantage 只训练 skill-identity tokens，且只有 clean single-oracle read 为正；read call 从 task loss 中删除，selector loss mass 另行归一。

## 最近的公平比较

SkillRL outcome-only 与 SkillGate 使用同一 Qwen3.5-9B 初始化、SFT checkpoint、数据、100 steps 与超参数。但 SkillGate 同时加入特权 Oracle utility、read-call masking 与 selector-mass normalization；credit / single-read ablation 只能拆分其中部分作用。

## 决定性证据

五个 benchmark、385 次试验中，SkillGate 为 **53.2%**，outcome-only 为 **47.0%**，SFT 为 **40.8%**。Oracle exposure 从 **54.3% 升至 83.9%**，misleading exposure 从 **69.6% 降至 21.8%**。

重复任务的 pooled difference 为 **+7.9pp**，task-clustered 95% interval 为 **+2.1 至 +14.3**；但 pass@4 与每个单独 benchmark 的区间都跨零。12,800 条 outcome-only 轨迹审计显示 identity tokens 的 loss weight 中位数只有 **0.14%**，与 dilution 假设一致，却不是随机化的机制检验。

## 仍未证明什么

每个配置只有一次 16×H800 training run，task bootstrap 不能替代独立 seed。训练还依赖 verified oracle identity、合成 hard negatives 与 single-read utility；三项 loss design 共同变化。开放 skill ecosystem、多技能组合和 library maintenance 都未覆盖。

## 生命周期边界

| 阶段 | 设计 |
|---|---|
| Write | 技能文件固定，不学习 artifact。 |
| Organize | 为任务提供带名称/描述的候选 slate。 |
| Read | policy 在 episode 内决定 read / skip / identity，并接收局部 credit。 |
| Update / forget | 更新的是 parametric access policy，不是 skill 内容。 |

## 对领域地图的影响

这是一条 **retrieval/access early signal**：局部 Oracle-supervision package 可以改变技能暴露与 trial success；现有证据还不能证明 credit location 是单独原因。
