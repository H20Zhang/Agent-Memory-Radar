# When Your Agent Opens the Chat App: Agent-Controlled Search over Raw Chat Logs Rivals Structured Memory

**arXiv:** [2608.12888](https://arxiv.org/abs/2608.12888) · **Published:** 2026-08-13 · **Category:** Retrieval & Access · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `episodic` `text` `timeline` `general-agent`

> **TL;DR.** ReFind is a strong negative result against mandatory semantic preprocessing: for precise chat-memory refinding, a stateful agent can search the raw archive with turn-level BM25 plus chat-native controls and outperform the compared graph/tree memory systems without any LLM-based index construction.

## Problem

Structured memory systems decide how to summarize, link, or compress a conversation before the future question is known. That can remove evidence and adds a construction pipeline. The comparison is therefore easy to confound: is a graph/tree/card representation helping, or did the structured system simply expose a better retrieval interface than a weak flat baseline?

## Core idea

ReFind takes the opposite extreme. It keeps the original timestamped chat archive, builds only a turn-level **BM25 access path**, and puts adaptation at query time. A ReAct-style retrieval agent can reformulate keywords and time ranges over several searches. Four chat-native controls then exploit structure already present in the archive: **session-aware RRF**, **±2-turn local context expansion**, **temporal filtering**, and **seen-session deduplication**. The retriever saves verbatim evidence; a separate reasoning stage answers from those notes.

The key distinction is worth being precise about: ReFind is not literally structure-free. It uses native turns, sessions, and timestamps. What it avoids is **generated semantic memory structure** such as summaries, entities, cards, trees, or graphs.

## Memory design

| Stage | Design |
|---|---|
| Write | Append raw user/assistant turns and update a turn-level BM25 index; no LLM construction pass. |
| Organize | Preserve native turn/session/timestamp organization; session identity informs ranking/dedup but no semantic memory is synthesized. |
| Read | Iterative keyword/time search → session RRF → local context expansion → seen-session filtering → saved verbatim notes → separate answer stage. |
| Update / forget | Append-only archive; no consolidation or forgetting. Retrieval-time state tracks notes, seen sessions, and the latest observation. |

## Compared to what

The strongest comparison is not merely ReFind versus a graph system. The paper includes two controls that isolate the interface itself:

- **Generic agentic BM25** keeps the same multi-round controller, note-taking, answer stage, and BM25 backend but removes all four chat-native controls.
- **One search** keeps the first query's retrieval behavior but removes evidence-driven reformulation and subsequent search rounds.

It also compares against BM25-RAG and structured systems including HippoRAG 2, RAPTOR, GraphRAG, Mem0, A-Mem, and Zep.

## Evidence

Across six MemoryAgentBench retrieval/fact-tracking tasks (~2,800 questions) with GPT-4o-mini matched to reused baselines, ReFind reaches **58.2** macro-average, versus **53.2** for HippoRAG 2 and **48.8** for BM25-RAG.

The more diagnostic evidence is on fixed LongMemEval-S/M subsets with GPT-5-mini: full ReFind reaches **93.2±3.3 / 89.3±6.0**; matched generic-agentic BM25 reaches **78.7±4.6 / 82.2±3.8**; the one-search control reaches **84.7±3.1 / 68.9±3.8**. Removing local context causes the largest S drop, while removing seen-session dedup hurts M much more strongly. With the agent/control layer held fixed, BM25 is also slightly stronger than dense or hybrid retrieval in these runs.

The causal conclusion should remain narrow: **iteration alone is insufficient, and the chat-native controls jointly matter**. The paper does not establish that lexical retrieval dominates semantic memory for every memory task.

## Why it matters

This paper raises the bar for future “structured memory” claims. If a complex memory representation is compared only to weak one-shot retrieval, the result may be measuring access-policy quality rather than the structure itself. For precise evidence-grounded chat search, **query-time control over an unmodified record is a serious baseline**, not a strawman.

## Limitations / questions

- Scope is precise retrieval and factual-update tracking over text chat, not semantic abstraction, low-latency serving, or tool-acting agents.
- ReFind shifts work to inference time. The full LongMemEval runs use substantially more tokens and latency than the generic/one-search controls.
- MemoryAgentBench baseline values are reused from prior evaluation rather than all reproduced in one implementation stack.
- Native session/time organization is doing real work; “no structure” should not be interpreted as “metadata-free.”

**Curator take:** **4/5**. The important contribution is the matched negative control against semantic memory construction. It does not kill structured memory; it shows that structure must beat a competent, stateful access interface before we credit the representation.
