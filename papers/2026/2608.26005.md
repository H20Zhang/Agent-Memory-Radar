# VoiceMem: Streaming Dual-Brain Memory for Real-Time Interaction

[Paper](https://arxiv.org/abs/2608.26005) · [Code](https://github.com/xzf-thu/VoiceMem) · [Project](https://xzf-thu.github.io/VoiceMem/) · [中文](2608.26005.zh.md) · [Representation & Organization](../../categories/representation-organization.md)

## Research delta

VoiceMem splits persistent conversational state into parallel **informational** and **affect/persona** paths, then keeps this upper organization/routing layer decoupled from the storage backend. The strongest portable evidence is backend uplift, not the “dual brain” metaphor.

## Problem

Real-time speech agents need factual continuity, persona/emotion continuity, and low retrieval delay simultaneously. A flat text store can erase acoustic/affective evidence or require large candidate sets incompatible with streaming interaction.

## Mechanism

A factual/entity “left brain” and affect/persona “right brain” receive asynchronous streaming writes. Query-time routing retrieves a small `K=5` set from the relevant structures and supplies it to the speech-language model; underlying memory backends remain interchangeable.

## Closest comparison

The most diagnostic comparison applies the **same upper VoiceMem layer** to Mem0, LangMem, and Zep rather than treating the complete VoiceMem stack as one indivisible baseline win.

## Decisive evidence

The paper reports factual-memory average 76.39 with top-5 retrieval. Adding the upper layer improves Mem0, LangMem, and Zep by **+29.52, +15.76, and +22.92 points**, raising their mean from 60.26 to 83.00. On persona evaluation with GPT-4o-mini, VoiceMem reports 74.16 versus MemOS 72.27; a separately fine-tuned responder reaches 76.56 and is a different condition. The system reports **134 ms retrieval** at `K=5` and about 430 memory tokens.

## Main caveat

The package co-varies extraction, factual/affective representation, graph structure, routing, and streaming I/O. The 134 ms figure is **memory retrieval latency**, not end-to-end speech response latency. Write/tagging/graph maintenance is off the critical path but its full lifecycle cost is not matched.

## Memory lifecycle

`streaming interaction → factual/entity extraction || affect/persona extraction → structured persistent paths → small-K routed read → response`

Conflict repair, forgetting, privacy deletion, backlog behavior, and complete asynchronous maintenance cost remain open.

## Why it matters

Multimodal memory may need different contracts for “what is true” and “how this user/interaction feels,” while the reusable systems boundary may be a thin organization/routing layer above storage rather than another monolithic memory backend.

## Related reading

[LeanMem](2608.03463.md) argues different memory types need different lifecycle contracts; VoiceMem pushes that separation into streaming multimodal interaction.
