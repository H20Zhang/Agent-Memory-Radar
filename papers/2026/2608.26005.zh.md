# VoiceMem：Streaming Dual-Brain Memory for Real-Time Interaction

[论文](https://arxiv.org/abs/2608.26005) · [代码](https://github.com/xzf-thu/VoiceMem) · [项目页](https://xzf-thu.github.io/VoiceMem/) · [English](2608.26005.md) · [Representation & Organization](../../categories/zh/representation-organization.md)

## Research delta

VoiceMem 把 persistent conversational state 拆成并行的 **informational** 与 **affect/persona** path，同时让这层 organization/routing 与底层 memory backend 解耦。最有价值的证据是 backend uplift，不是 “dual brain” 这个包装。

## Problem

real-time speech agent 同时需要 factual continuity、persona/emotion continuity 和低 retrieval latency。flat text store 容易丢掉 acoustic/affective evidence，或者靠巨大候选集换 recall，不适合 streaming interaction。

## Mechanism

factual/entity “left brain” 与 affect/persona “right brain” 接受异步 streaming write；query-time routing 从相关结构中取很小的 `K=5` candidate，再供给 speech-language model；底层 backend 可以替换。

## Closest comparison

最有判别力的是把**同一 VoiceMem upper layer**加到 Mem0、LangMem、Zep 上，而不是只比较完整 VoiceMem stack 与别的完整系统。

## Decisive evidence

论文报告 top-5 factual-memory average 76.39。加同一 upper layer 后，Mem0、LangMem、Zep 分别提高 **+29.52、+15.76、+22.92 points**，平均从 60.26 到 83.00。persona eval 在 GPT-4o-mini 下为 74.16，MemOS 为 72.27；另一个 finetuned responder 达 76.56，但那是不同条件。系统报告 `K=5` 时 **134 ms retrieval**、约 430 memory tokens。

## Main caveat

extraction、factual/affective representation、graph、routing、streaming I/O 同时变化，单组件因果归因有限。134 ms 是 **memory retrieval latency**，不是 end-to-end speech response latency。write/tagging/graph maintenance 被移出 critical path，但完整 lifecycle cost 没有配平。

## Memory lifecycle

`streaming interaction → factual/entity extraction || affect/persona extraction → structured persistent paths → small-K routed read → response`

conflict repair、forgetting、privacy deletion、backlog consistency 与异步 maintenance cost 仍未解决。

## Why it matters

multimodal memory 可能需要给“事实是什么”和“用户/交互状态是什么”不同 contract；真正可复用的系统边界也许是一层薄的 organization/routing，而不是再造一个 monolithic backend。
