# QUMem: Personalized Memory for Query-Conditioned User-State Inference in LLM Agents

**arXiv:** [2608.16168](https://arxiv.org/abs/2608.16168) · **Published:** 2026-08-17 · **Category:** Representation & Organization · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `semantic` `structured` `timeline` `personalization`

> **TL;DR.** QUMem separates persistent memory from the state actually delivered to the current decision. It preserves event context, decomposes each episode into independently retrievable facts/preferences/insights, then plans retrieval from explicit information needs and reconstructs a query-conditioned user state. The strongest ablation is downstream of storage: user-state reconstruction matters more than either episode segmentation or typed decomposition alone.

## Problem

Long-term personalization is not well modeled by one query over one flat memory store. Three failures interact:

- fixed turn/token/session boundaries can split a coherent event or mix unrelated evidence;
- one interaction can contain several reusable user signals with different scopes and lifetimes;
- the current task query often does not state which historical preferences, reasons, changes, or constraints must be verified.

A memory system therefore has to preserve enough source context to interpret an event, while also exposing fine-grained evidence that can be independently selected and jointly interpreted for the current task.

## Core idea

QUMem implements that separation in two phases.

**Write side.** A lightweight semantic-continuity classifier grows a variable-length dialogue episode until it detects a boundary. Each finalized episode is then decomposed three times into **factual memories**, **preference/constraint memories**, and **transferable insight memories**. Atomic memories remain linked to their source episode, supporting turns, and temporal position.

**Read side.** Three sequential agents turn the current task into a user state: an **Information-Need Agent** states what history must be verified; a **Retrieval Planning Agent** rewrites those needs into multiple queries and selects the relevant typed stores; a **User-State Inference Agent** jointly interprets the evidence into chronological facts, preference evolution/current applicability, and transferable decision principles.

The key design decision is that the retrieved records are **evidence**, not the final memory object consumed by the downstream actor.

## Memory design

| Stage | Design |
|---|---|
| Write | Maintain semantically coherent variable-length episodes; when one closes, run type-conditioned extraction for facts, preferences/constraints, and transferable insights. |
| Organize | Preserve complete source episodes for context plus independently retrievable typed atomic memories with temporal positions and provenance links. |
| Read | `current task → information needs → typed multi-query retrieval plan → merged evidence → query-conditioned user state → response/action`. |
| Update / forget | New history creates new episodes and typed evidence. Temporal validity is resolved mainly during query-time state inference; explicit stored-item deletion/revocation is not the paper's center. |

## Compared to what

The main baselines are **A-MEM**, **Mem0**, and **Zep**. These are reasonably strong long-term personalized-memory references: linked structured notes, extracted persistent memory with updates, and a temporal knowledge graph respectively.

The more informative comparison is internal. QUMem removes **Episode Construction**, **Typed Memory Decomposition**, or **User-State Reconstruction** one at a time. That makes it possible to ask which stage actually earns the complexity.

## Evidence

On **PersonaMem**, QUMem improves GPT-4o-mini overall accuracy from **52.99% → 61.02%** over the strongest baseline, and Gemini-3.5-flash from **63.29% → 70.58%**.

The component ablation is the result to remember:

- full QUMem: **61.02**
- w/o Episode Construction: **58.38**
- w/o Typed Memory Decomposition: **57.11**
- w/o User-State Reconstruction: **54.51**

The largest loss comes from removing the **query-time reconstruction pipeline**. That supports a sharper claim than “typed memory helps”: the high-value stage is task-driven evidence acquisition + joint interpretation into current state.

On **KnowU-Bench**, which requires personalized action rather than answer selection, QUMem reaches **17.4% overall success** versus **12.8%** for the strongest baseline. The absolute success rate remains low, but the result shows the memory benefit survives into an acting setting.

Construction accounting is also favorable on the authors' measurement: QUMem reports **27.1 builds / 81.4 generative LLM calls per 100 turns** and **1,221.2 construction tokens per turn**, lower than the compared systems. This is not a complete end-to-end cost comparison because the local boundary classifier and query-time three-agent inference are excluded.

## Why it matters

QUMem strengthens one of the radar's most important distinctions: **archive/representation ≠ consumer-facing state**. A persistent system can store good evidence and still fail if it sends the actor a bag of fragments rather than reconstructing the current state those fragments jointly imply.

This also creates a more demanding baseline for future personalized-memory work. A paper that only improves retrieval relevance should be compared against a system that explicitly models **preference evolution, contextual applicability, and current state**, not just top-k recall.

## Limitations / questions

- The method changes four things together—segmentation, typed representation, retrieval planning, and evidence interpretation—so stage-level attribution is better than architecture-level attribution but still not fully matched against alternative implementations of each stage.
- The episode-boundary classifier is trained from LoCoMo dialogue and its robustness under tool events, sparse user feedback, or very different conversational styles is not established.
- KnowU-Bench hard-task success remains low, so accurate personalized state reconstruction is still far from reliable personalized execution.
- Construction cost excludes the continuity classifier, while serving cost excludes the three query-time agents; lifecycle cost therefore remains incomplete.

**Curator take:** **4/5**. The important contribution is query-conditioned state reconstruction rather than merely another typed memory schema. The ablation supports that interpretation, but the overall package still changes several stages at once and end-to-end personalized action remains difficult.
