# QUMem: Personalized Memory for Query-Conditioned User-State Inference in LLM Agents

[arXiv 2608.16168](https://arxiv.org/abs/2608.16168) · Published 2026-08-17 · Importance **4/5** · Confidence **high**  
`semantic` `structured` `timeline` `personalization`

> **Research delta.** QUMem's load-bearing change is not another typed store: after retrieval, it reconstructs a **query-conditioned current user state**, and that downstream stage is the largest component in its ablation.

## Problem

Long-term personalization is not well modeled by one query over one flat memory store. Fixed turn/token/session boundaries can split coherent events, one interaction can contain reusable signals with different scopes and lifetimes, and the current query may not explicitly state which historical preferences, reasons, changes, or constraints need to be verified.

The design problem is therefore two-sided: preserve enough source context to interpret an event, but expose evidence at a granularity that can be independently selected and jointly interpreted for the current task.

## Mechanism

QUMem separates persistent evidence from the state consumed by the downstream actor.

**Write side.** A semantic-continuity classifier grows a variable-length episode until a boundary is detected. Each finalized episode is decomposed into **factual memories**, **preference/constraint memories**, and **transferable insight memories**, while retaining links to the source episode, supporting turns, and temporal position.

**Read side.** Three sequential stages turn the current task into an actor-facing user state:

`current task → information needs → typed multi-query retrieval plan → merged evidence → user-state inference → response/action`

The key architectural choice is that retrieved records are treated as **evidence**, not as the final memory object.

## Compared with

The external baselines are **A-MEM**, **Mem0**, and **Zep**. The more informative comparison is internal: remove **Episode Construction**, **Typed Memory Decomposition**, or **User-State Reconstruction** one at a time and ask which stage actually earns the complexity.

That makes QUMem more useful as a stage-attribution paper than as another architecture leaderboard.

## Decisive evidence

On PersonaMem with GPT-4o-mini, the strongest baseline is **52.99** and full QUMem reaches **61.02**. The component ablation is the result to remember:

| Variant | PersonaMem |
|---|---:|
| Full QUMem | **61.02** |
| w/o episode construction | 58.38 |
| w/o typed decomposition | 57.11 |
| w/o user-state reconstruction | **54.51** |

The largest loss comes from removing the **query-time reconstruction pipeline**. On KnowU-Bench, which requires personalized action, QUMem reaches **17.4%** overall success versus **12.8%** for the strongest baseline.

Construction accounting is also favorable in the paper's measurement, but it is not end-to-end: the local continuity classifier and the three query-time inference stages are not fully charged into one serving-cost comparison.

## Main caveat

The full system changes segmentation, persistent representation, retrieval planning, and evidence interpretation together. The ablation improves attribution, but it still does not compare each stage against fully matched alternative implementations.

Open questions:

- Does explicit state reconstruction still win under matched retrieved evidence and synthesis budget?
- How robust is the episode-boundary classifier outside LoCoMo-style dialogue?
- Can the method preserve provenance and avoid hallucinated current preferences when memories conflict or drift?
- Does the gain survive when the three read-time stages are included in full lifecycle cost?

## Memory lifecycle

| Stage | Design |
|---|---|
| **Write** | Maintain semantically coherent variable-length episodes; when one closes, extract facts, preferences/constraints, and transferable insights. |
| **Organize** | Preserve complete source episodes plus independently retrievable typed atomic memories with temporal positions and provenance links. |
| **Read** | Plan information needs, retrieve by type with multiple queries, then jointly infer current user state before response/action. |
| **Update / forget** | New history creates new episodes and typed evidence. Temporal validity is resolved mainly at read time; explicit deletion/revocation is not central. |

## Why it matters

QUMem strengthens a useful systems distinction: **archive/representation ≠ consumer-facing state**. A persistent system can store the right evidence and still fail if it delivers a bag of fragments rather than the state those fragments jointly imply for the current decision.

For future personalized-memory work, the baseline should therefore be stronger than top-k relevance: it should model preference evolution, contextual applicability, and current-state reconstruction.
