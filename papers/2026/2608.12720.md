# ERSkill: Evolving for Skill-Guided Adaptive Memory Retrieval

[← Latest Papers](../../README.md#latest-papers) · [Research Map](../../README.md#research-map) · [Memory Learning & Evolution](../../categories/memory-learning-evolution.md)

[arXiv 2608.12720](https://arxiv.org/abs/2608.12720) · Published 2026-08-13 · Importance **4/5** · Confidence **high**  
`procedural` `structured` `general-agent`

> **Research delta.** ERSkill makes the **memory read policy itself persistent and evolvable**: executable retrieval skills co-evolve with a query-conditioned router, so capability improvement depends on whether the controller can reliably activate the right access program.

## Problem

Many self-evolving memory systems change what is stored while leaving query-time access behavior fixed. That hides an important degree of freedom: different questions may require different evidence-construction procedures even when the underlying memory substrate is unchanged.

## Mechanism

ERSkill expresses retrieval behavior as executable skills composed from a fixed primitive library. Rollout traces are recorded in an experience trie; promising programs enter a broad capability frontier, while a more conservative deploy frontier keeps skills that can actually be selected reliably by the current router.

`query → learned router → retrieval skill → retrieval/evidence-processing primitives → evidence state → answer`

Training jointly explores candidate skills, evaluates them, and updates the router/frontiers.

## Compared with

The paper compares with standard memory systems and self-evolving experience/prompt methods. The more diagnostic controls remove **skill evolution**, replace the learned router, or simplify the frontier/search machinery.

The important attribution boundary is between **having a stronger retrieval program** and **being able to deploy it reliably on the right query**.

## Decisive evidence

Across LoCoMo, LongMemEval, and PerLTQA, ERSkill leads the reported average under both Qwen3-Next-80B-A3B-Instruct and GPT-5.4-nano.

The strongest evidence for the control-boundary claim is qualitative across ablations: the largest losses come from removing **skill evolution** or the **learned router**, while the double frontier and experience trie contribute smaller stability/search-efficiency gains.

The transfer result is also important: retrieval skills/router trained on LoCoMo are reused on LongMemEval **without additional training** and still lead the reported table for both backbones.

## Main caveat

The machinery is training-time expensive because candidate skills are judged through repeated rollouts and LLM-as-a-Judge supervision. The primitive library is also fixed, so evolution searches compositions of known operators rather than inventing fundamentally new access primitives.

Open questions:

- Does rollout-trained access policy still pay off on acting/tool-using agents versus a cheaper online adaptive controller?
- How much transfer comes from general retrieval programs versus benchmark overlap in memory-question structure?
- What should happen when a newly capable skill cannot yet be routed reliably?

## Memory lifecycle

| Stage | Design |
|---|---|
| **Write** | Compile histories into structured memory atoms; relation extraction is separated from repeatedly rewriting full history. |
| **Organize** | Keep memory atoms separate from executable retrieval skills; an experience trie and capability/deploy frontiers track explored programs. |
| **Read** | A learned router selects one retrieval skill, which executes primitives while maintaining evidence state for answer generation. |
| **Update / forget** | Rollout training proposes/evaluates skills, updates router/frontiers, and records accept/reject outcomes; underlying user-memory forgetting is not studied. |

## Why it matters

ERSkill exposes a distinct adaptation boundary: **the archive can stay fixed while the program that reads it evolves**. That is useful for thinking about agent memory as a programmable state interface rather than a static store plus one universal retriever.
