# The Retriever Should Remember：Experience-Amortized Reranking

[English](2608.22767.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#field-map) · [检索与访问](../../categories/zh/retrieval-access.md)

**Paper:** [arXiv:2608.22767](https://arxiv.org/abs/2608.22767) · **Published:** 2026-08-24 · **Importance:** 3/5 · **Confidence:** Low · **Artifact:** [代码](https://github.com/FengQi-HITSZ/earm)

> **Research delta.** Retriever 可以持久保存 query–memory relevance experience，以摊销后续 reranking；但 matrix completion 的净增量较小，固定顺序可能提供隐藏结构。

## Problem

Stateless LLM reranker 每次都重新给 candidate pool 打分，并丢弃已经获得的 relevance evidence。

## Mechanism

EARM 把 direct score 写入 query-by-memory matrix，用 temporal mask 的低秩 ALS 补全缺失值，再混合 observed/estimated score 重排固定 semantic candidate。

## Compared with

Observed-only 使用相同直接评分 anchor，但不做补全；semantic retrieval 与 full reranking 给出准确率和调用成本边界。

## Decisive evidence

Top-10 accuracy 为 **82.21** semantic、**88.83** observed-only、**91.62** full EARM；completion 净增 **2.79 points**，不是 package headline 的 9.41。Reranker call **307,982→78,736**；rank-2 temporal completion 反而 **81.31→80.06**。

## Main caveat

Content store 和 candidate set 都固定。Stable ID 与 question order 可能在 shuffle、增长、编辑或删除后消失。无 seed/uncertainty；ALS/storage growth、latency、price、ingestion、maintenance 与 energy 缺失。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 保存 direct relevance judgment。 |
| Organize | Temporal matrix completion 估计缺失 score。 |
| Read | Mixed score 重排固定 candidate。 |
| Update / forget | Score 累积；未测 drift、delete 与 retirement。 |

## Why it matters

Access policy 可以成为 persistent learned state，但还需在可增长、可编辑、被打乱的 store 上验证。
