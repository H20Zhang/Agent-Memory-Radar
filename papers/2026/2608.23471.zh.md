# InjecMEM：LLM Agent Memory 的单交互注入攻击

[English](2608.23471.md) · [← 最新论文](../../README.md#latest-papers) · [领域地图](../../README.md#field-map) · [评估与分析](../../categories/zh/evaluation-analysis.md)

**Paper:** [arXiv:2608.23471](https://arxiv.org/abs/2608.23471) · **Published:** 2026-08-24 · **Importance:** 4/5 · **Confidence:** Medium · **Artifact:** [代码](https://github.com/BlueBlood6/InjecMEM)

> **Research delta.** 一次普通 interaction 可以写入持久记录，随后被相关 query 取出并改变 response；可信的端到端上限是 MemoryOS 的 35.6%，不是 conditional steering success。

## Problem

即使攻击者不能读取或编辑 store，也可能利用正常 write–retrieve 路径影响后续 consumer。

## Mechanism

InjecMEM 把 topical retrieval anchor 与跨 surrogate prompt、位置和长度优化的短 command 组合。一次 interaction 写入，后续相关 query 将它检索进 actor prompt。

## Compared with

Retrieval 对照是相同评估下的 paraphrase+Multi-GCG。Steering 对照包括 DPI、BadChain、vanilla GCG 与 Multi-GCG，但后者获得更多 surrogate 与位置/长度多样性。MemoryOS/MemGPT 用于端到端检验。

## Decisive evidence

MemoryOS 的 retrieval 为 **46.5%**、conditional steering **76.6%**、joint success **35.6%**；MemGPT 为 **37.2/48.6/18.1**。Top-50 drift 时 retrieval 平均 **35.4%**。Perplexity filter 能完全阻断，但也拦截 **71.8%** benign input。

## Main caveat

最强设置是 white-box；同 family transfer 需要联合优化，held-out Llama 为零。Memory 必须保留近原文记录，real-background 只覆盖两个领域，target 也不是 operational action。Surrogate/optimization compute、GPU-hours、energy、美元、defense latency 与 non-target utility 不完整。

## Memory lifecycle

| 阶段 | 设计 |
|---|---|
| Write | 一次攻击 interaction 进入普通 memory path。 |
| Organize | MemoryOS/MemGPT 保存并老化近原文记录。 |
| Read | 相关 query 将记录取入 fused actor context。 |
| Update / forget | 测了 drift；未测 rewrite、repair、delete 与 expiry。 |

## Why it matters

Memory security 必须同时追踪 write、later retrieval 与真实 consumer influence，并报告 benign utility。
