# Researcher-first polish design

## Goal

Make Agent Memory Radar feel like a living survey researchers return to, not a project dashboard. Aesthetic choices should reduce reading friction and make comparisons, evidence, and open questions easier to scan.

## Public-page principles

- Use restrained typography and section hierarchy; avoid decorative dashboard UI, status cards, badge clutter, and emoji-heavy headings.
- Keep the first screen about research: scope, a concise field thesis, newest evidence, and four navigation anchors. Star/cross-radar CTAs are secondary.
- Use `Research take` rather than `AI take` on public research surfaces.
- Prefer numeric importance (`4/5`) to star glyphs where compact comparison matters.
- In `What’s Changing`, lead with cross-paper shifts (`old assumption → new evidence → implication`) before chronological compaction links.
- In `Research Map`, make lifecycle/control boundaries explicit so anchors teach a system model rather than form a list.
- Deep pages should offer consistent navigation back to Research Map / Reading Paths and one suggested continuation.
- Keep README as the judgment layer, category pages as the argument layer, paper notes as the evidence layer, and digests as the temporal synthesis layer.

## Canonical public order

`Latest Papers → What’s Changing → Reading Paths → Research Map → How to Use This Radar → What Counts as Agent Memory? → About → Contributing`

This keeps the sibling Agentic-RAG-Radar information architecture while adapting the content density and research lens for agent memory.
