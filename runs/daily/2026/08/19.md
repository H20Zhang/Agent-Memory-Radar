## Research-reader findings

**QUMem.** Full-paper review checked semantic episode construction, three typed memory stores, the information-need/retrieval-plan/user-state pipeline, PersonaMem and KnowU-Bench results, component ablations, retrieval-depth sensitivity, and construction accounting. PersonaMem GPT-4o-mini improves **52.99→61.02** over the strongest baseline; removing query-time user-state reconstruction drops the full system **61.02→54.51**, larger than removing episode construction (**58.38**) or typed decomposition (**57.11**). KnowU-Bench overall success improves **12.8%→17.4%**. The 4/5 interpretation is therefore **post-retrieval state reconstruction**, not merely “typed memory works.”

**HyperSkill.** The strongest Qwen3 ablation is **52.00 / 36.97 / 50.59** full on xBench / GAIA / WebWalkerQA versus **41.00 / 35.76 / 44.71** without the hypergraph structural pipeline, **43.00 / 32.73 / 47.06** without subtask retrieval, and **48.00 / 35.76 / 43.53** without trajectory retrieval. Skeptical review keeps it at 4/5 because `w/o hypergraph` changes both representation and access procedure; a matched flat/binary structure with the same controller is still missing.

**Skill2Query.** Full-paper review checked Skill Knowledge Graph construction, style/template/parameter generation, offline/online/training deployment modes, retrieval tables, generation ablations, and the end-to-end case study. ToolQA offline SkillRouter R@1 rises **35.80%→47.34%**; removing the Skill Knowledge Graph drops pseudo-query Exec-Pass **42.85%→22.63%** and functional coverage **11.32%→2.41%**. Online expansion improves some settings and hurts others, so the paper is 3/5 rather than a universal access-policy result.

**FTA-Mem.** The most useful evidence is the direct granularity comparison. ES-MemEval: session **31.76 F1 / 1.58M construction tokens**, turn-pair **37.06 / 6.40M**, FTA-Mem **38.71 / 4.99M**. LoCoMo flips the accuracy result: turn-pair **38.28** vs FTA-Mem **37.35** average F1, but costs **7.04M vs 3.39M** construction tokens. This supports a density/resource trade-off, not a universal semantic-unit optimum.

## Relevance / scope decisions

- **Executable Code Knowledge (2608.16295): hold out of canonical scope.** It is a source-bound validated knowledge representation for coding agents, but the paper does not center on persistence/evolution across interaction episodes; it is adjacent context infrastructure rather than agent memory under the current inclusion rule.
- **Aborted but Not Forgotten (2608.15939): exclude from memory radar.** The failure is KV-cache rollback consistency. KV-cache work is explicitly out of scope unless persistent agent memory is the central mechanism.
