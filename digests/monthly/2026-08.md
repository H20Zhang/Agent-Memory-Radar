# Agent Memory Monthly — 2026-08

**Status:** rolling month-to-date compaction through 2026-08-17. It will be finalized after the month closes.  
**Accepted August papers so far:** 29

## The month so far

The August map is no longer well described by “memory is becoming a state-control layer.” A more discriminating decomposition is:

**archive/representation → access program → evidence completion/selection → consumer-facing reuse → update feedback/governance → lifecycle cost/provenance**.

The strongest correction is methodological: **credit complexity only at the stage where a matched simpler alternative fails**. ReFind raises the raw-record baseline; RippleMem shows that structure can still earn its cost when it changes retrieval into controlled evidence completion under a more matched memory-unit/evidence budget. QCR and Demystifying Agent Skills isolate post-selection reuse/representation, while SkillEvo and ERSkill show that self-improvement depends on the feedback surface and on whether the read policy itself can evolve.

## Design-space movement

### 1. “Structured vs flat” → matched access controls

**ReFind** demonstrates that raw timestamped dialogue plus stateful lexical search and chat-native controls can outperform several structured-memory systems. That invalidates one-shot top-k as a credible “flat memory” control.

**RippleMem** prevents the opposite overcorrection. Its event graph is useful not because “graphs are better,” but because first-hop memories become **anchors for a missing-support query**. On LoCoMo, RippleMem reaches **87.14% LLM-judge accuracy** versus **83.83%** for RF-Mem when RF-Mem is given RippleMem's extracted memory units and the same per-query evidence budget. Removing graph expansion falls to **83.12**, and removing planned recollection to **84.35**.

**Current movement:** start from a competent raw-record/search control, then ask whether structure enables a qualitatively stronger operator—evidence completion, cross-modal bridging, admissibility, or selective view composition—that survives matched access conditions.

### 2. Fixed retrieval → evolvable access programs

**MESA** and **MAP-Graph** already separate “which representation should I expose?” from “may this evidence be used?” **ERSkill** pushes one step further: the access policy itself becomes persistent evolvable state. Retrieval behaviors are executable skills; a learned router chooses among them; a capability frontier and deploy frontier prevent oracle-good but unroutable skills from entering serving.

The strongest evidence is not the overall package alone. Ablations show the largest losses when **skill evolution** or the **learned router** is removed, while the frontier/trie machinery contributes smaller stability/search-efficiency gains. On LongMemEval, skills and router trained on LoCoMo transfer without extra training and still lead the reported table for both backbones.

**Current movement:** memory learning is expanding from “learn what to store” to **learn which evidence-construction procedure to execute**, with deployment quality depending on the controller's ability to activate the right procedure.

### 3. Retrieved evidence → consumer-compatible support

**QCR** holds the selected trajectory and actor conditions fixed and shows that target-conditioned reuse is a separate bottleneck from retrieval. It reaches **62.3% success**, **+10.7pp** over direct Full Trajectory, with **48.9% fewer online tokens**; under large binding shift, stale-binding errors fall **46.9%→10.9%** and correct rebinding rises **31.7%→77.8%**.

**Demystifying Agent Skills** isolates a neighboring procedural-memory boundary. With the **same source trajectories**, standardized Skills outperform Workflow Memory by **6.06 points**; contrastive coding attributes **65.7%** of skill cases to procedural anchoring and only **4.5%** to explicit knowledge injection. Retrieval correctness is then a weak proxy for utility: actual-use precision falls **29.6%→3.3%** as pools grow from 5 to 100, while downstream success remains comparatively stable and exact ground-truth invocation is neither sufficient nor necessary.

This reinforces PMCoder and Agent Memory Distillation: rich archival evidence can be the correct source while still being the wrong **consumer-facing representation**.

**Current movement:** archive, representation, selection, and reuse should be evaluated as different stages. A “better memory” claim that changes several of them at once is increasingly hard to interpret.

### 4. Self-improvement → feedback quality + governed state transitions

**SkillEvo** isolates a new variable: the **feedback surface** that drives procedural-memory updates. Across 9 production cloud-support Skills, four evolution rounds reach **81.8%** task success versus **66.4%** when multi-turn interaction is replaced by single-turn QA while attribution, revision, governance, and round count remain matched. Governance has a smaller score effect (**78.6% without it**) but sharply constrains cumulative bloat (**+2.8% vs +16.2%**).

**Practice Makes Unsafe** and **SkillJack** expose the complementary risk: updated procedures become descendant state whose authoring, retrieval, execution, and revocation are distinct gates.

**Current movement:** memory evolution needs two separate controls—**diagnostic feedback rich enough to reveal useful gradients, and governance strong enough to keep persistent descendants safe and compact**.

## Strongest papers so far

1. **ReFind + RippleMem** — the most important current tension: raw-record search is a strong baseline, but matched associative recollection shows when structure can still earn complexity.
2. **QCR + Demystifying Agent Skills** — strongest current evidence that retrieval, representation, and reuse are different causal stages; the same selected/source experience can become materially more useful after consumer-compatible transformation.
3. **SkillEvo + ERSkill** — strongest current evidence that evolution quality depends on both the feedback generator and the access policy/controller being evolved.
4. **LycheeMemory V2 + Total Recall** — strongest write-side and lifecycle-cost evidence; construction frequency and serving economics cannot be inferred from final context size.
5. **Practice Makes Unsafe + SkillJack** — strongest state-lineage warning for persistent procedural adaptation.

No paper is rated **5/5**. The controls are getting sharper, but external validity remains concentrated in conversational QA, terminal/software agents, benchmark web agents, cloud-support skills, and controlled evolution environments.

## Persistent vs weakening themes

**Strengthening:** matched access controls; evidence-completion operators; learned/evolvable read programs; consumer-conditioned reuse; procedural anchoring as a distinct representation effect; feedback-rich procedural evolution; explicit lifecycle governance and cost accounting.

**Weakening:** semantic preprocessing as an unquestioned default; one-shot top-k as a meaningful flat baseline; retrieval success as sufficient for reuse; exact ground-truth skill retrieval as a sufficient utility metric; self-reflection as a sufficient evolution signal; “more structure” or “more skill memory” as a contribution without a matched simpler control.

**Still unresolved:** where computation should live. ReFind spends online search to avoid preprocessing; RippleMem spends write-time structure and query-time recollection; ERSkill spends training-time rollout/judge compute; Lychee amortizes write-side consolidation; QCR adds target-time synthesis; standardized skill construction spends offline distillation to reduce noisy trace dependence. The field still lacks a common objective over construction cost, serving latency, reuse quality, and lifecycle risk.

## Tensions and hidden assumptions

- **Raw archive vs associative structure:** ReFind and RippleMem are not contradictory once the access interface is controlled; the real question is which tasks require relations that cannot be cheaply reconstructed online.
- **Retrieval labels vs procedural relevance:** Demystifying Agent Skills shows related non-ground-truth skills can still help, so retrieval benchmarks may under-specify what “relevant” means for procedural memory.
- **Adaptive access vs training cost:** ERSkill can improve read behavior without rewriting memory, but rollout evaluation may cost more than a simpler online controller saves at inference.
- **Persistent capability vs governance:** every mechanism that compiles experience into reusable state creates a descendant-state problem that retrieval accuracy alone cannot measure.

## What would falsify the current view

The current thesis should weaken if a matched-budget raw-record search closes RippleMem's evidence-completion gain; standardized Skills lose their advantage over matched Workflow Memory outside software/terminal tasks; ERSkill-style evolved access programs fail when transferred to acting/tool tasks; SkillEvo's multi-turn advantage disappears under real-user feedback; or target-conditioned reuse adds no benefit once naturally recurring tasks have minimal binding shift.
