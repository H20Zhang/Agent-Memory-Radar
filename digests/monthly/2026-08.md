# Agent Memory Monthly — 2026-08

**Status:** rolling month-to-date compaction through 2026-08-19. It will be finalized after the month closes.  
**Accepted August papers so far:** 34

## The month so far

The August map is no longer well described by “memory is becoming a state-control layer.” A more discriminating decomposition is:

**archive/representation → access program → evidence completion/selection/admission → consumer-facing state/reuse → update feedback/governance → lifecycle cost/provenance**.

The strongest correction is methodological: **credit complexity only at the stage where a matched simpler alternative fails**. ReFind raises the raw-record baseline; RippleMem shows that structure can still earn its cost when it changes retrieval into controlled evidence completion under a more matched memory-unit/evidence budget. TRACE-Memory adds a different access-stage control: personal evidence should be admitted only when it adds utility beyond the public/non-memory path, with an explicit empty-set action when personalization is unnecessary. QUMem and QCR isolate a later stage: retrieved historical evidence is not necessarily the state an actor should consume. Skill2Query sharpens retrieval supervision for procedural artifacts, while LycheeMemory V2 and FTA-Mem make write granularity an explicit quality-cost control. SkillEvo, ERSkill, and HyperSkill then show that self-improvement depends on the feedback surface, the read policy, and whether stored relational structure is actually consumed by retrieval and maintenance.

## Design-space movement

### 1. “Structured vs flat” → matched access controls

**ReFind** demonstrates that raw timestamped dialogue plus stateful lexical search and chat-native controls can outperform several structured-memory systems. That invalidates one-shot top-k as a credible “flat memory” control.

**RippleMem** prevents the opposite overcorrection. Its event graph is useful not because “graphs are better,” but because first-hop memories become **anchors for a missing-support query**. On LoCoMo, RippleMem reaches **87.14% LLM-judge accuracy** versus **83.83%** for RF-Mem when RF-Mem is given RippleMem's extracted memory units and the same per-query evidence budget. Removing graph expansion falls to **83.12**, and removing planned recollection to **84.35**.

**TRACE-Memory** adds a different question after retrieval: even a relevant memory may be the wrong thing to expose if public context already makes it redundant or if the evidence is too weak to improve the response. Its access pipeline is `public-conditioned information-gap query → coverage retrieval → source-traceable evidence units → utility-aware admission / EMPTY`. The diagnostic intervention is selective abstention: from public-context level L0 to L3, the `EMPTY` rate rises **7.69%→12.53%** while average reward rises **0.31→0.62**. Under fixed response generators, TRACE-Memory has positive signed preference advantage over random memory use in all six reported Controlled/Natural settings and over semantic similarity in four of six.

**Skill2Query** adds a procedural-memory version of the same lesson. A skill document is not one semantic blob: capability, parameter, and example structure can improve synthetic retrieval supervision. On ToolQA, offline augmentation raises SkillRouter R@1 **35.80%→47.34%** and dense SR-Emb R@1 **13.22%→29.79%**. But online query expansion hurts several settings, so the result supports **structure-aware retrieval supervision**, not a universal online expansion policy.

**Current movement:** start from a competent raw-record/search control, then ask whether structure or policy enables a qualitatively stronger operator—evidence completion, cross-modal bridging, capability-grounded routing, admissibility, selective view composition, or explicit abstention—that survives matched access conditions.

### 2. Fixed retrieval → evolvable access programs and operational structure

**MESA** and **MAP-Graph** separate “which representation should I expose?” from “may this evidence be used?” **ERSkill** pushes one step further: the access policy itself becomes persistent evolvable state. Retrieval behaviors are executable skills; a learned router chooses among them; a capability frontier and deploy frontier prevent oracle-good but unroutable skills from entering serving.

**HyperSkill** adds a different kind of evidence. Each trajectory becomes a hyperedge binding reusable subtask and skill nodes; query-time access combines a subtask path with a trajectory path, then ranks skills by how often they co-occur across the retrieved trajectories. On Qwen3-30B-A3B, the full model reaches **52.00 / 36.97 / 50.59** on xBench / GAIA / WebWalkerQA, versus **41.00 / 35.76 / 44.71** when the hypergraph/dual-path structural pipeline is replaced by flat skill retrieval. Removing only subtask retrieval gives **43.00 / 32.73 / 47.06**; removing only trajectory retrieval gives **48.00 / 35.76 / 43.53**.

The skeptical correction matters: the no-hypergraph arm changes both representation and access procedure, so it does **not** isolate the n-ary hypergraph substrate by itself. What the evidence does support is that **stored structure can matter when retrieval and maintenance explicitly consume it**, rather than when a graph is merely decorative metadata.

**Current movement:** memory learning is expanding from “learn what to store” to **learn or design which evidence-construction procedure to execute, and make stored relations operational in that procedure**.

### 3. Retrieved evidence → consumer-compatible state

**QCR** holds the selected trajectory and actor conditions fixed and shows that target-conditioned reuse is a separate bottleneck from retrieval. It reaches **62.3% success**, **+10.7pp** over direct Full Trajectory, with **48.9% fewer online tokens**; under large binding shift, stale-binding errors fall **46.9%→10.9%** and correct rebinding rises **31.7%→77.8%**.

**QUMem** reaches the same boundary from personalization. It stores source-linked episodes plus typed facts, preferences/constraints, and transferable insights, but its largest ablation is query-time **user-state reconstruction**: PersonaMem overall drops **61.02→54.51** without reconstruction, versus **58.38** without episode construction and **57.11** without typed decomposition. On KnowU-Bench, QUMem improves overall success **12.8%→17.4%** over the strongest baseline, showing that reconstructed state can affect personalized action rather than only response selection.

**Demystifying Agent Skills** isolates a neighboring procedural-memory boundary. With the **same source trajectories**, standardized Skills outperform Workflow Memory by **6.06 points**; contrastive coding attributes **65.7%** of skill cases to procedural anchoring and only **4.5%** to explicit knowledge injection. Retrieval correctness is then a weak proxy for utility: actual-use precision falls **29.6%→3.3%** as pools grow from 5 to 100, while downstream success remains comparatively stable.

**Current movement:** archive, representation, selection/admission, state reconstruction, and reuse should be evaluated as different stages. A “better memory” claim that changes several of them at once is increasingly hard to interpret.

### 4. Write granularity → density- and cost-aware construction

**LycheeMemory V2** shows that *when* consolidation runs is load-bearing: semantic segmentation preserves quality while reducing construction frequency relative to eager per-turn writing.

**FTA-Mem** adds a complementary result on *how large one persistent unit should be*. On ES-MemEval, session-level construction gives **31.76 F1 / 1.58M construction tokens**, turn-pair gives **37.06 / 6.40M**, and situation-level FTA-Mem reaches **38.71 / 4.99M**. On denser LoCoMo, however, turn-pair is slightly more accurate (**38.28 vs 37.35 average F1**) but costs **7.04M vs 3.39M** construction tokens. The right conclusion is therefore **granularity depends on information density and resource budget**, not “semantic segmentation always wins.”

The Sleeping Agent adds a field-preservation warning: even a compact representation with good aggregate quality can systematically erase a sparse field such as temporal anchors.

**Current movement:** write policy is becoming a three-way control over **boundary/granularity, transformation frequency, and preservation contract**.

### 5. Self-improvement → feedback quality + governed state transitions

**SkillEvo** isolates a new variable: the **feedback surface** that drives procedural-memory updates. Across 9 production cloud-support Skills, four evolution rounds reach **81.8%** task success versus **66.4%** when multi-turn interaction is replaced by single-turn QA while attribution, revision, governance, and round count remain matched. Governance has a smaller score effect (**78.6% without it**) but sharply constrains cumulative bloat (**+2.8% vs +16.2%**).

**HyperSkill** complements that story on maintenance: sufficiently observed low-utility nodes are pruned, while redundant skills are merged using quality-weighted structural propagation. Sensitivity analysis peaks at light pruning and degrades both when pruning is disabled and when it is too aggressive. This is useful evidence that “evolution” includes **retiring and consolidating persistent state**, not only adding new skills.

**Practice Makes Unsafe** and **SkillJack** expose the complementary risk: updated procedures become descendant state whose authoring, retrieval, execution, and revocation are distinct gates.

**Current movement:** memory evolution needs separate controls for **diagnostic feedback, the state/access policy being changed, and maintenance/governance of the descendants that accumulate**.

## Strongest papers so far

1. **ReFind + RippleMem** — the most important current tension: raw-record search is a strong baseline, but matched associative recollection shows when structure can still earn complexity.
2. **TRACE-Memory + QUMem + QCR** — strongest current evidence that relevant memory, admissible memory, selected evidence, and consumer-facing state are different causal stages.
3. **SkillEvo + ERSkill + HyperSkill** — strongest current evidence that evolution quality depends on the feedback generator, the access policy being evolved, and whether stored relational structure is operational during retrieval/maintenance.
4. **LycheeMemory V2 + FTA-Mem + Total Recall** — strongest write-side/lifecycle evidence; construction boundary, consolidation cadence, and serving economics all need explicit accounting.
5. **Practice Makes Unsafe + SkillJack** — strongest state-lineage warning for persistent procedural adaptation.

No paper is rated **5/5**. The controls are getting sharper, but external validity remains concentrated in conversational QA, personalized generation, terminal/software agents, benchmark web agents, personalized-agent benchmarks, cloud-support skills, and controlled evolution environments.

## Persistent vs weakening themes

**Strengthening:** matched access controls; evidence-completion operators; public-conditioned memory admission with abstention; capability-grounded skill retrieval; learned/evolvable read programs; **structure that is consumed by retrieval/maintenance**; query-conditioned consumer-state reconstruction; procedural anchoring as a distinct representation effect; density-aware write granularity; feedback-rich procedural evolution; explicit lifecycle governance and cost accounting.

**Weakening:** semantic preprocessing as an unquestioned default; one-shot top-k as a meaningful flat baseline; relevance as a sufficient memory-admission criterion; graph/hypergraph structure as a contribution without an operational read/update mechanism; retrieved records as the final consumer state; retrieval success as sufficient for reuse; exact ground-truth skill retrieval as a sufficient utility metric; one global memory-unit granularity; self-reflection as a sufficient evolution signal.

**Still unresolved:** where computation should live. ReFind spends online search to avoid preprocessing; RippleMem spends write-time structure and query-time recollection; TRACE-Memory spends learned query/admission control to avoid unnecessary personal context; Skill2Query trades offline augmentation against inconsistent online expansion; QUMem pays for typed construction plus three query-time reasoning stages; FTA-Mem spends more write compute than coarse summaries but less than turn-pair memory; ERSkill spends training-time rollout/judge compute; HyperSkill spends decomposition/extraction plus periodic merge decisions. The field still lacks a common objective over construction cost, serving latency, state/reuse quality, privacy/admission, and lifecycle risk.

## Tensions and hidden assumptions

- **Raw archive vs associative structure:** ReFind and RippleMem are not contradictory once the access interface is controlled; the real question is which tasks require relations that cannot be cheaply reconstructed online.
- **Relevance vs incremental utility:** TRACE-Memory makes public-context sufficiency part of the access decision, but its utility signal is still a target-response likelihood/entropy proxy rather than direct user utility.
- **Stored evidence vs current state:** QUMem and QCR both require a post-retrieval transformation, but that transformation itself can hallucinate applicability or bindings; stronger provenance-preserving reconstruction controls are still missing.
- **Structure vs structural pipeline:** HyperSkill's strongest ablation removes both the hypergraph and the dual-path retrieval built on it. The next decisive control is a flat or binary-graph representation with the same decomposition, trajectory retrieval, co-occurrence ranking, and maintenance budget.
- **Granularity vs density:** FTA-Mem wins its intended sparse-dialogue regime but turn-pair memory slightly wins denser LoCoMo quality. A lifecycle controller may need to adapt write granularity online rather than commit to one representation globally.

## What would falsify the current view

The current thesis should weaken if a matched-budget raw-record search closes RippleMem's evidence-completion gain; TRACE-Memory-style admission offers little once a strong response-aware selector is conditioned on the same public context and evidence budget; QUMem-style user-state reconstruction adds little once retrieved evidence and synthesis budget are held fixed against a strong alternative; a flat/binary representation with HyperSkill's same dual-path controller closes the hypergraph gain; FTA-Mem's granularity advantage disappears outside one low-density benchmark family; standardized Skills lose their advantage over matched Workflow Memory outside software/terminal tasks; or SkillEvo/ERSkill gains fail under real-user/domain transfer.
