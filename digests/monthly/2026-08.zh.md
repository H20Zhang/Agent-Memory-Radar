## 本月核心判断

八月没有建立一个胜出的 memory architecture。更重要的更新发生在因果归因上：**只有当同预算、同 consumer interface、同 qualification policy 下的简单 archive 仍然失败时，复杂 persistent state 才应获得机制 credit。** native-v2 记录反复指向同一个瓶颈：真正决定后续 actor 行为的，往往是“哪些状态仍然有效、适用、经过验证、允许暴露并能被复用”的控制策略，而不是更复杂的存储表示本身。

native-v2 从 2026-08-20 开始。更早的八月论文由于历史 Radar acceptance time 不可恢复，可以作为上下文，但不计入这份闭周期月报的八月接受证据。

## 三个 design-space movement

### 1. `retrieve → consume` 变成 `candidate state → qualify → consume`

**StateMem** 把 retrieved history 与 current operative state 分开：在 DeepSeek 设置上，extraction-only 为 **0.174**，加入 supersession 后为 **0.298**，完整 StateMem 为 **0.363**；dependency propagation 并非普遍有益，移除它反而达到 **0.373**。更干净的因果证据来自 **When Stale Constraints Go Unchecked**：保持 `k=2` verification budget 不变，只把一个已有 verification slot 分配给关键 provenance path，superseded world 中遵循当前记录的决策提高 **61.3–74.0 个百分点**，而 valid world 只变化 **0–2.0 个点**。

**MemTrapBench**、**Remember, Verify, or Ask?**、**Utility Under Attack** 与 **MemGuard** 分别暴露相邻的失败面：相关历史仍可能不适用于当前任务；authority/scope 应在 commitment 前决定；trust weighting 会在安全与合法低信任证据之间形成 trade-off；verifier output 只有跨过 admission 后继续参与维护与消费，才真正成为 governed state。共同结论比“verification 有用”更窄：memory quality 需要一个显式的 **consumer-exposure 前 qualification policy**。

### 2. Procedural memory 越来越像“关于 skills 的 policy”，而不是 skill library 本身

**SkillGate** 把 skill exposure 变成学习问题；**Optimal Skill Selection** 说明 skill utility 可能是 set-valued，不能按单项 relevance 独立判断；**Break It Down, Pass It On** 则表明 write granularity 可以直接翻转 procedural memory 的平均收益。**Recuris** 给出了最强的 control：tau2-Retail 上 Base 为 **58.1%**，working-memory-only **82.0%**，使用同一十项 skill library 的 model-controlled invocation 为 **65.6%**，完整 Recuris 为 **83.6%**。固定 library 后，current-state tracking 与 invocation policy 比“有没有 skills”更能解释结果。它在 Terminal-Bench 上的 adaptation headline 也被最接近的 attempt-budget control 基本解释：**58.6%→60.9%，p=.774**。

**HiPS** 进一步把 memory-management policy 本身持久化为 shared rule 与 persona-specific delta。它最有价值的证据来自 matched ablation 与跨模型 rule transfer，而不是异构 backbone 的 headline leaderboard。研究单元因此正在从“存什么 artifact”转向 **write unit × state estimator × set selector × invocation/update policy**。

### 3. Architecture claim 需要同时通过 executable behavior、强 raw/verbatim control 和完整 lifecycle cost

**DreamBench-SWE** 是八月最重要的负对照。persistent state 确实能改变后续 executable patch：no external memory 为 **21/180**，deterministic verbatim storage 为 **82/180**；但更复杂的 typed/raw hybrid 只有 **83/180**，所有 preregistered hybrid-versus-verbatim/raw/typed 比较都未拒绝原假设。与此同时，hybrid 消耗 **174.205M tokens**，verbatim 仅 **2.209M**。这证明 persistence 有用，却没有证明 typed/sleep mechanism 值得 credit。

**KOPE** 展示了 execution-grounded reuse 的 systems upside：在同一 GLM-5.2 workflow 下，active context management 把 pass rate 从 **60.0%→84.6%**，同时把 optimization tokens 从 **15.9B→1.113B**；移除 Experience Graph Memory 后 full-suite pass rate 降到 **55.2%**。但 selection、compression、injection 仍然一起变化。**MemFuse**、**SCALE-QA / TSIM**、**The Compaction Cliff** 与 **VoiceMem** 从不同方向给出同一个归因压力：answer-time access 可能比 fused structure 更关键；episode reconstruction 仍是 package-level；preservation contract 需要 source-fidelity control；VoiceMem 的 **134 ms** 是 retrieval latency，不是端到端 interaction latency。

## 最强证据与负对照

1. **When Stale Constraints Go Unchecked**：目前最干净的 fixed-budget verification-allocation 因果诊断。
2. **DreamBench-SWE**：最强的机制过度归因反例——复杂 memory mechanism 没有显著胜过 deterministic verbatim，却昂贵得多。
3. **Recuris**：最强的 same-library control，把 persistent artifact 与 working state / invocation policy 分开，同时给出 retry-matched negative result。
4. **MemFuse**：最清楚地提醒我们，answer-time evidence completion 可能比被宣传的 fused representation 更能解释收益。
5. **KOPE**：目前最强的 systems case，说明 execution-grounded experience reuse 能改变后续 tool decision 并降低 context load，但内部机制仍是 bundled。

八月所有 25 条 native-v2 记录最高只有 4/5，且仍是各自 direction 的单篇 `early_signal`；因此 durable Field Map 保持不变。

## 核心张力、可证伪条件与阅读路径

本月最重要的张力是 **更好的 stored state，还是对普通 stored state 更好的控制**。当前证据比 system paper 的 headline 更偏向后者，但三个隐藏假设可能改变结论：qualification policy 可能依赖 oracle provenance 或 privileged supervision；learned selector 可能比 control 花更多 compute；所谓“在线便宜”也可能只是把 extraction、verification、consolidation 或 graph maintenance 移出了可见 critical path。

如果 learned non-oracle qualification policy 无法在 strong raw/verbatim archive 上继续改善后续 open-ended action；如果 same-library selector/invocation gain 在 supervision 与 token/tool budget 匹配后消失；或者 structured memory mechanism 在 construction、access、maintenance、retry、reacquisition 全部匹配后稳定胜过 raw/verbatim control，那么八月的这套判断应当收缩。

最小阅读路径：**DreamBench-SWE → StateMem → When Stale Constraints Go Unchecked → Recuris → KOPE**。这五篇足以理解八月最重要的修正：从 representation-first 叙事转向 lifecycle-matched causal attribution。
