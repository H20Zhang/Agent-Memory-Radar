# Agent Memory Yearly — 2026

**Status:** rolling yearly compaction through 2026-08-15.  
**Radar coverage:** active curation starts in August and includes one backfilled paper published 2026-07-25; this is **not a full-year reconstruction**.

## Current yearly thesis

Within the narrow coverage available so far, agent memory is moving from a retrieval add-on toward a **multi-stage state interface**:

`archive/representation → access program → evidence completion/selection → consumer-facing reuse → update feedback/governance → lifecycle cost/provenance`.

The most important correction is methodological: **memory complexity should be credited only at the stage where a matched simpler alternative fails**. ReFind raises the raw-record baseline; RippleMem shows that structure can still earn its cost when it enables controlled evidence completion under a more matched access comparison. QCR isolates consumer-facing reuse, while SkillEvo and ERSkill show that self-improvement depends on the feedback surface and on whether the access policy itself can evolve.

## Durable shifts visible in current coverage

### Precomputed representation → controllable evidence interface

V-Mem and MESA show that relations/views matter when access policy can exploit them. **ReFind** adds a strong negative control: generated semantic structure is not required for precise archival refinding when the agent receives a competent raw-record interface. **RippleMem** adds the counterexample that keeps this from becoming a new dogma: event associations are useful when retrieved memories become anchors for a missing-evidence search rather than the endpoint of retrieval.

**Current interpretation:** neither flat top-k nor elaborate pre-built structure is the default. The right baseline is a competent access policy over minimally transformed evidence; structure must justify itself by enabling an operation that online search cannot cheaply recover.

### Fixed access → evolvable read programs

**ERSkill** makes retrieval behaviors persistent executable skills and co-evolves them with a learned router. The capability/deploy frontier distinction exposes a practical systems constraint: an oracle-good read strategy is not deployable if the controller cannot reliably activate it.

**Current interpretation:** adaptive memory state can live in the access program itself, not only in stored records or learned per-memory scores.

### Retrieved memory → adapted support for the current consumer

**QCR** holds retrieval and acting conditions fixed and shows that target-bound support from the same selected trajectory substantially outperforms direct raw-trace injection under binding shift.

**Current interpretation:** archival memory and actor-facing memory can be different objects. Retrieval quality and reuse quality need separate accounting.

### Self-improvement → feedback-rich, governed state transition

**SkillEvo** shows that multi-turn interaction feedback can keep exposing actionable defects after single-turn QA saturates, while governance mainly controls regression/bloat. **Practice Makes Unsafe** and **SkillJack** show why those persistent updates need lineage, attribution, and revocation.

**Current interpretation:** memory evolution requires both a useful gradient source and a governance contract for the descendants it creates.

### Per-turn memory work → explicit lifecycle scheduling and economics

**LycheeMemory V2** isolates consolidation granularity, while **Total Recall** shows that total serving cost depends on internal ingest/reflection behavior and can move break-even by hundreds of turns.

**Current interpretation:** write/update cadence and end-to-end serving economics are first-class design choices, not implementation details.

## Strongest papers in current coverage

- **ReFind + RippleMem** — strongest current tension over when raw-record search is sufficient and when structure earns complexity through evidence completion.
- **QCR / Beyond Retrieval** — clearest separation of retrieval from post-retrieval reuse.
- **SkillEvo + ERSkill** — strongest current evidence that self-improvement quality depends on feedback richness and evolvable access control.
- **LycheeMemory V2 / Total Recall** — strongest evidence that write cadence and lifecycle economics matter independently of final context size.
- **Practice Makes Unsafe / SkillJack** — strongest persistent-adaptation lineage and revocation warning.

No work is currently rated **5/5**. The abstractions are becoming sharper, but coverage remains narrow and most evidence is benchmark-bounded rather than long-running deployment evidence.

## Themes strengthening, weakening, unresolved

**Strengthening:** matched stage-specific controls; query-time search over raw evidence; evidence-completing associative access; evolvable retrieval programs; target-conditioned reuse; feedback-rich procedural evolution; provenance/revocation and lifecycle cost accounting.

**Weakening:** “structured memory” as a contribution by itself; one-shot flat retrieval as an adequate baseline; correct retrieval as sufficient for procedural reuse; self-reflection as a sufficient evolution signal; final-context tokens as a proxy for total cost.

**Still unresolved:** where computation should live. ReFind moves intelligence online; RippleMem spends on write-time structure plus recollection; ERSkill spends training-time rollout/judge compute; Lychee amortizes write-side consolidation; QCR adds target-time support synthesis. We do not yet have a common optimization framework spanning construction cost, access latency, reuse success, and lifecycle risk.

## What evidence would change this yearly view

The interpretation should weaken if matched-budget raw-record search closes RippleMem's evidence-completion gain; evolved access programs fail outside memory QA; SkillEvo's multi-turn feedback advantage disappears with real users; or provenance/governance controls cannot transfer to long-running agents without substantial utility loss.
