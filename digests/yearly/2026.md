# Agent Memory Yearly — 2026

**Status:** rolling yearly compaction through 2026-08-19.  
**Radar coverage:** active curation starts in August and includes one backfilled paper published 2026-07-25; this is **not a full-year reconstruction**.

## Current yearly thesis

Within the narrow coverage available so far, agent memory is moving from a retrieval add-on toward a **multi-stage state interface**:

`archive/representation → access program → evidence completion/selection → consumer-facing state/reuse → update feedback/governance → lifecycle cost/provenance`.

The durable methodological correction is becoming clearer: **memory complexity should be credited only at the stage where a matched simpler alternative fails**. ReFind raises the raw-record baseline; RippleMem shows that structure can still earn its cost when it enables controlled evidence completion under a more matched access comparison. QUMem and QCR show that retrieved evidence is not necessarily the state an actor should consume. SkillEvo, ERSkill, and HyperSkill move self-improvement into feedback quality, access policy, and structure-aware maintenance rather than only “better stored memories.”

## Durable shifts visible in current coverage

### Precomputed representation → controllable evidence interface

V-Mem and MESA show that relations/views matter when access policy can exploit them. **ReFind** adds a strong negative control: generated semantic structure is not required for precise archival refinding when the agent receives a competent raw-record interface. **RippleMem** adds the counterexample that keeps this from becoming a new dogma: event associations are useful when retrieved memories become anchors for a missing-evidence search rather than the endpoint of retrieval. **Skill2Query** adds a narrower procedural-memory version: retrieval supervision improves when capability and parameter structure are exposed, but online expansion is not uniformly beneficial.

**Current interpretation:** neither flat top-k nor elaborate pre-built structure is the default. The right baseline is a competent access policy over minimally transformed evidence; structure must justify itself by enabling an operation that online search cannot cheaply recover.

### Fixed access → evolvable read programs and operational structure

**ERSkill** makes retrieval behaviors persistent executable skills and co-evolves them with a learned router. **HyperSkill** makes trajectory relations operational in dual-path retrieval, cross-trajectory skill ranking, and maintenance.

The important caveat is that HyperSkill's no-hypergraph condition removes the structural retrieval pipeline too, so its evidence supports the whole operational-structure package more strongly than the hypergraph representation alone.

**Current interpretation:** adaptive memory state can live in the access program itself, and stored structure matters most when that program actively consumes it.

### Retrieved memory → reconstructed state for the current consumer

**QCR** holds retrieval and acting conditions fixed and shows that target-bound support from the same selected trajectory substantially outperforms direct raw-trace injection under binding shift.

**QUMem** reaches the same boundary from long-term personalization. Its largest component ablation is query-time user-state reconstruction, not episode segmentation or typed memory decomposition; KnowU-Bench shows the reconstructed state can also affect personalized action rather than only answer selection.

**Current interpretation:** archival memory, retrieved evidence, and actor-facing state can be three different objects. Retrieval quality and state/reuse quality need separate accounting.

### Self-improvement → feedback-rich, governed state transition

**SkillEvo** shows that multi-turn interaction feedback can keep exposing actionable defects after single-turn QA saturates, while governance mainly controls regression/bloat. **HyperSkill** adds structure-aware pruning/merging as part of the evolution loop. **Practice Makes Unsafe** and **SkillJack** show why those persistent updates need lineage, attribution, and revocation.

**Current interpretation:** memory evolution requires a useful gradient source, a clearly defined state/access policy being changed, and a governance contract for the descendants it creates.

### Per-turn memory work → adaptive write granularity and lifecycle economics

**LycheeMemory V2** isolates consolidation cadence; **FTA-Mem** shows that the right persistent unit can depend on information density—situation-level construction beats session memory in sparse dialogue, while finer turn-pair memory slightly wins denser LoCoMo quality at substantially higher construction cost. **Total Recall** shows that total serving cost depends on internal ingest/reflection behavior and can move break-even by hundreds of turns.

**Current interpretation:** event boundary, write/update cadence, preservation contract, and end-to-end serving economics are first-class design choices, not implementation details.

## Strongest papers in current coverage

- **ReFind + RippleMem** — strongest current tension over when raw-record search is sufficient and when structure earns complexity through evidence completion.
- **QUMem + QCR** — clearest separation of stored/retrieved evidence from current consumer-facing state.
- **SkillEvo + ERSkill + HyperSkill** — strongest current evidence that self-improvement quality depends on feedback richness, evolvable access control, and operational structure.
- **LycheeMemory V2 + FTA-Mem + Total Recall** — strongest evidence that write granularity/cadence and lifecycle economics matter independently of final context size.
- **Practice Makes Unsafe + SkillJack** — strongest persistent-adaptation lineage and revocation warning.

No work is currently rated **5/5**. The abstractions are becoming sharper, but coverage remains narrow and most evidence is benchmark-bounded rather than long-running deployment evidence.

## Themes strengthening, weakening, unresolved

**Strengthening:** matched stage-specific controls; query-time search over raw evidence; evidence-completing associative access; capability-grounded skill retrieval; evolvable retrieval programs; query-conditioned consumer-state reconstruction; density-aware write granularity; feedback-rich procedural evolution; provenance/revocation and lifecycle cost accounting.

**Weakening:** “structured memory” as a contribution by itself; one-shot flat retrieval as an adequate baseline; retrieved records as the final consumer state; correct retrieval as sufficient for procedural reuse; one global memory-unit granularity; self-reflection as a sufficient evolution signal; final-context tokens as a proxy for total cost.

**Still unresolved:** where computation should live. ReFind moves intelligence online; RippleMem spends on write-time structure plus recollection; Skill2Query trades offline augmentation against inconsistent online expansion; QUMem adds typed construction and three query-time inference stages; ERSkill spends rollout/judge compute; HyperSkill spends decomposition/extraction plus structural maintenance; FTA-Mem spends more write compute than coarse summaries but less than turn-pair memory. We still lack a common optimization framework spanning construction cost, access latency, consumer-state quality, and lifecycle risk.

## What evidence would change this yearly view

The interpretation should weaken if matched-budget raw-record search closes RippleMem's evidence-completion gain; QUMem-style state reconstruction adds little once synthesis cost and retrieved evidence are held fixed; a flat/binary representation with HyperSkill's same controller closes the structural gain; FTA-Mem's density-dependent granularity result fails outside one dialogue family; evolved access programs fail outside memory QA; or governance controls cannot transfer to long-running agents without substantial utility loss.
