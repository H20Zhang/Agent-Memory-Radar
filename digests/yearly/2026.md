# Agent Memory Yearly — 2026

**Status:** rolling yearly compaction.  
**Radar coverage:** starts 2026-08-03; this is **not yet a full-year reconstruction** of 2026.

## Current yearly thesis

Within the coverage available so far, agent memory is moving from a **retrieval-centric component** toward a **state-management system** with explicit decisions about representation, write/update policy, forgetting, cost, provenance, and security.

The strongest early signals are:

1. **Heterogeneous lifecycle semantics** — different evidence types increasingly receive different storage, update, and access contracts rather than sharing one flat memory abstraction.
2. **Policy-aware memory management** — construction, compression, retention, and forgetting are beginning to be optimized as explicit decisions rather than fixed heuristics.
3. **Persistent-state correctness** — authority, provenance, poisoning, and state integrity matter once remembered information can influence future agent behavior across sessions.

## Strongest papers in current coverage

- **MemoryCPT** — end-to-end cost/quality optimization across memory construction and query-time compression.
- **LeanMem** — heterogeneous evidence types with different lifecycle semantics.
- **Scrub Jay Memory** — per-memory future utility as a forgetting / retention abstraction.
- **AuthMem-Bench** — authority preservation as a memory invariant.
- **MAFIA** — persistent-memory poisoning as a cross-session state-integrity threat.

No work is currently rated 5/5. The signals are meaningful, but the available coverage is still too narrow to call any one result field-shaping for the year.

## Design-space movement observed so far

### Flat semantic memory → typed / structured memory

Recent systems increasingly separate profile, event, record, timeline, provenance, or other memory forms instead of treating all history as interchangeable chunks.

### Retrieval heuristics → explicit lifecycle policies

The design question is broadening from *which items are similar to this query?* to *what should be stored, compressed, retained, updated, or forgotten given downstream utility and cost?*

### Answer correctness → state correctness

A memory can retrieve the right-looking information and still be behaviorally wrong because provenance, authority, or integrity was lost. This expands the definition of memory correctness.

## Unresolved trade-offs

- **Expressiveness vs efficiency:** richer typed or structured memory may improve reasoning but increase construction and maintenance cost.
- **Adaptivity vs controllability:** learned memory policies may outperform fixed heuristics while becoming harder to reason about or constrain.
- **Utility vs provenance/security:** aggressive compression or forgetting can remove exactly the metadata needed to establish trust and authority.
- **Specialized structure vs generality:** heterogeneous memory may help specific query types but risks brittle routing and schema assumptions.

## What evidence would change this view

This yearly interpretation should weaken if broader evaluations show that strong flat semantic memory matches heterogeneous systems at lower complexity, if learned memory policies fail to generalize beyond narrow benchmarks, or if provenance/security failures do not materially affect downstream agent behavior in realistic settings.
