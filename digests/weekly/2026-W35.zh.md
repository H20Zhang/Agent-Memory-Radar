**接受论文：** 20

## 一句话结论

本周没有出现足以确立新 memory architecture 的证据。更值得更新的因果问题从**“应该持久化什么表示”**转向了**“什么 policy 才允许持久状态影响后续 actor”**：current-state resolution、applicability、verification allocation、skill-set selection、invocation 与 execution-grounded reuse 的作用，反复至少与存下来的 artifact 本身同样重要。

## 实际发生了什么变化

### 1. 消费前的资格判断成为核心控制边界

多项结果把“memory 被检索到”与“memory 现在仍值得使用”拆开。**StateMem** 显式处理 supersession 与 answer-time recomputation：DeepSeek 上 extraction-only 为 **0.174**，加入 supersession 后为 **0.298**，完整 StateMem 为 **0.363**；但移除 dependency propagation 反而升到 **0.373**，说明增加更多 state relation 并不天然有益。**MemTrapBench** 则展示相反方向的失败：历史内容即使语义相关，只要旧 reasoning pattern 已不适用，也可能伤害当前任务。

最干净的因果干预来自 **When Stale Constraints Go Unchecked**。固定 `k=2` verification budget，只把一个 verification slot 换到关键 provenance path，就让 superseded world 中与当前记录一致的决策提升 **61.3–74.0 个百分点**；而 valid world 只变化 **0–2.0 个百分点**。这隔离的是 verification allocation failure，而不是 retrieval failure 或 provenance 缺失。不过 forced-critical arm 使用 oracle path，只能作为因果识别工具，不能直接当 deployment scheduler。

**研究含义：** 更合理的 memory interface 已经不是 `retrieve → consume`，而接近 `candidate state → authority/freshness/applicability check → admitted consumer state`。以后应把 stale / inapplicable-use error 与 recall failure 分开测量。

### 2. Procedural memory 更像 skill policy，而不是 skill library

**Break It Down, Pass It On** 表明 write granularity 可以改变 procedural memory 的平均效果：task-level no-memory/text/code 为 **22.1/20.9/18.0%**，subtask-level 为 **24.8/26.7/25.3%**。把冻结的 subtask library 重放给 task actor 后，两种模型平均增加 **9.9 个百分点**；但 architecture、query frequency、write count 与 source trajectory 并未完全配平，所以不能推出“更细粒度永远更好”。

**Optimal Skill Selection** 更进一步把 selection 明确成 set-valued utility：受控实验里，任一单 skill 都是 **0%**，互补 skill pair 达到 **93%**，再加入无关 procedure 后降到 **56%**。**Recuris** 又抬高了控制基线：tau2-Retail 上 Base 为 **58.1%**、working-memory-only **82.0%**、使用同一十个 skill 的 model-controlled invocation **65.6%**、完整 Recuris **83.6%**。因此 standing skill library 本身不是主要解释变量。更关键的是，Terminal-Bench 配平 retry 后 adaptation 只有 **58.6→60.9%（p=.774）**，self-evolution 的 headline 不再成立。

**研究含义：** procedural-memory 工作应冻结 library 与 actor，再在相同 context / supervision budget 下独立改变 write unit、set selector、state-conditioned invocation 与 update policy。“skill 更好”这个 attribution 已经太粗。

### 3. Execution-grounded outcome 抬高证据门槛，也暴露 lifecycle-cost 混杂

**DreamBench-SWE** 是本周最强的 mechanism over-credit 反例。后续 executable patch 从 no external memory 的 **21/180** 提升到 deterministic verbatim storage 的 **82/180**，但 typed/raw hybrid 只有 **83/180**，所有 preregistered hybrid-vs-verbatim/raw/typed test 都未拒绝原假设。更重要的是 hybrid 使用 **174.205M tokens**，verbatim 只有 **2.209M**。它证明 persistent state 确实改变后续行为，却没有证明 typed consolidation 或 sleep 是原因。

**KOPE** 展示另一面的 systems upside：同一 GLM-5.2 workflow 中，active context management 把 pass rate 从 **60.0%→84.6%**，optimization tokens 从 **15.9B→1.113B**；移除 Experience Graph Memory 后 full-suite pass rate 降到 **55.2%**。但 selection、compression、injection 共同变化，graph 的 downstream-outcome score 也只是 retrieval heuristic，不是 causal label。**SCALE-QA / TSIM**、**The Compaction Cliff** 与 **VoiceMem** 同样给出有价值的 representation/package signal，但最强 claim 仍缺 component-matched control 与完整 lifecycle accounting。

**研究含义：** 一个严肃的 memory claim 现在至少需要同时满足三点：后续 behavioral / executable effect、强 raw/verbatim controller，以及 construction + access + maintenance cost。缺一项时，结论应停留在 package-level。

## 需要继续追踪的张力

- **State control 与 memory mechanism：** Recuris 中 state/invocation 的作用压过 standing library；DreamBench-SWE 则让更强的 typed-mechanism claim 在 verbatim control 下归零。
- **Safety 与 utility：** provenance weighting、applicability gate、verifier state 能抑制有害 memory，但强 trust filtering 也会删掉合法的 low-trust evidence；“更安全”不天然是 Pareto improvement。
- **Adaptation 与额外 compute：** Recuris 在 retry matching 后失去 Terminal-Bench adaptation 增益；其他系统也常把 classification、verification 或 async write 移出可见 critical path，而不是消除 lifecycle cost。

## 本周暴露出的研究缺口

最高杠杆的下一项实验是一个 **matched persistent-state intervention matrix**。固定 base model、source archive / skill library、task stream 与总 token/tool/latency budget，独立变化 write granularity、supersession/state schema、selector/set policy、verification/applicability gate、consumer reconstruction/invocation，以及 update/rollback；同时报告后续 executable behavior、stale/unsafe-use error、protected-slice regression 与完整 lifecycle cost。

这个实验可以直接区分当前论文经常混在一起的三种解释：stored representation 更好；controller 更会准入正确 state；或者系统只是花了更多 reconstruction、verification、retry 与 maintenance compute。

## 下一步应观察什么证据

如果 learned、non-oracle qualification policy 能在真实 open-ended agent action 上胜过强 raw/verbatim archive；set-level 与 state-conditioned skill policy 能在 supervision 配平后迁移到未筛选 unseen task；execution-grounded memory 的收益在多 seed 和完整 construction/query/maintenance accounting 下仍成立，本周判断会增强。

如果这些差异在配平 raw-state access、attempt count、context budget、selection supervision，以及 deferred/asynchronous lifecycle cost 后消失，本周的“policy boundary”解释就应减弱。

## 最小阅读顺序

1. **DreamBench-SWE** — 用 executable behavior 与强 verbatim control 抬高证据门槛。
2. **StateMem** — 把 current-state resolution 与 retrieval 拆开。
3. **When Stale Constraints Go Unchecked** — 在固定 budget 下隔离 verification allocation。
4. **Optimal Skill Selection** — 把 procedural reuse 变成 set-utility 问题。

6. **KOPE** — 展示 execution-grounded experience reuse 的 systems upside，同时保留 package-level attribution 限制。
