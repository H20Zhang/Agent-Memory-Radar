## The week in one sentence

The week did not establish a new memory architecture. It shifted the sharper causal question from **what representation should persist** to **under what policy persistent state is allowed to influence a later actor**: current-state resolution, applicability, verification allocation, skill-set selection, invocation, and execution-grounded reuse repeatedly matter at least as much as the stored artifact itself.

## What actually changed

### 1. Qualification before consumption became the central control boundary

Several results separate “the memory was retrieved” from “the memory was safe and valid to use.” **StateMem** makes supersession and answer-time recomputation explicit: on DeepSeek, extraction-only scores **0.174**, adding supersession reaches **0.298**, and full StateMem reaches **0.363**; removing dependency propagation actually improves the result to **0.373**, so not every extra state relation helps. **MemTrapBench** shows the opposite failure mode: relevant prior history can reduce performance when its old reasoning pattern no longer applies.

The cleanest causal intervention is **When Stale Constraints Go Unchecked**. At the same `k=2` verification budget, replacing one verification slot with the critical provenance path raises current-record-consistent decisions in superseded worlds by **61.3–74.0 percentage points**, while valid-world outcomes change by only **0–2.0 points**. This isolates a verification-allocation failure rather than a retrieval or provenance-availability failure, although the forced-critical arm uses oracle knowledge and is not a deployable scheduler.

**So what:** the useful interface is no longer `retrieve → consume`; it is closer to `candidate state → authority/freshness/applicability check → admitted consumer state`. Future memory systems should measure stale or inapplicable-use errors separately from recall.

### 2. Procedural memory looks more like a policy over skills than a skill library

**Break It Down, Pass It On** shows that write granularity can flip the average effect of procedural memory: task-level no-memory/text/code are **22.1/20.9/18.0%**, while subtask-level variants are **24.8/26.7/25.3%**. A frozen subtask library replayed into a task actor adds **9.9 points** on average for two models, but architectures, query frequency, write count, and source trajectories are not fully matched.

**Optimal Skill Selection** makes the selection problem explicitly set-valued: in a controlled case, either one skill yields **0%**, the complementary pair yields **93%**, and adding an irrelevant procedure drops success to **56%**. **Recuris** then raises the control bar further. On tau2-Retail, a base agent scores **58.1%**, working-memory-only **82.0%**, same-library model-controlled invocation **65.6%**, and full Recuris **83.6%**. The standing ten-skill library is therefore not the main explanatory variable. On Terminal-Bench, however, retry-matched adaptation is only **58.6→60.9% (p=.774)**, so the self-evolution headline does not survive the closest attempt-budget control.

**So what:** procedural-memory papers should freeze the library and actor, then vary write unit, set selector, state-conditioned invocation, and update policy independently under the same context and supervision budget. “Better skills” is too coarse an attribution.

### 3. Execution-grounded outcomes raise the evidence ceiling—and expose lifecycle-cost confounds

**DreamBench-SWE** is the strongest warning against mechanism over-credit. Later executable patches improve from **21/180** with no external memory to **82/180** with deterministic verbatim storage, but the typed/raw hybrid reaches only **83/180**, and every preregistered hybrid-versus-verbatim/raw/typed comparison fails to reject. The hybrid also consumes **174.205M tokens** versus **2.209M** for verbatim storage. The benchmark demonstrates that persistent state matters; it does not demonstrate that typed consolidation or sleep is the reason.

**KOPE** shows the opposite systems opportunity. In the same GLM-5.2 workflow, active context management raises pass rate **60.0%→84.6%** while reducing optimization tokens **15.9B→1.113B**; removing Experience Graph Memory drops the full-suite pass rate to **55.2%**. Yet selection, compression, and injection co-vary, and the graph’s downstream-outcome score is a retrieval heuristic rather than a causal label. **SCALE-QA / TSIM**, **The Compaction Cliff**, and **VoiceMem** likewise report useful representation/package signals, but their strongest claims still need component-matched and full-lifecycle controls.

**So what:** a serious memory claim now needs three things together: downstream behavioral or executable effect, a strong raw/verbatim controller, and construction + access + maintenance cost. Without all three, system gains should stay package-level.

## Tensions worth tracking

- **State control vs memory mechanism:** Recuris makes state/invocation dominate a standing library, while DreamBench-SWE nulls the stronger typed-mechanism claim against verbatim storage.
- **Safety vs utility:** provenance weighting, applicability gates, and verifier state can suppress harmful memory, but aggressive trust filtering can also remove legitimate low-trust evidence; “safer” is not automatically Pareto-improving.
- **Adaptation vs extra compute:** Recuris loses its Terminal-Bench adaptation claim after retry matching, and several other systems move classification, verification, or asynchronous writes outside the visible critical path rather than eliminating lifecycle cost.

## Research gaps exposed this week

The highest-value next experiment is a **matched persistent-state intervention matrix**. Hold the base model, source archive or skill library, task stream, and total token/tool/latency budget fixed; independently vary write granularity, supersession/state schema, selector/set policy, verification/applicability gate, consumer reconstruction/invocation, and update/rollback. Measure later executable behavior, stale/unsafe-use errors, protected-slice regressions, and complete lifecycle cost.

This would distinguish three competing explanations that the current literature often bundles: the stored representation is better; the controller admits the right state; or the system simply spends more compute on reconstruction, verification, retries, and maintenance.

## Evidence to watch next

The week’s interpretation strengthens if learned, non-oracle qualification policies improve real open-ended agent actions over a strong raw/verbatim archive; set-level and state-conditioned skill policies transfer to unfiltered unseen tasks with matched supervision; and execution-grounded memory gains survive seeds plus full construction/query/maintenance accounting.

It weakens if those gains disappear once raw-state access, attempt count, context budget, selection supervision, and deferred/asynchronous lifecycle cost are matched.

## Minimal reading order

1. **DreamBench-SWE** — raises the evidence ceiling with executable behavior and a strong verbatim control.
2. **StateMem** — separates current-state resolution from retrieval.
3. **When Stale Constraints Go Unchecked** — isolates verification allocation at a fixed budget.
4. **Optimal Skill Selection** — makes procedural reuse a set-utility problem.
5. **Recuris** — separates library availability from working state/invocation and includes a retry-matched negative result.
6. **KOPE** — shows the systems upside of execution-grounded experience reuse while retaining package-level attribution caveats.
