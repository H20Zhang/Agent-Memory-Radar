# Agent Memory Weekly — 2026-W32

**Window:** 2026-08-03 to 2026-08-09  
**Accepted papers:** 8  
**Highest importance:** 4/5

## The week in one sentence

Agent memory moved further away from “a better retriever over old text” toward a **controlled state system**: representation became heterogeneous, memory policy became an optimization problem, and persistent state acquired provenance and lineage invariants.

## What actually changed

### 1. Memory policy now has a state-dimension problem

**MemoryCPT**, **Scrub Jay Memory**, and the backfilled **RoMeRL** all optimize memory policy, but at different layers. MemoryCPT learns construction and query-time compression under a cost-quality objective; Scrub Jay makes future utility a per-memory retention property; RoMeRL argues that runtime memory RL should not attach an independently learned utility to every accumulated trajectory.

RoMeRL's useful correction is that **more stored experience does not imply more feedback-bearing state**. Its four semantic coordinates concentrate feedback and sharply reduce the maintained utility pool.

**So what:** learned memory management is not just “train the retriever.” The control state itself—its dimension, semantics, and reward attribution—becomes an architectural choice.

### 2. Representation is splitting by lifecycle, not only semantics

**LeanMem** separates profile, event, and source-grounded evidence because they need different update contracts. **Activity Frames** reaches a similar conclusion from a different direction: some high-volume personal history can be deterministically compiled into auditable frames before any LLM-based memory construction.

**So what:** the emerging abstraction is a set of memory types with distinct write/update/access semantics, not one universal store with increasingly elaborate metadata.

### 3. Trust must survive memory transformations

**AuthMem-Bench** shows that consolidation can preserve a claim while erasing who was authorized to make it. **MAFIA** shows that persistent retrieval memory can be poisoned through ordinary interaction. **SkillJack** adds a new boundary: poisoned experience can be transformed into a separately stored skill, become less detectable, and survive deletion of its source record.

**So what:** provenance is not merely an annotation on stored text. If memory is summarized, consolidated, or compiled into skills, trust and revocation must propagate through the **artifact lineage**.

## Papers worth reading

1. **RoMeRL** — strongest new control-state idea: bounded semantic utility state rather than one learned variable per trajectory.
2. **MemoryCPT** — strongest end-to-end systems/learning formulation for explicit cost × answer-quality optimization.
3. **LeanMem** — cleanest representation argument for heterogeneous evidence lifecycles.
4. **SkillJack** — strongest lifecycle-security correction: deleting a source record is insufficient once experience has descendants.
5. **AuthMem-Bench + MAFIA** — read together for authority and direct persistent-state integrity; complementary to SkillJack rather than redundant.

**Also useful:** Scrub Jay for time-dependent utility/forgetting. **Watch, don't over-index yet:** Activity Frames has a compelling deterministic-compilation point but narrow evidence.

## Tensions worth tracking

- **Richer state vs bounded state:** LeanMem argues for more semantically differentiated memory structures; RoMeRL argues that learning a utility per stored item creates feedback dilution. A scalable system may need rich stored evidence but a much smaller learned control state.
- **Optimization vs auditability:** MemoryCPT learns memory transformations; Activity Frames prefers deterministic compilation. The open design boundary is which transformations should be learned and which should remain reproducible/auditable.
- **Compression vs trust lineage:** compression and skill extraction can improve efficiency or capability while stripping authority or laundering risk. Any lifecycle optimizer that ignores provenance may optimize the wrong objective.

## Research gaps exposed this week

The missing benchmark is increasingly clear: an **end-to-end memory lifecycle benchmark** that jointly stresses representation, write/update, access, forgetting, cost, feedback sparsity, provenance, and downstream actions. Current papers optimize one or two axes at a time, so cross-stage regressions remain easy to hide.

A second gap is **causal memory credit**. RoMeRL reduces the Memory-Reward Trap by shrinking the active utility state, but explicitly does not identify each memory's marginal causal contribution. Stronger attribution evidence could overturn how aggressively the field should pursue learned per-memory utility.

## Evidence to watch next

The W32 thesis would strengthen if heterogeneous/bounded memory policies survive open-ended tool-use workloads and if provenance-aware lifecycle controls prevent failures without erasing the cost gains of compression. It would weaken if a strong flat-memory baseline with matched compute and trust metadata closes the current gaps.
