# Agent Memory Weekly — 2026-W32

**Window:** 2026-08-03 to 2026-08-09  
**Accepted papers:** 6  
**Highest importance:** 4/5

## The week in one sentence

Agent-memory work this week looked less like “better retrieval” and more like **stateful system design**: papers focused on differentiated memory lifecycles, learned cost/quality policies, memory-specific forgetting, and the security invariants created by persistent state.

## What actually changed

### 1. Memory is becoming typed, not flat

**LeanMem** and **Activity Frames** both push against the assumption that all historical information should share one storage/update contract. LeanMem separates profile, event, and source-grounded evidence with different lifecycle semantics; Activity Frames shows that some high-volume personal memory can be deterministically compiled before retrieval rather than repeatedly summarized by an LLM.

**So what:** the emerging design question is no longer only *which vector store or retriever?* It is *which memory type deserves which representation, write policy, and access path?*

### 2. Forgetting and compression are becoming first-class policies

**Scrub Jay Memory** models forgetting through per-memory future utility rather than a global recency heuristic. **MemoryCPT** goes one step further and treats memory construction plus query-time compression as trainable components under an explicit cost–quality objective.

**So what:** memory management is moving toward an optimizer problem: retain, compress, or discard information based on expected downstream utility and cost, not just similarity or age.

### 3. Persistent memory creates new trust boundaries

**MAFIA** shows that malicious information can enter persistent state now and affect a later benign-looking interaction. **AuthMem-Bench** highlights a different failure: consolidation can preserve a claim while losing who had authority to make it.

**So what:** provenance, authority, and state integrity are not optional metadata once memory can change future tool-using behavior. They are part of memory semantics.

## Read priority

1. **MemoryCPT** — strongest systems/learning formulation this week; useful if you care about end-to-end memory optimization rather than isolated retrieval.
2. **LeanMem** — strongest representation/lifecycle paper; useful for thinking about heterogeneous memory views and operations.
3. **Scrub Jay Memory** — cleanest new abstraction: forgetting as per-memory future utility.
4. **MAFIA + AuthMem-Bench** — read together; they expose two different persistent-state invariants: integrity and authority.

**Watch, don't over-index yet:** Activity Frames has an interesting deterministic-compilation design point, but current evidence is narrow.

## Tensions worth tracking

- **Learned vs deterministic memory construction:** MemoryCPT learns memory policies; Activity Frames argues that high-volume streams may benefit from deterministic compilation. The likely answer is hybrid, but the boundary is still unclear.
- **Utility-based forgetting vs provenance preservation:** aggressive compression/forgetting may improve cost while deleting precisely the metadata needed for authority and security checks.
- **Benchmark fragmentation:** current papers optimize different axes on different workloads, making it difficult to know whether a better memory system is simultaneously cheaper, safer, and more accurate.

## Research gaps exposed this week

The biggest missing benchmark is not another long-horizon QA set. It is an **end-to-end memory lifecycle benchmark** that jointly stresses write, update, forgetting, provenance, retrieval, and cost under persistent interaction. Without that, improvements to one memory stage can silently break another.
