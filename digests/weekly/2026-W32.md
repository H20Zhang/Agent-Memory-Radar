# Agent Memory Weekly — 2026-W32

**Window:** 2026-08-03 to 2026-08-09  
**Accepted papers:** 11  
**Highest importance:** 4/5

## The week in one sentence

The week sharpened a more useful thesis than “agent memory is becoming structured”: **memory structure only pays when it is aligned to the control variable that consumes it**—the agent phase, student capability, temporal utility, or trust boundary—and extra structure can fail when that alignment is absent.

## What actually changed

### 1. Memory policy has a state-dimension problem

**MemoryCPT**, **Scrub Jay Memory**, and **RoMeRL** all make memory policy explicit, but at different layers. MemoryCPT learns construction and query-time compression under a cost-quality objective; Scrub Jay assigns future utility per memory; RoMeRL argues that runtime reinforcement should not attach an independently learned utility to every accumulated trajectory.

RoMeRL remains the strongest correction: **rich evidence state does not imply equally rich feedback-bearing state**. Its reduced-order semantic coordinates concentrate sparse feedback and reduce exposure to bundle-level reward contamination.

**So what:** when memory becomes learnable, the dimension and semantics of the control state are architectural choices, not bookkeeping details.

### 2. Structure is useful when it matches the consumer's decision granularity

Three papers now support this from different directions. **LeanMem** separates evidence by lifecycle. **Agent Memory Distillation (AMD)** maps teacher experience into task-, subtask-, and function-level memories and changes *when* each level is delivered to a weaker student. **PMCoder** conditions episodic retrieval on the current repair phase and lets memory statistics trigger replanning.

The strongest skeptical counterexample is **MERIT**: cross-query repair memory helps over stateless repair, but failure typing + polarity + hybrid ranking is **not reliably better than untyped dynamic retrieval**.

**So what:** “more structured memory” is not the design rule. The stronger rule is **structure should correspond to a decision boundary the controller can exploit**.

### 3. Memory and controller state are becoming bidirectionally coupled

PMCoder contributes a distinct systems result. Planning is not merely another prompt upstream of retrieval: planner state changes retrieval, then memory-derived trajectory statistics can change planner state. Its 2×2 study reports a positive **+2.1pp interaction** beyond plan-only and memory-only effects.

AMD shows a related but cross-model form of coupling: the same teacher experience is useful only when represented and scheduled at a granularity the student can operationalize.

**So what:** the memory subsystem is starting to look less like a passive database and more like part of the agent's control loop.

### 4. Trust must survive memory transformations

**AuthMem-Bench** shows that consolidation can preserve a claim while erasing who was authorized to make it. **MAFIA** shows that persistent retrieval memory can be poisoned through ordinary interaction. **SkillJack** adds the descendant-artifact failure: poisoned experience can become a separately stored skill and survive deletion of the source record.

**So what:** provenance and revocation must propagate through **artifact lineage**, not merely remain attached to source text.

## Papers worth reading

1. **PMCoder** — best evidence this week that memory and controller state should be co-designed; the factorial interaction is more informative than the coding headline.
2. **RoMeRL** — strongest correction to trajectory-indexed learned memory: bound the feedback-bearing state instead of scaling it with every stored episode.
3. **Agent Memory Distillation** — strongest new cross-model memory role: training-free teacher→student capability transfer aligned to task/subtask/function granularity.
4. **MemoryCPT** — strongest end-to-end cost × answer-quality formulation for learned memory construction and read-time compression.
5. **SkillJack** — strongest lifecycle-security correction: deletion is not revocation once experience has derived descendants.

**Important negative result:** read **MERIT** to avoid over-generalizing from the structured-memory successes; its extra typing is not reliably better than simpler dynamic retrieval.

## Tensions worth tracking

- **Rich evidence vs compact learned state:** LeanMem/AMD/PMCoder add differentiated evidence interfaces while RoMeRL argues that the learned control state should remain much smaller.
- **Useful structure vs decorative structure:** AMD and PMCoder connect structure to concrete control points; MERIT shows that typing/polarity alone does not guarantee an incremental gain.
- **Optimization vs correctness:** MemoryCPT optimizes transformations for cost/quality, while AuthMem-Bench and SkillJack show that compression or compilation can silently change authority/provenance semantics.

## Research gaps exposed this week

A decisive benchmark would vary **memory representation × controller state × access policy** while holding base model and evidence fixed. Current papers often improve several interfaces together, making it hard to know whether the winning abstraction is the representation itself or its alignment with the controller.

The second gap remains **causal memory credit**. RoMeRL reduces exposure to bad credit; MERIT uses “causal” only in the temporal-eligibility sense; neither identifies each memory's marginal behavioral contribution.

## Evidence to watch next

The W32 thesis strengthens if planner-conditioned or consumer-aligned memory improves open-ended agents under matched evidence/budget, and if simpler dynamic retrieval fails to close the gap. It weakens if benefits disappear once controllers are less hand-structured, or if flat retrieval with matched metadata performs equally well.
