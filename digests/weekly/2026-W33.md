# Agent Memory Weekly — 2026-W33

**Window:** 2026-08-10 to 2026-08-16  
**Accepted papers:** 16  
**Highest importance:** 4/5

## The week in one sentence

The week made “best memory architecture” a weaker research question: the sharper unit of comparison is now the **stage-specific control boundary**—archive/representation → access program → evidence completion/selection → consumer-facing reuse → update/governance → lifecycle cost—and memory complexity should receive credit only where a matched simpler alternative fails.

## What actually changed

### 1. Access claims now need a competent raw-record control

**ReFind**, **RippleMem**, **MESA**, and **MAP-Graph** collectively move the debate away from “flat versus structured memory.” ReFind shows that raw timestamped turns plus stateful lexical search and chat-native controls can recover much of the value often attributed to semantic preprocessing. RippleMem supplies the important counterexample: when first-hop memories become anchors for a missing-support query, associative structure still improves over a more matched RF-Mem control using the same extracted memory units and evidence budget. MESA and MAP-Graph add two different access controls—selective view composition and admissibility/trust gating.

**So what:** representation is not the causal unit. The defensible claim is that a structure enables a stronger **read operation**—evidence completion, selective exposure, cross-modal bridging, or admissibility—that cannot be reconstructed cheaply enough from the raw archive.

### 2. Retrieval success and memory reuse are separate stages

**QCR / Beyond Retrieval** gives the cleanest evidence this week: hold the selected trajectory and actor conditions fixed, then change only the consumer-facing support object. Target-conditioned reuse reaches **62.3% success**, **+10.7pp** over direct Full Trajectory, with **48.9% fewer online tokens**; under large binding shift, stale-binding errors fall **46.9%→10.9%**.

**Demystifying Agent Skills** backfills the same boundary from procedural memory. Holding source trajectories fixed, standardized Skills outperform Workflow Memory by **6.06 points**; contrastive coding finds **65.7%** of skill cases work through procedural anchoring versus only **4.5%** through explicit knowledge injection. Retrieval is then a separate bottleneck: as pools grow from 5 to 100, actual-use precision falls **29.6%→3.3%** while downstream success is comparatively stable, and exact ground-truth skill invocation is neither sufficient nor necessary.

**HyMeS** reaches the same boundary from embodied control. It keeps reusable motor competence in policy weights but places history-dependent task state and update logic in inspectable code, letting symbolic memory steer a frozen VLA rather than merely retrieve text into a prompt.

**So what:** “retrieved the right memory” is no longer sufficient evidence for a memory system. The selected evidence still has to be represented, adapted, and invoked in a form the current consumer can operationalize.

### 3. Self-improvement is splitting into feedback quality, evolvable access, and governance

**SkillEvo** isolates the feedback surface: replacing multi-turn interaction with matched single-turn QA drops final task success from **81.8% to 66.4%**, while governance mainly constrains regression and bloat. **ERSkill** moves adaptation into the read path itself by evolving executable retrieval skills and a router rather than only rewriting stored content. **Practice Makes Unsafe** shows why this requires lifecycle governance: unsafe authoring, later retrieval, and fresh-session harm are distinct events, so persistent descendants need attribution and revocation rather than one endpoint safety score.

**So what:** “self-evolving memory” now hides at least three independent design choices—what failure signal is observed, what persistent state is allowed to evolve, and what governance follows the resulting descendants.

### 4. Memory economics and forgetting need stage-level accounting

**LycheeMemory V2**, **Total Recall at What Cost?**, and **The Sleeping Agent** attack three different lifecycle blind spots. Lychee shows that batching and semantic segmentation are separate write-side controls: batching reduces construction frequency while semantic boundaries preserve evidence. Total Recall shows that smaller answer context does not imply cheaper memory once ingest/reflection/retrieval calls are metered; sustained break-even ranges from near-immediate to never within the tested grid. Sleeping Agent shows that compression is selective forgetting: a generic gist prompt preserved the story while systematically deleting temporal anchors, and one targeted preservation instruction recovered much of the lost temporal signal.

**So what:** memory quality cannot be summarized by recall or final context size. Write frequency, preserved fields, serving cost, and downstream utility are separate axes that can move in opposite directions.

## Papers worth reading

1. **ReFind** — strongest methodological correction of the week: structured-memory claims need a competent raw-record, stateful-access control rather than one-shot top-k.
2. **RippleMem** — strongest counterweight to that correction: structure can still earn complexity when it enables planned evidence completion under a more matched control.
3. **QCR / Beyond Retrieval** — cleanest causal separation of retrieval from reuse; the same selected trajectory can become much more useful after target-conditioned rebinding.
4. **Demystifying Agent Skills** — strongest procedural-memory evaluation of the week: same source experience, different representation; retrieval correctness and downstream utility decouple.
5. **SkillEvo** — strongest evidence that the *feedback surface* can matter more than another memory-editing algorithm.

**Also read:** **Total Recall at What Cost?** for lifecycle economics, **ERSkill** for retrieval-policy evolution, and **MAP-Graph** if your memory system crosses trust/permission boundaries.

## Tensions worth tracking

- **Raw archive vs precomputed structure:** ReFind spends more online search to avoid semantic preprocessing; RippleMem spends write-time structure so later queries can perform bounded evidence completion. The decisive comparison is end-to-end compute on the same task, not graph versus BM25 in isolation.
- **Representation vs retrieval labels:** Demystifying Agent Skills shows that standardized procedural representation helps even with identical source experience, but exact ground-truth retrieval is a weak proxy because related non-ground-truth skills can still help.
- **Adaptive access vs adaptation cost:** MESA and ERSkill improve query-time selection, but increasingly powerful selectors can move substantial cost into validation, rollout, or judge-driven training.
- **Capability evolution vs descendant-state risk:** SkillEvo/ERSkill make persistent capability more adaptive, while Practice Makes Unsafe and earlier SkillJack show that every compiled descendant creates provenance, rollback, and revocation obligations.

## Research gaps exposed this week

The highest-value missing benchmark is a **stage-factorized memory evaluation**. Hold the base model and task fixed, then independently vary raw archive/preprocessing, access operator, selected evidence, consumer-facing reuse representation, update policy, and lifecycle budget. Without that decomposition, many “memory architecture” gains remain impossible to attribute.

A second gap is **long-running acting-agent evidence**. Current strongest controls still concentrate on conversation QA, terminal/software agents, benchmark web agents, cloud-support skills, synthetic governance workflows, and small embodied suites. The field needs months-long state drift, conflicting memories, permission changes, tool failures, and descendant artifacts in one trace.

## Evidence to watch next

The W33 thesis strengthens if ReFind and RippleMem can be compared under matched end-to-end latency/cost on the same acting workload; if QCR-style reuse still helps when binding shift is naturally small or multiple memories conflict; if Demystifying Agent Skills' representation advantage survives larger evolving libraries and non-software domains; if SkillEvo's multi-turn advantage survives real-user feedback; and if ERSkill-style evolved access programs transfer to tool-using domains without excessive training overhead.

It weakens if a single strong raw-record controller closes most structure/reuse gains once budgets are matched, or if the added lifecycle machinery costs more than the capability it preserves.
